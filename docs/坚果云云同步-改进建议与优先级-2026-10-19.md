# 坚果云云同步 · 改进建议与优先级（2026-10-19）

> 基线：0.56.0 实现（`core/webdav.js` 702 行 / `features/cloud-sync.js` 1545 行 / `prefs-cloud.js` 321 行），
> 真机 17/17、单测 133 项、门禁 80/80 已通过。
> 本文只提**有代码依据**的改进项，按「数据安全 > 正确性 > 性能 > 可维护性」排序。
> 评级：P0 = 会造成数据错乱/用户可感知故障，建议下一版必做；P1 = 显著收益、成本可控；P2 = 打磨项。
>
> **实施状态（2026-10-19）**：批次 1（0.59.0）已落地 —— P0-1 / P0-3 / P0-4 / P0-5 / P1-4 / P1-6。
> 单测 163 项、接线扫描 1555 项、`preflight --fast` 82 项（arXiv 套件一次并发抖动，单独复跑 9/9 通过）。
> 详见文末「批次 1 实施记录」。

## 0. 结论摘要（先做这 5 件）

| 顺序 | 改进 | 一句话理由 |
|---|---|---|
| 1 | **收敛设置快照范围**（排除缓存/机器路径/大对象） | 现在会把 `uiWallpaperPath`、`cnDownloadDir`、`rankDataPath` 同步到另一台机器，直接改坏对方配置 |
| 2 | **分卷生命周期 + 组装内存上限** | 每次改大文件都留一套旧 `.pparts`（配额泄漏）；512MB 在内存里拼会卡死/OOM |
| 3 | **删除/重命名语义（墓碑）** | A 机删掉的安装包，B 机下次同步会把它传回来 |
| 4 | **索引按账号+根目录隔离** | 换账号/改同步根后旧 etag 全量失配，制造大量假冲突 |
| 5 | **文档与实现对齐 + 文件数/深度上限** | 文档写了「单次 2000 文件上限」，代码里没有；深度 >6 静默丢弃 |

## 1. P0：数据安全与正确性

### P0-1 设置快照范围失控（最高优先）· ✅ 已落地

**现状证据**
- `snapshotPrefs()` 用 `Services.prefs.getChildList(PREFIX)` 取**全部** pref，仅排除密钥与 `cloudSync*`。
- 实际被带上的非设置项包括：
  - 缓存/统计：`readingProgress`（LRU 3000）、`readingStats`、`autoTagCache` / `autoTagCacheData`、`searchSubsRecoCache`、`searchSubsSeen`、`discoveryResults`、`agentAuditLog`、`workbenchSessions`；
  - 机器相关路径：`uiWallpaperPath`、`uiWallpaperUrl`、`cnDownloadDir`、`rankDataPath`、`metaRulesJournalDir`；
  - 身份/设备：`installId`、`renewPromptShownFor`、`prefsFoldOpen`（已排除）；
  - 大对象：`translateGlossary`、`rankDataSets*`、`skillPacksInstalled`。

**影响**
1. 换机后壁纸/下载目录/分区数据路径被改成对方机器的绝对路径 → 功能静默异常（壁纸不显示、下载失败）。
2. 快照体积随缓存增长（`readingProgress` 数千条 + 术语表 + 分区数据），**改一个开关就整包上传**。
3. 缓存每日自然变化 → 双设备反复产生"两边都改"冲突。

**建议**
- 把快照分三层（代码里用三张表，别靠正则猜）：
  - `SYNC_SETTINGS`：用户手写的偏好（提示词、语言、列开关、主题名、快捷键…）；
  - `SYNC_DATA`（默认关，可勾选）：阅读进度、阅读统计、技能包记账；
  - `EXCLUDE`：缓存、机器路径、`installId`、`cloudSync*`、密钥类。
- 快照 > 1MB 时拒绝上传并明确提示"设置项过大，请关闭 XX 数据集"。
- 面板把"设置项"拆成「偏好设置」与「本地数据」两个勾选项。

**收益**：快照体积预计降 80–95%（从数百 KB 到几十 KB）；消除跨机路径污染；冲突率显著下降。
**成本**：中（需要梳理 ~190 个 pref 键，一次性）。**适用**：所有多设备用户，单机也能少传缓存。

### P0-2 删除与重命名没有语义 · ✅ 已落地（0.60.0）

**现状证据**
- `decideAction()` 只有「本地有云端无 → 上传」「本地无云端有 → 下载」。
- 全模块**没有调用 `client.del()`**（check-wiring 48.11 是刻意钉住"删除不传播"）。

**影响**
- 设备 A 删除 `packages/installers/foo.xpi` → 设备 B 仍持有该文件 → 下次同步 B 判定"云端没有" → **传回来**。用户视角是"删了又出现"。
- 重命名同理：旧名复活 + 新名新增，云端出现两份。

**建议**
- 引入**墓碑**（`data/.tombstones.json`，30 天过期）：本地删除时写 `{rel, at, device}` 并**可选**上传；三向判定优先看墓碑：
  - 墓碑在、对端文件 mtime ≤ 墓碑时间 → 删除对端；
  - 对端在墓碑后修改过 → 视为"删除 vs 修改"冲突，按 keepBoth 保留；
- 重命名识别：同内容 hash、不同路径 → 当作 move（删旧建新，不产生冲突）；
- 开关 `cloudSyncPropagateDelete`（默认**关**，保持现在的安全侧），开启后才传播。

**收益**：删除可预期；避免"幽灵文件"；云端不堆垃圾。
**成本**：中高（要动决策矩阵 + 单测矩阵扩充）。**适用**：多设备、经常整理安装包的用户。

### P0-3 分卷文件的生命周期与内存 · ✅ 已落地

**现状证据**
- `_uploadParts()`：分卷目录名含内容 hash（`partsDirFor`），**每次内容变化就是一个新目录**，旧目录不清理。
- `_downloadParts()`：`new Uint8Array(v.total)` 一次性分配，上限是 `maxFileMB`（默认 512MB）。

**影响**
- 一个 200MB 的 xpi 改 5 版 → 云端留 5 份分片（1GB），配额被悄悄吃掉；`PROPFIND` 虽跳过 `.pparts`，但配额不骗人。
- 512MB 连续分配在中低配机器上会让 Zotero 卡顿甚至 OOM；失败后用户只看到"下载失败"。

**建议**
- 清单写入成功后，删除**同 basename 的其它 hash 目录**（保留当前），失败只记日志；
- 组装上限独立于 `maxFileMB`（建议 128MB）；超过则提示"该文件过大，请在坚果云网页下载"；
- 分卷下载写入临时文件后可校验 `manifest.sha256`（已具备字段），失败即删。

**收益**：杜绝配额泄漏；把 OOM 风险从"512MB 峰值"降到"128MB 峰值"。
**成本**：低。**适用**：所有传大安装包的用户。

### P0-4 索引没有按账号/根目录隔离 · ✅ 已落地

**现状证据**：`_indexPath()` 固定返回 `<数据目录>/papilot-cloud/index.json`。

**影响**
- 切换坚果云账号（或改 `cloudSyncRoot`）后，旧索引里的 etag 全部对不上 → 第一轮同步大量"云端已变"→ 触发冲突/覆盖。
- 多账号用户（个人/团队）无法并存。

**建议**：索引文件名带指纹 `index-<sha1(baseUrl|email|root).slice(0,8)>.json`；登录成功且指纹变化时提示"检测到账号/目录变更，已启用独立索引"；旧索引保留 30 天。
**收益**：消除换账号后的假冲突与潜在误覆盖。**成本**：低。

---

### P0-5 上限与文档不一致 · ✅ 已落地

**现状证据**：方案文档 R6 写「单次同步文件数上限（默认 2000）」，代码中无该上限；`_walkRemote` 深度 >6 直接 `return`，无任何提示。

**影响**：超大目录同步可能跑很久；深层目录被静默跳过，用户以为已备份。

**建议**：
- 实现 `maxFiles`（默认 2000）与 `maxDepth`（默认 6），超限时**计入结果并在面板显示**「已跳过 N 个（超出上限）」；
- 或者删掉文档里的说法（不推荐——上限本身有价值）。

**收益**：防跑飞；消除"同步成功但少文件"的静默失败。**成本**：低。

## 4. 边界情况清单（现状如何处理）

| 场景 | 当前行为 | 风险 | 建议归属 |
|---|---|---|---|
| 两设备同时改同一文件 | `412` → keepBoth 两份 | 可接受 | 已覆盖 |
| 重试时 `412` 但大小相同 | 视为"上次已成功"（`_uploadOne` attempt>0 分支） | **可能吞掉真实冲突** | P0-2 一并复核 |
| 索引损坏/被删 | 退化为"无基线"；同大小视为已同步 | 同大小不同内容 → 静默漏同步 | P1（加 mtime+抽样 hash） |
| 索引 90 天清理 | 老文件再改 → 无基线 → 冲突 | 噪音 | P2（改为按条目数/容量淘汰） |
| 云端文件名非法字符（Windows） | 写盘抛错 → 该文件失败，其余继续 | 单个文件永远同步不下来 | P1-7 |
| 大小写不敏感文件系统 | `A.json` / `a.json` 互相覆盖 | 数据丢失 | P1-7 |
| 坚果云限流 503 | 归因 `RATE_LIMIT`，等 120s ×2 | 最长约 4 分钟后失败；用户需知道 | 已在面板提示，P1-4 优化等待曲线 |
| 配额满 507 | 逐文件失败 | 日志刷屏、浪费时间 | P1-6 |
| 文件 >512MB | 直接跳过并报错 | 用户以为已备份 | 面板已在日志里提示，P2 增强 |
| 设置应用瞬间 | 一次性写全部键，触发 UI/进度模块重载 | 当前会话可能跳变 | P1-1 顺带：只写有变化的键 |
| 账号/根目录切换 | 沿用旧索引 | 大量假冲突 | P0-4 |
| 单机删除文件 | 不传播（设计如此） | 云端留垃圾 | P0-2 开关 |

| P1-6 | `QUOTA` 与授权失效一样**立即中止整轮** | 不再逐文件刷失败 |

**行为变化（需在发版说明里写清）**：
- 阅读进度 / 阅读统计 / Agent 记忆 **不再随设置项同步**（它们本来就是本机数据，`prefs.js` 注释也写明「不上传」）；需要的用户后续可走 `SYNC_DATA` 数据集（批次 2）。
- 超限不再是"悄悄少同步几个文件"，而是**整个数据集跳过**并在摘要里显示「告警 N」。

## 7. 批次 2 实施记录（0.60.0，2026-10-19）

| 项 | 落地内容 | 关键取舍 |
|---|---|---|
| 删除墓碑 | 本地删除写 `tombstones.json`，与云端 `data/.tombstones.json` 合并；30 天过期、上限 500 条 | **只对目录型数据集**（技能包/安装包）；设置/对话删了就是清空，太危险 |

新增 pref：`cloudSyncPropagateDelete`（默认 true）。单测 198 项，新增墓碑/合并/文件名/冲突列表 28 项。

## 8. 不建议做的事
