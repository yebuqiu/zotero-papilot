核心结论
  • 可复用面比想象中窄：100 个里 AGPL-3.0（39 个）＋ GPL-3.0（12 个）合计 51 个属强 copyleft，Papilot 为 Apache-2.0，这些项目的代码一律不能搬；另有 26 个仓库无任何许可证（默认保留所有权利），同样不可复用。真正能从许可证层面"拿来就用"的只有 23 个宽松/文件级许可项目，其中经适配性核查后我给出 A 级（建议直接复用）的是 13 个。
  • 最值得立刻采用的是 3 个：windingwind/zotero-plugin-toolkit（MIT，插件开发底座，可大幅削减 Papilot 的 UI/菜单/偏好面板样板代码）、volatile-static/Chartero（Apache-2.0，阅读统计图表，同族许可零摩擦）、cookjohn/zotero-mcp（MIT，把 Papilot 能力以 MCP 对外开放的生态位）。
  • 功能重叠度很高但只能"抄思路"：翻译（zotero-pdf-translate）、中文元数据（jasminum）、分区列（zotero-style / updateifsE）、阅读状态（reading-list）、AI 精读（AI-Butler / papersgpt）都与 Papilot 正面重合，且几乎全是 AGPL —— 建议作为功能对标清单而非代码来源。
  • 生态位机会：Papilot 的差异化不在"再做一个 AI 问答"，而在于账号+模型通道+账号后台这套别人没有的基础设施，以及可把能力以 MCP/本地 API 形式对外供给（上游目前只有 ZotServer、zotero-mcp 等少数且多已停滞）。
  • 关于"热门"的提醒：Top 10 中有 3 个（zotfile、ai4paper、suppr）要么无许可证、要么已停滞 —— 星数不代表可复用性，务必以许可证与维护状态为准绳。

一、调研方法与口径

数据获取：通过 GitHub Search API 以 topic:zotero-plugin、topic:zotero、zotero in:name、zotero in:description、zotero-7 in:name,description 等 7 组查询抓取共 678 个去重仓库；再用社区维护的 zotero-chinese/zotero-plugins 官方插件索引（138 个在架插件）交叉核对，补回 4 个被初筛漏掉的高星项目（ai4paper、suppr、Aria、Beaver）。最终在甄别掉客户端本体（zotero/zotero、Android/iOS 版）、数据集（styles、translators）、库与周边（pyzotero、papis）后，取按 Star 排序的前 100 个真实可安装 Zotero 插件/扩展。

字段口径：Star、Forks、许可证、最近提交时间均取自 GitHub API 快照（2026-10-02）；缺少 SPDX 许可证的仓库经 /repos/:owner/:repo/license 二次探测（Licensee 识别），仍无结果者记为「未识别（保留所有权利）」。

活跃维护分级：按默认分支最近一次推送距今天数 —— 活跃 ≤30 天、维护中 31–180 天、低活跃 181–365 天、停滞 >365 天（归档项目单列）。该指标为近似值，可能包含仅由机器人/依赖更新触发的提交。

复用评级定义：A 可直接复用代码（许可证兼容 + 架构契合）｜B 仅可借鉴实现（AGPL/GPL 传染或架构差异）｜C 竞品对照/仅参考｜D 不建议。

三、推荐清单（按采用优先级排序）

第一梯队 · 建议直接采用

许可证与 Papilot（Apache-2.0）兼容或同族 —— 可以合法地直接复用代码/模块，且与现有能力互补。

  1. windingwind/zotero-plugin-toolkit★ 200 ｜ MIT ｜ 维护中

    MIT 许可、与 Apache-2.0 完全兼容、专为 Zotero 7+ 插件打造。Papilot 目前大量 UI/菜单/偏好面板/通知逻辑是手写样板，长期维护成本高；引入该工具包可把这块收敛为可复用层，是投入产出比最高的一项。

  2. volatile-static/Chartero★ 519 ｜ Apache-2.0 ｜ 维护中

    Apache-2.0 与 Papilot 同族许可，阅读统计与图表模块可直接复用（保留声明即可），补强「文献统计图谱」这一现有薄弱环节，且法律摩擦为零。

  3. cookjohn/zotero-mcp★ 1,201 ｜ MIT ｜ 活跃

    MIT 许可；把 Papilot 的库检索、全文读取、批注写入能力以 MCP 暴露给外部 AI 客户端，是「让别人的 Agent 用你的能力」的生态位，与 Papilot 的 AI 定位互补而非竞争。

  4. dcartertod/zotero-plugins★ 211 ｜ Apache-2.0 ｜ 低活跃

    Apache-2.0，一组小功能实现，可逐项甄别后直接并入「功能中心」，零许可风险地补长尾能力。

  5. SciImage/zotero-attachment-scanner★ 135 ｜ MIT ｜ 活跃

    MIT 许可，「库健康」是 Papilot 已有栏目，其扫描分类逻辑可直接复用或对照补齐，风险低。

  6. retorquere/zotero-better-bibtex★ 7,181 ｜ MIT ｜ 活跃

    MIT 且高度成熟：导出与 citekey 逻辑是 LaTeX 用户的刚需，Papilot 若补「导出/引用键」可直接复用原子模块；更稳妥的做法是检测到 BBT 时走共存联动。
