# 启动管理控制台 · v1.8.0 重构设计

> 对象：`启动Papilot后台.bat` / `启动Papilot后台.vbs` → `scripts/launcher.ps1`（Windows PowerShell 5.1 + WinForms）
> 目标：让控制台与「服务端 1.8.0 + 插件 0.45.x」的真实运行形态一致，从「进程开关面板」升级为「账号/AI 计费/通道/告警」的统一运维台。

---

## 1. 设计依据：最近更新带来的控制台影响

| 近期变更 | 对运维的实际影响 | 控制台必须怎么改 |
|---|---|---|
| **服务端 1.8.0：取消「赠送调用次数」**，`dailyLimit` / `user.dailyLimit` / 429 全下线 | 旧控制台「套餐与收款」还在编辑每日额度；用户列表还在显示 `今日 x / 上限 y`，改出来的配置会被服务端忽略 | 删除每日额度输入；用户列表改为「AI 余额 + 今日调用」；提示文案明确「无次数上限」 |
| **Pro 每月 ¥20 额度**（不结转），Free 仅注册赠送 ¥6 | 控制台看不到月度额度与发放口径，客服无法解释「为什么这个月只有 ¥20」 | 套餐页改编辑「每月额度 ¥」；总览新增「计费阀门」卡 |
| **`balance.enforce=true`**：余额不足（含 0）→ 402 | 用户报「AI 用不了」时，第一个要判断的是余额/阀门，而不是端口 | 总览显示拦截开关；计费页显示注册赠送、Pro 月度额度、充值档位、在线支付状态 |
| **1.7.0 在线支付**（易支付/码支付，默认关） | 未配置时仍走收款码 + 人工核销；控制台需要能一眼看出「自动到账是否可用」 | 计费页新增「在线支付：已启用 / 未配置」；未配置时给出配置入口 |
| **1.7.1 `cost.last` / 成本看板** | 排障时要看「谁在烧钱、单价有没有配」 | 计费页暴露 `pricedModels / meteringGaps`；提供成本看板入口 |
| **公网通道便携化（runtime/）** | 换盘后 `token.txt` / `cloudflared.exe` 可能缺失，现象是公网 530 | 服务页显示通道依赖自检（exe / token / 运行器） |
| **`/api/health` 扩展**（users / ordersAwaitingReview / meteringGaps / backlog / snapshots / sessionsActive / onlinePay…） | 旧控制台只用了「ok」，大量运维信号被浪费 | 总览 KPI 与运维页直接消费这些字段 |
| **0.44.x 插件更新提示 / 0.45.x** | 控制台不知道本机装的是哪版、dist 里最新 xpi 是哪版 | 维护页显示「插件 manifest / 最新 xpi / 服务端版本」 |
| **日志双轨缺陷**（cmd `>> server-console.log` 独占句柄 → Node `log()` 静默失败） | 「查看服务日志」经常是空的，误导排障 | stdout 改重定向到 `server-stdout.log`；控制台分别提供「服务日志 / 标准输出」 |

### 现有控制台的结构性问题

1. **单页堆叠**：5 个 GroupBox 从上往下排，472×672 固定宽，功能一多就靠「打开另一个对话框」，导航不可见。
2. **只监控「进程/端口」**：没有计费、告警、审计、快照等业务状态。
3. **操作无留痕**：启动/停止/重启/快照等控制台动作不进任何日志（服务端审计只管 HTTP 管理写操作）。
4. **异常处理靠 MessageBox**：没有「启动中 / 降级 / 刷新失败」的持续状态，也没有托盘告警。
5. **与 1.8.0 口径冲突**：会员管理里仍可编辑每日次数，用户列表仍显示次数上限。

## 2. 核心功能模块与交互流程

### 2.1 总览（overview）

- **进入即刷新**：服务状态（本地 3s 轮询）+ 健康快照（缓存 4s）。
- 四张状态卡：账号后台 / 公网通道 / AI 模型通道 / 计费阀门。
- 六个 KPI：用户数、待核销订单、未配价模型、活跃设备、告警积压、快照数。
- 快捷操作：启动 / 停止 / 重启、打开管理页、测试公网、立即刷新。
- 最近事件：控制台本地操作审计（最近 8 条）。

流程：`打开控制台 → 总览 → 看四卡是否全绿 → 异常卡点进对应分页`。

### 2.2 服务与通道（services）

- 账号后台：状态行（PID / uptime / 版本）、启动/停止/重启（停止与重启二次确认）、服务日志、标准输出。
- 公网通道：状态行（已连接 / 进程在未连边 / 未运行）、启动/停止/测试访问、通道日志、依赖自检（cloudflared.exe / token.txt / 运行器）。
- AI 模型通道：活动通道与默认模型、上线模型数 / 高级模型数、通道管理、打开网页管理。
- 底部：端口与数据目录事实说明。

流程：`服务异常 → 看状态行是 stopped / starting / degraded → 重启（确认）→ 停留观察 uptime 与健康`。

### 2.3 计费与会员（billing）

- 计费口径：余额拦截开关、注册赠送、Pro 每月额度、在线支付状态。
- 套餐与价格：Free / Pro 的每月额度、高级模型、当前价格档位（读 `/api/plans`，缓存 60s）。
- 数据健康：已配价模型数、未配价模型数（`meteringGaps`）。
- 入口：会员管理（订单/激活码/价格/套餐/审计）、用户列表、打开网页管理页。
- 固定说明：**1.8.0 起无每日调用次数上限；余额是唯一阀门；auto 恒按基础档计费**。

流程：`用户报 AI 402 → 计费页确认 enforce / 余额口径 → 用户列表查余额 → 会员管理调账或充值`。

### 2.4 运维与告警（ops）

- 告警与积压：`backlogCount / backlogOldestMinutes / backlogOverdue`、邮件告警是否配置、立即巡检。
- 数据健康：`meteringGaps`、`pricedModels`、快照数 / 最近快照、审计体积、活跃设备 / 超限设备。
- 数据快照：立即快照（写 `launcher-audit`）、打开备份目录、最近快照 ID。
- 最近管理审计：`/api/admin/audit?limit=8`，时间 / 动作 / 对象 / 结果。

流程：`告警积压 > 0 → 立即巡检 → 去会员管理核销；改配置前先立即快照`。

### 2.5 维护与关于（about）

- 开机自启（账号后台 + 公网通道）、数据目录、项目目录、安装包（dist 最新 xpi）。
- 运行环境：node 路径、运行时目录、cloudflared / token 是否存在。
- 版本：服务端（health）、插件（manifest.json）、最新 xpi、站点地址。
- 退出说明：关闭窗口 = 托盘驻留；「退出程序」不影响已启动的服务与通道。

- **导航**：左侧 5 项，单选高亮；不嵌套二级菜单，所有深操作仍走既有对话框（通道管理 / 会员管理 / 用户列表）。

- **底部状态条**：`$lblMsg` 承载操作结果，右侧显示最后刷新时刻——用户永远知道「数据是不是新的」。
- **窗口**：1000×700，固定边框（不做自由缩放，避免 WinForms 布局重排引入不可控回归）。

## 4. 关键 UI 状态与异常处理

### 4.1 服务状态机

| 状态 | 判据 | 界面 | 按钮 |
|---|---|---|---|
| running | 端口 8000 有 node 监听且 `/api/health.ok` | 绿灯「运行中（PID / 已运行）」 | 启动禁用，停止/重启可用 |
| starting | 端口在听但健康未就绪且进程 < 30s；或进程在但端口未通 | 黄灯「启动中」 | 启动禁用，停止可用 |
| degraded | 端口在听但健康不过且进程 ≥ 30s | 橙灯「服务异常」 | 停止/重启可用 |
| stopped | 无端口、无进程 | 红灯「未运行」 | 启动可用 |

启动超过 40s → 底部提示查 `server-console.log`（只提示一次）。重启用「先停后起」，最多等端口释放 10s。

### 4.2 通道与模型

| 场景 | 界面 |
|---|---|
| `/ready.readyConnections > 0` | 绿「已连接 pp.xinglintools.top」 |
| 进程在、未连边 | 橙「进程在，尚未连接边缘」 |
| 无进程 | 红「未运行（插件无法连接账号服务器）」 |
| 活动通道存在 | 绿「活动通道：名称（模型）· 共 N 个」 |
| 无活动通道 / 无通道 | 橙「未设置活动通道（503）」/「暂无通道」 |
| 后台未连接 | 灰「后台未连接」 |

### 4.3 计费状态

| 场景 | 界面 |
|---|---|
| `balanceEnforce=true` | 绿「余额拦截：开启（余额不足 402）」 |
| `balanceEnforce=false` | 橙「余额拦截：关闭 —— 等于不限量，仅压测用」 |
| `onlinePay=false` | 灰「在线支付：未配置（收款码 + 人工核销）」 |
| `meteringGaps>0` | 橙「有 N 次调用缺 usage，成本未知 → 去补价/查上游」 |
| 后台未连接 | 计费页整体灰显 + 「后台未连接」 |

### 4.4 操作与异常

| 场景 | 处理 |
|---|---|
| 端口被非 node 进程占用 | MessageBox 显示进程名 + PID，不启动 |
| 停止/重启 | 二次确认（会中断在线 AI 请求） |
| 双击启动/重复点击 | `$script:busy` 互斥；按钮短暂禁用 |
| 快照/巡检/审计 API 失败 | 底部红字 + MessageBox 详情（`Get-HttpErrorDetail`），不清空旧数据 |
| 日志文件不存在 | 提示「该日志尚未产生」，并给出文件路径 |
| token.txt / cloudflared.exe 缺失 | 启动通道前直接拦截，提示补依赖与 `refresh-token.ps1` |
| 刷新超时 | 保留上一份数据，状态点转灰，底部标注最后成功时间 |
| 控制台自身异常 | 定时器 `try/catch` 兜底，绝不让刷新异常打断窗口 |

## 8. v1.8.1 补丁：启动可靠性 + 卡顿治理（2026-10-17 13:xx）

### 8.1 现场问题与根因

| 现象 | 根因 |
|---|---|
| 双击后「没反应」/重复双击只弹一个看不见的提示 | wscript 是异步的，返回 0 不代表 PowerShell 真起来了；隐藏进程的 MessageBox 容易被其他窗口盖住；重复启动只弹提示、不激活已有窗口 |
| 启动后很卡 | 3s 定时器在 **UI 线程**上串行做：`Get-NetTCPConnection`（200~800ms）+ `Get-CimInstance node/cloudflared`（200~800ms）+ `/ready` 1s + `/api/health` 2s；`Shown` 里还先做一轮 2~4s 的网络探测，窗口「出来了但点不动」 |
| 打开控制台不会拉起服务 | 旧逻辑只检测状态，启动/通道都要手点 |

### 8.2 修复内容

1. **默认自动拉起**：`Start-ServicesOnBoot`（HKCU `Papilot\AutoStartServices`，默认 1）在首屏 250ms 后执行——后台未运行则 `Start-Server`，通道进程不在则 `Start-Tunnel`；维护页新增复选框可关闭。
2. **探测分层 + 缓存**：
   - 端口状态用 150ms TCP 连接（`Test-PortOpen`），不再每拍 `Get-NetTCPConnection`；PID 只取一次并缓存。
   - 进程列表：node 60s / cloudflared 30s 缓存，启动/停止时主动失效。
   - `/ready` 改 `WebRequest` 400ms 硬超时，每 9 秒一次；健康 1s、6 秒缓存；通道列表 60 秒。
3. **首屏不等网络**：`Shown` 只画界面 + 读本地事件，首次网络探测放到 250ms 后的一次性 timer。
4. **启动可观测**：`%TEMP%\papilot-launcher-boot.log` 记录每个阶段；脚本级 `trap` 与 UI 线程异常都写日志并弹「默认桌面」提示；重复启动优先 `FindWindow + SetForegroundWindow` 激活已有窗口（P/Invoke 首参必须 `IntPtr.Zero`，`$null` 会变成空串导致永远找不到窗口）。
5. **bat 存活确认**：wscript 之后最多等 12s，用 launcher 写下的 `%TEMP%\papilot-launcher.pid` + `System32\tasklist.exe` 确认进程真的活着；失败时打印启动日志路径并 pause。探测命令全部用 `%SystemRoot%\System32\` 绝对路径，避免被 MSYS/Git 的 `find.exe` 抢占。

### 8.3 实测（本机 1920×1080）
