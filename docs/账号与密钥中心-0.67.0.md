# 账号与密钥中心（0.67.0，专业版）

> 面向维护者与验收者。功能说明给用户看的部分在「使用教程 · 三、期刊分区秘钥」末尾有入口指引。
> 一句话：把散落在多张设置卡里的第三方凭据收进一个窗口，统一做**脱敏查看 / 受控编辑 / 加密托管 / 访问审计**。
>
> 0.67.0 起：覆盖 **8 类**凭据；知网改为「账号+密码」合并托管；新增可逐项开启的**仅托管模式**（本机不留明文）。

---

## 1. 为什么做、边界在哪

第三方凭据原本分散在设置面板的不同卡片里：

| 凭据 | 原落点 | 卡片 |
|---|---|---|
| 知网用户名 / 密码 | `cnkiUsername` / `cnkiPassword`（base64 混淆） | 文献获取 · 知网账号与校园网 |
| 坚果云邮箱 / 应用密码 | `cloudSyncEmail` / `cloudSyncToken`（明文） | 数据与同步 · 云同步与备份 |
| easyScholar SecretKey | `easyScholarKey`（明文） | 条目与标签 · 列表数据列 |
| 自定义 AI 通道 Key | `aiChannels` JSON 内的 `apiKey`（明文） | AI 能力 · AI 模型通道 |
| 第三方文献源站点 / 账号 / 密码 | `thirdSourceSite` / `thirdSourceUsername` / `thirdSourcePassword`（base64） | 文献获取 · 第三方文献源（试验） |
| Semantic Scholar API Key | `s2ApiKey`（明文） | 条目与标签 · 数据列 |
| MCP 访问令牌 | `mcpToken`（明文） | 集成与互操作 · MCP 对外供给 |
| 旧版单通道 Key（历史） | `aiApiKey`（明文，仅在有值时列出） | — |

分散带来三个真实问题：**看不到全貌**（换了电脑忘了哪几项要重填）、**明文裸露**（截图、录屏、同事瞄一眼就泄露）、**没有痕迹**（谁在什么时候改了 Key 无从查起）。

本功能不改变任何**消费方**的读取方式——这是刻意的设计约束：

> 知网登录、坚果云 WebDAV、分区列查询、AI 调用这些热路径都在**同步**代码里读 pref。
> 一旦把它们改成异步（例如从系统密钥库或服务端取），登录、同步、列渲染都会引入
> 时序依赖，故障面远大于收益。

因此本功能的定位是 **「统一视图 + 访问控制 + 备份通道」**，而不是「把 pref 换成加密存储」。

## 2. 四层结构

```
设置面板「账号与会员」卡 → [打开凭据中心]  ┐
工具菜单 · 功能中心 ▸ 账号与密钥         ├→ vault.xhtml / vault.js（窗口层）
功能中心 · 数据列与配置 → 账号与密钥     ┘        │
                                                  ├→ CredVault（核心域）
                                                  │     · 注册表 / 脱敏 / 口令 / 审计 / 门控
                                                  │     · pref 读写（保持消费方格式）
                                                  │     · 账号托管（/api/user/secrets）
                                                  └→ 消费方：CNAuth / CloudSync / RankColumn / Channels
```

- **窗口层** `chrome/content/vault.xhtml` + `vault.js`：只负责渲染与「什么时候可以把明文放进 DOM」。
- **核心域** `chrome/content/scripts/features/cred-vault.js`（`Zotero.Papilot.credVault`）：唯一写入点。
- **服务端** `server/account-server.js` 的 `/api/user/secrets/<name>`：AES-256-GCM 加密托管（1.9.1 起覆盖四类）。

## 3. 存储分层（诚实说明保护强度）

| 层 | 位置 | 强度 | 说明 |
|---|---|---|---|
| L1 本机 | Zotero pref（profile） | 混淆，**不是加密** | 密码类沿用 base64（与 `CNAuth.deobfuscate` 一致）；其余为明文。主要保护来自系统账户权限。 |
| L2 账号托管 | 服务端 `users.json` 的 `secrets.<name>.enc` | AES-256-GCM | 主密钥 `server/data/.secret.key` 不进备份；列表只回掩码；明文读取需登录 + 限速 + 审计。 |
| L3 访问层 | 窗口内 | 门控 + 口令 + 自动隐藏 | 默认全量脱敏；解锁才渲染明文；到期从 DOM 移除（不是 CSS 隐藏）。 |
| L4 审计 | `vaultAudit` pref | 仅本机 | 只记动作/条目/时间，最多 40 条，不含任何值。 |

**为什么不在本机做 AES**：WebCrypto 只有异步 API，而消费方是同步读 pref。用纯 JS 手写同步 AES-GCM 属于「自己造密码学」，出错方式还是静默的——不做。真正的机密性由 L2 提供；L1 的目标只是「别让 prefs 文件一眼看穿」。

### 托管名映射（必须与服务端白名单一致）

| 条目 | 服务端 secret 名 | 上限 |
|---|---|---|
| `cnki.pass` | `cnki_account`（`{u,p,v}` JSON）**+** `cnki_password` 兼容副本 | 400 / 200 |
| `nutstore.token` | `nutstore_token` | 200 |
| `rank.key` | `easyscholar` | 200 |
| `ai.*`（全部通道） | `ai_channels_keys`（`{channelId: key}` JSON） | 8000 |
| `third.pass` | `third_source_password` | 200 |
| `s2.key` | `s2_apikey` | 200 |
| `mcp.token` | `mcp_token` | 200 |

**知网为什么合并**：只托管密码的话，换机取回后仍要手填用户名，"一键恢复"是断的。
现在一条 `cnki_account` 同时存 `{u,p}`；上传前缺用户名会被**拒绝**（不制造半个恢复）。
同时写 `cnki_password` 兼容副本，让 0.66.x 及更旧客户端仍能取回密码。

AI 用**集合**而不是逐通道存：服务端白名单是静态枚举，动态名不可枚举；逐通道存也会让恢复变成 N 次请求。

## 4b. 仅托管模式（0.67.0，逐项可选）

目标：让**磁盘上真的没有明文**，而不只是"混淆过"。

打开某一项的「仅托管」后：

1. 先上传到账号（失败则不动本机，**避免"本机清了、云端也没有"**）；
2. 本机 pref 清空；
3. 值搬进内存副本 `CredVault._mem`（不落盘）；
4. `vaultHostedOnly` 记下条目 id，启动时 / 同步前 / 登录后水合。

消费方通过 `CredVault.cached()` 读（内存优先，其次 pref）：

| 消费方 | 读取点 | 水合时机 |
|---|---|---|
| 知网登录 | `CNAuth.creds()` | `hydrateVault()` 在 `_ensureAccess` / `loginInteractive`（都是 async） |
| 坚果云同步 | `CloudSync.config()` | `syncNow()` 开头、`main.js` 启动 + 会话恢复通知 |
| 第三方文献源 | `ThirdSource.creds()` | 启动水合（与知网共用） |

**代价必须说清**：离线或未登录 Papilot 账号时，该项不可用。所以它是 per-item 开关、默认关，
确认框里明写代价；UI 上显示「仅托管 · 需要登录并联网才能取回」。

**为什么不给 AI 通道**：通道 Key 嵌在 `aiChannels` JSON 里，清掉等于删通道；而且
`AIClient` 在同步路径读它，收益小于"删掉用户配置"的风险。

**绝不同步**：`vaultHostedOnly` 已进 `cloud-sync.js` 的 `NON_SETTING_LEAVES`。
同步过去会让另一台机器也清空本机凭据，而那边的登录/网络未必满足水合条件——等于远程关功能。

## 4. 访问权限控制

1. **门控**：`CredVault.access()` 用本地会员缓存判定（`Account.isPro()`），离线同样生效。未登录 / Free / 过期 → 锁定卡，**不渲染任何条目值**，只列出能力清单与升级入口。
   - 失败方向是 fail-closed：会员缓存损坏按 Free 处理。
2. **解锁**：
   - 设了访问口令 → 必须输入口令；连续错 3 次冻结 30 秒（内存计时，关窗重置）；
   - 没设口令 → 窗口内二次确认（说明「屋里所有人都能看到」并建议设口令）。
3. **自动隐藏**：`vaultAutoHideSec`（默认 30 秒，可选 15/30/60/永不）。任何点击重置计时；超时即 `lockNow()` → 重渲染，明文从 DOM 消失。
4. **口令存储**：`vaultPassHash = "salt:hash"`，`hash = SHA-256^8000(salt : pass)`。口令本身**不参与加密**，忘记后本机重置即可（不影响已存凭据）。
5. **明文边界**：不提供「复制明文」按钮（剪贴板会被其它程序读取且无法可靠清空）；用户要粘贴就在编辑框里自行 Ctrl+C。
6. **从账号取回要确认**：单字段取回是覆盖语义（AI 集合仍只填空缺），误点会让旧值当场消失。
7. **审计不可静默清空**：点「清空记录」会保留一条 `audit-clear` 留痕——"谁把痕迹擦了"也该能查到。

## 5. 写入后谁立即生效（回归重点）

| 动作 | 写入点 | 立即受影响的功能 |
|---|---|---|
| 改知网密码 | `cnkiPassword`（base64） | 设置面板「知网账号」下次登录；`CNAuth.creds()` |
| 改坚果云应用密码 | `cloudSyncToken`（明文） | 云同步下次请求（`CloudSync.config()` 同步读） |
| 改分区 Key | `easyScholarKey` | 分区列下次查询；`RankColumn.refreshHostedKey()` |
| 改 AI Key | `aiChannels` JSON | AI 调用下一次构建通道配置 |
| 从账号取回 | 同上 | 同上（覆盖本机值；AI 只填空缺） |

**AI 取回策略**：只填充本机为空的通道，不覆盖已有 Key。多设备各配过不同通道时，覆盖会让另一台机器的配置凭空消失。

## 6. 不变量（改动前先读）

1. 明文**永不**进入日志、审计、云同步快照、导出文件。
2. 写入必须保持消费方格式：`cnkiPassword` = base64；坚果云/分区/AI 为原样字符串。
3. AI Key 只能整体写回 `aiChannels`，不能另存一份（两份不同步 = 面板显示新 Key、实际调用用旧 Key）。
4. 锁定时不渲染值，连「末 4 位」也不给（首尾片段足以在截图里认出密钥）。
5. 新增托管类型必须同步改：服务端 `HOSTED_SECRETS`、`CredVault.FIELDS[*].hosted`、本文件的映射表。
6. 新增 pref 必须判断是否进入云同步：`vaultAudit` / `vaultHostedOnly` / `vaultSelfTest` 进 `NON_SETTING_LEAVES`，`vaultPassHash` 进 `SECRET_LEAVES`。
7. 新增「仅托管」消费方时，读取处必须走 `CredVault.cached()`，且在 async 上下文里先 `await hydrateHostedOnly()`；
   漏了这一步的表现是「开了仅托管，功能静默失效」（本机看起来"没配置"）。

## 8. 运维

- 服务端 1.9.1 起支持四类托管；改完必须**同轮重启生产 :8000**（`scripts/start-account-server.ps1`，先 `Stop-Process` 旧 PID）。
- 换机器要带走 `server/data/.secret.key`，否则已托管的凭据解不开（表现为「账号里没有保存该项」，不会半残运行）。
- 托管读取有每账号每分钟限速（`PP_SECRET_GET_MAX`），批量取回失败时先看 429。
