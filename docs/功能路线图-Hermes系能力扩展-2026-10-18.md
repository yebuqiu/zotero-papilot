# Papilot 功能路线图：Hermes 系能力扩展（2026-10-18）

> 背景：0.50.0 已落地 Hermes 式的八项能力（Agent 工具/记忆前置/定时任务/MCP/技能沉淀/路由/画像/审计撤销）。
> 本文回答「后面还能做什么」，按「价值 × 投入」排序，并给出建议的版本节奏与明确不做的清单。
> 参考项目：Hermes Agent（工具/MCP/子代理/记忆）、zotero-addons（插件市场）、zotero-gpt、
> Better Notes（模板/工作台）、Connected Papers / Litmaps（引文图）、Scite（引文上下文）、
> Elicit / Consensus（证据综合）、NotebookLM（源约束综述）、OpenAlex / Semantic Scholar（元数据与推荐）。

## 一、已完成基线（不重复建议）

Agent 模式（11 工具 / 多轮回 / 写确认 / 审计撤销 / 沉淀 / 路由 / 画像）、MCP 双工具外供桥、
会话持久化、定时任务（晨报/周报/库体检）、技能商店 45 包 + 社区投稿链路、术语领域化、
PDF 左原右译、阅读进度 2.0、AI 打标签 v2、参考文献一键入库、知网登录、第三方文献源实验。

## 二、十个候选（按建议顺序）

| # | 功能 | 做什么 | 为什么值得 | 复用什么 | 投入 | 风险 |
|---|---|---|---|---|---|---|
| 1 | **AI 回答内引用可点击** | 把回答里的「文献 n /（作者, 年份）」渲染成可点 chip，点击定位/打开条目；无匹配时灰色 | 低成本高体感；把「AI 说了什么」变成「一秒看到原文」 | chat-float 气泡渲染 + `_chipItems` | 小 | 低 |
| 2 | **Agent 长期记忆** | pref 化的记忆库（项目/结论/偏好三类），两个新工具 `memory_read` / `memory_write`（写需确认+可撤销），设置面板可浏览/删除，`/记忆` 快捷查看 | Hermes 的记忆是「越用越懂你」的核心；与画像互补：画像=静态偏好，记忆=动态事实 | AgentTools 注册表 + 审计撤销 + pref LRU | 中 | 中（记忆污染→需人工可审可删） |
| 3 | **相关文献推荐（S2/OpenAlex）** | 条目详情页新增「相关文献」区：按标题+摘要取 S2 recommendations，展示 5 条（标题/年份/被引/来源），一键入库+打 `#来源/S2推荐` | 研究者最刚需的一步（顺着一篇找到一串）；zotero-addons 生态里同类需求旺盛 | S2Client + RefImport + 一条新端点 | 中 | 低（公开 API 限速） |
| 4 | **引文上下文（Scite 风格）** | 给定 DOI，拉引用它的论文中**引用句**（S2 citations API 带 contexts），标注支持/对比/批评倾向，输出「谁怎么引了它」清单 | 判断一篇工作的真实影响力；审稿/综述直接可用 | S2Client + 新增 MCP/Agent 工具 `get_citation_context` | 中 | 低-中（API 覆盖不全） |
| 5 | **元数据医生（检测→修复）** | MetaLint 已有「查」，补「治」：选中条目按标题反查 Crossref/DOI，预览差异 → 一键补 DOI/期刊/年份/作者；批量+可撤销；修复前后对照表 | 库治理闭环（检测无修复=半成品）；对中文库尤甚 | MetaLint + 审计撤销 + 离线可测的 diff 预览 | 中 | 中（错误匹配→必须预览确认，不自动写） |
| 6 | **检索订阅（Saved query → 定时入库）** | 定义检索式（arXiv 分类+关键词 / Crossref 查询），定时（复用 Scheduler）执行，新结果去重后入库+自动打标签+生成「订阅速递」笔记 | 把「每日晨报」从「看看库」升级为「自动长大」；Hermes 的定时任务语义完整化 | Scheduler + ArxivFetch + 去重（DOI/标题指纹）+ 自动标签 | 中 | 中（重复入库→指纹去重必须可靠） |
| 7 | **标注→论点速记** | 在阅读器选中若干标注（或整页标注）→ AI 整理成「论点-证据-页码」三条目笔记；可一键入 literature matrix | 把「划线」变成「可写进论文的素材」，阅读产出率最高的一步 | Reader API 批注读取 + 现有提示词风格 | 小-中 | 低 |
| 8 | **综述工作台（旗舰）** | 选 10-30 篇 → 生成分节大纲（复用 survey-writer）→ 逐节起草，引用为**真实条目链接**（文献 n → itemID）→ 导出 MD/docx（复用 export 四件套） | 从「读文献」到「写出初稿」的产线闭环，是 Elicit/NotebookLM 的核心价值 | 已有：综述提示词、文献矩阵、docx 导出、bilingual 导出链 | 大 | 中（幻觉→强制引用约束 + 逐节人工确认） |
| 9 | **多篇对比阅读** | 同主题 3-5 篇并排：方法/数据/样本/结论/局限自动对齐成表，点击单元格跳原文位置 | 综述与开题的高频动作；Litmaps 式「横向对照」 | PDF 文本层 + 表格生成 + 现有双栏窗口壳 | 大 | 中（版面与长文档性能） |
| 10 | **技能包 JS 沙箱 v2** | 允许技能包含受限 JS（Cu.Sandbox + 能力 API：读条目/发通知/写笔记），签名+权限清单+人工审核 | 生态跃迁（从「声明式配置」到「可编程扩展」）；zotero-addons 证明插件市场可行 | 现有商店/审核/记账体系 | 大 | **高**（安全）→ 必须最后做，且默认关闭 |

## 三、建议的批次节奏

- **0.51（下一批，2 周内）**：#1 引用可点击 + #2 Agent 记忆 + #3 相关文献推荐
  - 理由：三个都直接乘在 0.50.0 的新底座上（气泡/审计/工具注册表/S2），边际成本最低；
  - 验收：引用点击跳转成功率、记忆写入可撤销、推荐条目一键入库。
- **0.52**：#4 引文上下文 + #5 元数据医生 + #7 标注速记
  - 理由：把「治理」与「证据」两块补齐，均为单点工具、可独立验收。
- **0.53**：#6 检索订阅 + #8 综述工作台
  - 理由：订阅依赖 Scheduler v2 的去重与限流；综述工作台是旗舰，值得单独一个版本讲清楚。
- **0.54+（观察需求）**：#9 多篇对比阅读；#10 JS 沙箱（安全评审单独立项，先出 RFC 再动工）。

## 四、明确不建议做的（防止跑偏）

1. **重造 Zotero 原生能力**：PDF 阅读器、引文插入（Word 插件）、同步、重复合并的原生实现——只在原生之上做 AI 增强层。
2. **服务端重型协作**（团队批注/共享库）——Zotero Groups 已覆盖 80%，且会引入合规与运维负担；共享术语库可先借 open-termbank 轻量实现。
3. **无审计的自动写库**（自动合并重复、自动改元数据）——本项目纪律是「写操作可确认、可撤销」；任何批量写必须先预览。
4. **多智能体编排（子代理）**——Hermes 有，但单机文献场景收益低、调试成本高；等记忆与工具生态稳定后再评估。
5. **追热点式功能**（AI 生图/播客摘要）——与科研工作流弱相关，分散维护精力。

## 五、判断依据（为什么这样排序）

- **复用度**：0.50.0 刚建成的四个底座（工具注册表、审计撤销、Scheduler、S2/arXiv 客户端）让 #1-#4 的增量成本最低。
- **可验证性**：每个候选都能写成「单测 + 真机一条命令」的验收断言（本项目门禁文化），#10 例外（需安全评审）。
- **失败代价**：#5/#6 涉及批量写库 → 必须「预览+撤销」；#8 涉及生成内容 → 必须「引用约束+逐节确认」；#10 安全风险最高 → 最后做。
- **用户价值密度**：引用点击（每次对话都受益）> 记忆（跨会话复利）> 推荐（每次找文献都受益）> 其余。
