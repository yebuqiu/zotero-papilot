# Papilot 设置面板设计改进方案（0.72.1）

> 依据《设置面板设计审查裁决》逐条产出的可落地设计改进方案。
> 对象：`chrome/content/prefs.xhtml`（19 卡 / 7 类）+ `chrome/content/prefs.css`（令牌制）。
> 原则：**收敛回既有令牌体系，不推翻重做**；优先「只改 CSS / 类名 / 属性」的改法，动结构的改动单独标注工作量。
> 所有对比度数字均为真实计算（WCAG 相对亮度公式，alpha 先按合成背景再求比值；复算结果与裁决一致：4.34 / 4.17 / 4.19 / 3.92 / 3.10 / 1.33 / 1.55），非记忆估算。

---

## 1. 设计决策总述

### 1.1 视觉方向（一句话）

延续既定的 **GitHub Primer 式卡片设置页**不动摇，本轮只做三件事：**把游离值收编进令牌、把状态色的对比度补到 AA、把「长得像按钮的 span」全部变成真按钮**——视觉语言不变，可信度与可用性上一个台阶。

结构指纹：目录式长页 × Primer 中性灰蓝 × 无增强手法（纯控件语言）。这个指纹是对的，不需要换。

## 2. P0 / P1 逐项设计方案

### P0-① 77 处 emoji → 内联 SVG / 纯文字

**改什么**：`prefs.xhtml` 19 处 `.pp-card-icon` 的 emoji 文本；按钮内 emoji（⚡🔍📡👁×2🎲🌄↻×2）；提示文案里的 🔒☀️🌙⚡🖼🔑；搜索图标 `⌕`、折叠箭头 `▾`、清除钮 `×`、状态点 `●`。
**怎么改**：
- `.pp-card-icon` 容器已有 26×26 描边底托（accent-soft 底 + accent 色），把 emoji 换成 **16×16、stroke=currentColor、stroke-width=1.5、fill=none 的 Lucide 风格线图标**，直接内联 `<html:svg>` 进 xhtml（这些 span 无脚本读写 innerHTML，安全）。19 张卡选型（形状描述，绘制时按 Lucide/Feather 同名图标取路径）：

| 卡 | 现 emoji | SVG 选型（形状） |
|---|---|---|
| 账号与会员 | 👤 | 圆头 + 双肩人形（user） |
| AI 模型通道 | 🔌 | 两针插头带引线（plug） |
| AI 参数与智能体 | 🎛️ | 三条水平滑杆、各带一圆钮（sliders-horizontal） |
| 技能包商店 | 🧩 | 单块拼图（puzzle） |
| 翻译引擎与术语表 | 🌐 | 圆 + 经纬线（globe） |
| 阅读器划词浮窗 | 💬 | 圆角对话气泡带左下尾（message-square） |
| PDF 阅读主题 | 📖 | 摊开的书、中缝双线（book-open） |
| 知网账号与校园网 | 📚 | 两层叠书侧视（library，与「单本翻开」区分） |
| 第三方文献源 | 🧪 | 锥形烧瓶带液面线（flask-conical） |
| 检索订阅 | 📡 | 圆点 + 两道同心弧线（rss） |
| 定时任务 | ⏰ | 圆钟面 + 时针分针（clock） |
| 列表数据列 | 📊 | 三根不等高竖柱 + 基线（bar-chart-3） |
| 规则打标与 AI 打标 | 🏷️ | 斜置标签带圆孔（tag） |
| 工具与增强 | 🧰 | 扳手（wrench） |
| WPS 集成 | 🧩 | 文档轮廓 + 右上角折角 + 页内引号（file-text）——与技能包的 puzzle 区分开 |
| 界面主题与壁纸 | 🎨 | 调色板带四个色孔（palette） |
| 菜单定制 | 🧭 | 层级列表树：三行横线带缩进折线（list-tree） |
| 快捷键 | ⌨️ | 圆角矩形 + 3×3 键点阵（keyboard） |
| 云同步与备份 | ☁️ | 云朵轮廓内含上下双箭头（cloud + sync） |

- 按钮内 emoji：**一律去掉图标只留文字**（⚡推荐配置→推荐配置；🔍检测→检测；📡拉取→拉取；🎲随机美图→随机美图；🌄固定美图→固定美图；↻刷新→刷新）。按钮文字已自解释，图标是噪音。
- `👁` 密钥眼睛钮（2 处）：换内联 SVG eye / eye-off（切换时换路径），`aria-label="显示密钥"/"隐藏密钥"`。
- `⌕` 搜索图标 → SVG 放大镜（currentColor）；`▾` 折叠箭头 → SVG chevron-down（旋转逻辑不变）；`×` 清除钮 → SVG x；`●` 状态点（wps/cloud）→ 保留字符但加 `aria-hidden="true"`，颜色由 css 类控制，或改 `::before` 圆点。
- 提示文案里的 emoji（🔒☀️🌙⚡🖼🔑）：🔒/🔑 删字符改纯文字（「数据去向：」「账号与密钥」）；☀️🌙⚡🖼 是主题卡徽章的**图例**——主题卡由 themes 相关 JS 生成，需同步改 JS 把徽章换成文字标签（「浅」「深」「动」「在线」），xhtml 图例同步改文字。**这是唯一跨出 prefs 两文件的改动**。
**为什么**：裁决①；emoji 渲染随平台漂移、无双主题适配、读屏读出噪音。
**工作量**：M（xhtml 图标替换 S；主题徽章 JS 改动 S；合计 M）。

### P0-② 深色主按钮对比度 3.10 → ≥4.5

**改什么**：`prefs.css` `.pp-btn-primary` / `:hover` / `:active`。
**怎么改**：新增组件层令牌（见 §1.2.1），深色主题覆盖：
```css
.pp-root { --pp-btn-primary-bg: var(--pp-accent); --pp-btn-primary-bg-hover: var(--pp-accent-emphasis); --pp-on-accent: #ffffff; }
@media (prefers-color-scheme: dark) {
  .pp-root { --pp-btn-primary-bg: #1f6feb; --pp-btn-primary-bg-hover: #1158c7; }
}
.pp-btn-primary { color: var(--pp-on-accent); background: var(--pp-btn-primary-bg); border-color: var(--pp-btn-primary-bg); }
.pp-btn-primary:hover:not(:disabled) { background: var(--pp-btn-primary-bg-hover); border-color: var(--pp-btn-primary-bg-hover); }
```
**复测目标**：默认 4.63 / hover 6.47（浅色维持 5.19 / 6.95）。注意 `color: #ffffff` 裸值一并收编。
**工作量**：S（纯 CSS）。

### P0-③ 7 处 span 假按钮 + 弹窗可访问性

**改什么**：`#pp-register-link` / `#pp-forgot-link` / `#pp-reg-back` / `#pp-mb-code-toggle` / `#pp-bal-order-view` / `#pp-mb-order-view`（span.pp-link）；`#pp-account-email`（可点脱敏）；`#pp-mb-renew`（整张可点横幅）；`#pp-mb-compare-toggle`（已有 role/tabindex 但仍是 span）；付款弹窗 `.pp-dlg-close` span。
**怎么改**——统一「链接外观按钮」模式：
```xhtml
<html:button type="button" id="pp-register-link" class="pp-link-btn">注册账号</html:button>
```
```css
.pp-root .pp-link-btn { appearance:none; background:none; border:0; padding:0; font:inherit; font-size:var(--pp-fs-md); color:var(--pp-accent); cursor:pointer; }
.pp-root .pp-link-btn:hover { text-decoration:underline; }
.pp-root .pp-link-btn:focus-visible { outline:2px solid var(--pp-accent); outline-offset:2px; border-radius:2px; }
```
id 不变，面板脚本 `getElementById + addEventListener('click')` 不受影响；白得 Enter/Space 键盘触发。`#pp-mb-renew` 改 `<html:button type="button" class="pp-mb-renew">`（块级按钮，样式不变补 `width:100%;text-align:left;font:inherit`）。弹窗：关闭钮改真 button + SVG x + `aria-label="关闭"`；JS 补 **Esc 关闭 + focus trap**（打开时焦点进弹窗、Tab 循环、关闭后焦点归还触发按钮）；`role="dialog" aria-modal="true" aria-labelledby`。
**为什么**：裁决③。
**工作量**：xhtml+css S；弹窗 JS（Esc/trap）M。

### P0-④ 98 个 label 无 for= / 搜索框无 aria-label / QR 无 alt

**改什么**：全文件 `<html:label class="pp-label">` 与控件的关联。
**怎么改**——两种批量模式，按场景选：
1. **包裹式（首选，占大头）**：`.pp-field` 场景把 div 改 label，控件包进去，无需对 id：
```xhtml
<html:label class="pp-field"><html:span class="pp-label">邮箱</html:span><html:input …/></html:label>
```
`getElementById` 全部不受影响。`.pp-field` 的 `display:flex` 对 label 同样生效。
2. **for= 式**：label 与控件不同容器时（如工具条行内 `<html:span class="pp-label">官方模型</html:span>` + select）→ span 改 `<html:label class="pp-label" for="pp-account-official-model">`；目标无 id 的补 id。
3. 搜索框 `aria-label="搜索设置项"`；QR 两张图 `alt="付款二维码，请用手机扫码支付"`；占位说明性空 label（`&#160;` 那处）改 `aria-hidden` 占位 div。
**为什么**：裁决④。包裹式零 id 协调成本，是 98 处规模下唯一现实的改法。
**工作量**：M（机械但量大，建议按卡分批提交）。

### P1-⑥「测试连通」动词与反馈位统一

**改什么**：动词散在「实测 / 检测权限 / 检测入口 / 检测本机自建服务 / 重新检测 / 保存并测试 / 连接测试」；反馈位散在卡片底部（`#pp-ch-test-result` / `#pp-tr-test-result`）vs 行内。
**怎么改**：
- 动词表收敛为四个（详见 §4.1）：连通性一律「**测试连接**」，授权探测「**检测权限**」，本机服务发现「**扫描本机服务**」，状态更新一律「**刷新**」（删「重新检测」）。
- 反馈位规范：**一律行内**——触发按钮右侧跟一个 `.pp-msg` 反馈槽（`.pp-row` 内最后一个孩子），禁止跳到卡片底部。通道卡把每行的「实测」结果槽移回行内（`#pp-ch-test-result` 降级为表单级错误的兜底位）；翻译卡保持行内不动。
- 反馈文案格式统一：`成功 · 延迟 320ms · 模型 42 个` / `失败 · 401 密钥无效`（动词开头，分隔用 ·）。
**为什么**：裁决⑥。
**工作量**：S（文案 + 个别槽位移动；通道行是 JS 生成，改生成模板）。

### P1-⑨ 焦点环 1.33 / 1.55 → ≥3:1

**怎么改**：所有 `:focus-visible` 处从单层 alpha 光晕改为**实色主环 + 可选光晕**：
```css
.pp-root :where(.pp-btn, .pp-input, .pp-select, .pp-textarea, .pp-fold-head, .pp-ts-chip):focus-visible {
  outline: none;
  border-color: var(--pp-accent);
  box-shadow: 0 0 0 2px var(--pp-accent), 0 0 0 4px var(--pp-focus-ring);
}
```
实测：实色 2px 环 浅 5.19 / 深 4.97（≥3:1 ✓）；alpha 提到多少都不够（.65 也只有 2.89），实色是唯一解。输入类控件已有 `border-color: accent`，叠加即可。
**工作量**：S。

## 4. 交互一致性规范建议

### 4.1 按钮动词表（收敛后）

| 语义 | 统一动词 | 废弃说法 |
|---|---|---|
| 连通性测试 | **测试连接** | 实测 / 检测入口 / 保存并测试（改「保存并测试连接」）/ 连接测试 |
| 权限/授权探测 | **检测权限** | —（仅知网一处） |
| 本机服务发现 | **扫描本机服务** | 检测本机自建服务 |
| 状态刷新 | **刷新** | 重新检测 / 刷新状态 / 刷新余额 / 刷新会员（→ 刷新 + 语境由位置提供） |
| 拉取上游列表 | **拉取模型列表** | 📡 拉取 |
| 自动识别 | **自动识别** | 🔍 检测 |
| 导出/导入 | 导出到剪贴板 / 从剪贴板导入 | （现状已统一，保持） |
| 破坏操作 | 动词 + 对象（清除凭据 / 取消订单 / 删除托管） | — |

### 4.2 反馈位规范

- **行内优先**：一切按钮触发的结果，反馈出现在**同行右侧 `.pp-msg` 槽**；没有行内槽的（表单级错误）才用区块底部槽。卡片底部不再出现「跳出来的远端反馈」。
- 所有 `.pp-msg` 反馈槽统一加 `aria-live="polite"`（动态文本对读屏可见，一处 css 类管不住 aria，需 xhtml/JS 补属性）。
- 文案格式：`结果 · 关键参数`（如 `成功 · 延迟 320ms`），成败色走 `--pp-success` / `--pp-danger-fg`，加载中走 `--pp-muted`。

### 4.3 可交互元素模式

1. **任何可点的东西都是 `<html:button>`**；需要链接外观时用 `.pp-link-btn`（§2-③ 的样式块）；需要块级横幅可点时用 `button` + `width:100%;text-align:left`。
2. 禁止新增 span/div + cursor:pointer + click 监听的模式；code review 门禁词：`class="pp-link"` 出现在 span 上即打回。
3. 按钮八状态实现现状盘点：default/hover/focus-visible/active/disabled 已有；**loading / error / success 缺**——规范：异步按钮点击后进入 loading（`disabled` + 文案「…中」+ `aria-busy="true"`），结果经行内 pp-msg 槽呈现 error/success，按钮本体不常驻成败色。

### 4.4 渐进披露模式

- 统一用原生 `<html:details class="pp-disclose">`（summary 文案 = 「更多条件」/「高级参数（…）」，动词-free 名词式）；
- 何时用：单区控件 >6 个、或存在「日常不需要碰」的参数组；
- 表单被外部填充时（如 AI 解析回填）必须自动展开对应 details，禁止「值被藏进折起来的区域」。
