# 翻译引擎可用性复核（2026-10-23，0.75.0）

> 起因：用户报「多个翻译接口无法正常调用」。本文记录**逐引擎实测结论**、根因与改动，
> 便于下次接口再变时快速定位。复核工具：`scripts/diag/probe-translate-live.js`（真实联网，
> 用**生产代码**逐个引擎跑一句样文，可 `--flow` 再走一次完整回退链）。

## 怎么复现这次复核

```bash
node scripts/diag/probe-translate-live.js            # 全部引擎（需密钥的自动跳过）
node scripts/diag/probe-translate-live.js edge bing  # 只探指定引擎
node scripts/diag/probe-translate-live.js --flow     # 再验证一次主流程（llm 不可用 → 回退链）
node scripts/diag/probe-translate-live.js --secret deepl=<key>   # 临时注入密钥（不落盘）
```

本机（中国大陆家宽，直连）2026-10-23 结果：

| 引擎 | 结果 | 说明 |
|---|---|---|
| `edge` | ✅ 594ms | 修复后（新端点） |
| `bing` | ✅ 2076ms | 旧链路仍可用，但每次要取页面参数 |
| `youdao` | ✅ 102ms | 可用 |
| `transmart` | ✅ 327ms | 可用（偶有「1.」编号噪声，属对端行为） |
| `mymemory` | ✅ 887ms | 可用（限额低） |
| `google` / `googleapi` | ❌ 超时 | **网络不可达**（非代码问题），见下 |
| `libretranslate` / `lingva` / `deeplx` / `deepl` / `microsoft` / `baidu` / `tencent` / `caiyun` | ⏭ 跳过 | 需自建地址或凭据，本机无凭据；只做契约加固 |

## 逐引擎：问题 → 根因 → 改动

### 1. `edge`（微软翻译）— 唯一确定「代码坏了」的引擎

- **现象**：所有请求秒失败 `HTTP 404 https://edge.microsoft.com/translate/auth`。
- **根因**：微软在 **2026-08** 下线了该免鉴权取票端点（固定 404），
  而我们的链路是「先取 JWT → 再带 Bearer 调 `api-edge.cognitive.microsofttranslator.com`」，
  第一步就死；它又排在默认回退链**首位**，等于「翻译一上来就废」。
- **改动**：改走同域的**新免鉴权端点**
  `POST https://edge.microsoft.com/translate/translatetext?to=<code>[&from=<code>]`，
  请求体 `["文本"]`，响应 `[{translations:[{text}]}]`（与 v3 同构，复用同一解析函数）。
  两个细节：**必须带浏览器 UA**（否则 400 `Client Browser Version not supported`）；
  **源语言 auto 时必须省略 `from`**（传 `from=auto` 会 400）。
  已删除 `prepare()`（不再需要联网预处理）。
- **验证**：`test/translate.test.js` ⑧ 节 12 条断言 + 真实联网 594ms 返回中文。

### 2. `google` / `googleapi`

- **现象**：固定约 10~15s 超时，`curl` 同样 `000`（TCP 不通），DNS 能解析。
- **根因**：**网络层不可达**（中国大陆直连 Google 被阻断），不是代码缺陷。
  真正的产品问题是我们把它放在**默认回退链第 2 位**：首次翻译要先白等一个 20s 单路预算。
- **改动**：
  1. 默认回退链改为 `edge → bing → youdao → transmart`（`google` 移出）；
  2. 连接层失败单独归类为 `unreachable`，冷却从 60s 提升到 **3 分钟**，避免每翻一句都撞一次超时；
  3. 引擎说明里写明「国内直连不可达」，并在收起态也强制显示（`warn: true`）；
  4. 新增**可选镜像地址**字段：有自建反代（Cloudflare Worker / nginx）的用户填上即可继续用 Google 质量。
- **验证**：单元测试覆盖「不可达 → 长冷却 + 可落地提示」；联网仍然超时（符合预期）。

### 3. `bing`（必应网页版）

- **现象**：可用，但每次翻译都要先 GET 一次 `www.bing.com/translator` 取 `IG/IID/反滥用 token`（约 1~2s）。
- **根因**：`prepare()` 产物没有缓存 —— 长文按段翻译时会**每段都取一次页面**。
- **改动**：`prepare` 产物按 TTL 缓存（页面里第三个数字就是有效期，通常 1 小时，封顶 30 分钟）；
  改密钥/地址立即失效；`prepare` 也受单路预算约束（不再固定 12s）。
- **验证**：单测断言「第二次翻译不再请求页面」（`hits('www.bing.com/translator') === 0`）。

### 4. `tencent`（腾讯云 TMT）— 签名与报文格式错误

- **现象**：无凭据无法实测，但按官方 v1 规范静态复核，**几乎所有输入都会 AuthFailure**。
- **根因**：两个硬伤 —— ① 签名对**原文**计算，请求体却发**URL 编码后**的文本（含空格/中文必然对不上）；
  ② `Content-Type` 写 `application/json` 却发表单体。另外 `Nonce` 写死 `9744`。
- **改动**：统一「编码一次 → 同一份字符串用于签名与请求体」；改为
  `application/x-www-form-urlencoded`；`Nonce` 每次随机。
- **验证**：单测用同一规则重算签名并比对（`Signature == HMAC-SHA1(编码后的排序串)`）。

### 5. `baidu`

- **现象**：4000 字节文本走 GET，URL 编码后轻易破 8KB，被网关拒（414/连接重置）。
- **改动**：改 `POST` 表单（官方同样支持），签名仍按 `appid+q+salt+key` 原文计算。
- **验证**：单测断言请求体含 `q/appid/to/sign/salt`，方法为 POST。

### 6. `mymemory`

- **现象**：引擎本身可用；但「联系邮箱（提升免费额度）」这个可选字段**在界面上从未渲染过**。
- **根因**：设置面板的密钥表单渲染条件写死 `if (s.needsSecret && ...)`，
  而 MyMemory 是「免密钥但可填邮箱」，于是永远进不去这个分支。
- **改动**：条件放宽为 `secretFields.length`（Google 镜像地址同理一并生效）。
- **验证**：面板测试断言 MyMemory 行出现 1 个输入框，改动后写进复合密钥串。

### 7. `transmart` / `youdao` / `deepl` / `microsoft` / `caiyun` / `libretranslate` / `lingva` / `deeplx`

- 实测可用（前两个）或需凭据（其余）。仅做加固：DeepL 补单次上限（此前未声明，长文会被对端截断）。
- `transmart` 偶发把句号译成 `1.`（对端分段行为），不影响可用性，未做后处理（避免误伤正常数字）。

## 运行时加固（所有引擎共享）

| 项 | 旧行为 | 新行为 |
|---|---|---|
| 429 限流 | 会「重试一次」（350ms 后连发） | **不重试**，冷却 5 分钟，交给回退链 |
| 连接层失败 | 与密钥错一样只冷 60s | 标记 `unreachable`，冷却 3 分钟，文案区分「没连上」与「密钥错」 |
| 重试等待 | 固定 350ms | 尊重 `Retry-After`（上限 3s），默认 600ms |
| prepare | 每次调用都联网 | 按 TTL 缓存；改配置即失效 |
| 默认回退链 | `edge → google → bing → youdao` | `edge → bing → youdao → transmart`（老用户仅当从未自定义过才迁移） |
| 排障 | 只能点单个「测试」 | 新增**一键体检**：真实逐个调用并列出每个引擎的结果与原因 |

## 已知限制

- Google 系在中国大陆**无法从代码层修复**，只能靠镜像/代理/换引擎；提示语与默认链已按此设计。
- `bing` / `edge` 都是非官方网页接口，随时可能再变 —— 所以本仓库存了联网探针，
  发版前或用户报障时先跑一次，别靠猜。
- 需凭据的 8 个引擎本期无法实测（本机无凭据），只做了协议层修正；
  其中腾讯云的签名修正属"按文档修正"，装机后应优先用真实密钥验证一次。
