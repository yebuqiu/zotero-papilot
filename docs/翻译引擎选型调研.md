# 翻译引擎选型调研（2026-10）

> 调研时间：2026-10-13 · 面向 Papilot `TranslateSvc`（当前 13 个引擎）的补强选型
> 目标：找出**免费 + 响应快**的机器翻译引擎与调用方案，给出融入本项目的适配场景、引入成本与优先级。
> 说明：所有额度/限流/语种数均来自公开资料（官方定价页、GitHub README、第三方对比），
> **语种数以各家官方 `/languages` 接口为准**，下表区间是不同统计口径（仅文本 / 含音译词典）造成的差异。

---

## 0. 结论速览（先看这段）

三条路线，各有取舍：

| 路线 | 代表 | 成本 | 稳定性 | 适合 |
|---|---|---|---|---|
| **A. 免密钥网页接口** | Edge 翻译、Google gtx、腾讯 TranSmart、有道/金山/搜狗、Yandex、MyMemory | 零 | ⚠ 依赖对方网页协议，会变、会限 IP | 开箱即用、零门槛（默认链路的**主力**） |
| **B. 官方免费额度（需注册）** | Azure Translator F0（2M 字符/月永久免费）、Google Cloud（50 万/月）、DeepL（已收紧） | 零（需实名/绑卡） | ✅ 稳定、有 SLA | 想要稳定又不想自建（**兜底**） |
| **C. 自建 / 离线** | LibreTranslate、Argos、DLX、Lingva、NLLB-200、Ollama+Qwen | 零（要机器） | ✅✅ 最稳、无限流、数据不出本机 | 隐私敏感、批量全文翻译（**长跑兜底**） |

**对本项目的三条最高优先级建议**（详见 §4）：

1. **P0｜必应升级为 Edge token 方式**：`edge.microsoft.com/translate/auth` 取临时 token →
   `api-edge.cognitive.microsofttranslator.com/translate`。免注册、约 140 语种、比现在抓
   `www.bing.com/translator` 的 legacy 路径稳得多（参考实现 `plainheart/bing-translate-api`
   明确写了"EPT 稳定 / legacy 易 429"）。
2. **P0｜修 MyMemory 的 500 字节上限**：我们当前把整段（最大 1200 字符）直接发过去，
   而 MyMemory 单次上限是 **500 UTF-8 字节**（不是 500 个字符）→ 长句必然失败。必须按字节分段。
3. **P0｜补 Azure F0 申请指引**：`microsoft` 引擎已就绪，只差"怎么拿到 F0 免费 key"的说明；
   2M 字符/月永久免费是当前所有官方云端里最划算的。

另外建议（P1）：给回退链加**每路超时 + 总预算 + 失败冷却**（FluentRead 那套 5s/20s/1min），
并新增 **Lingva**（自建即得 Google 质量的 100+ 语种、无限流）与 **腾讯 TranSmart**（免密钥中文强）两个引擎。

## 1. 调研范围与方法

- 检索 GitHub 上封装各翻译服务的库与工具，重点是**免密钥**与**自建**两类；
- 逐个核对官方定价页（Azure / Google Cloud / DeepL / LibreTranslate）；
- 以 zotero-pdf-translate 的参考实现（已在本项目 0.28.0 落地）与 FluentRead 的"免密钥服务池"做交叉验证；
- 只记录能给出出处的数字；无法核实的（如 Amazon Translate 免费额度）**不写入**，以免误导。

## 4. 融入 Papilot 的建议

### 4.1 现状盘点（0.30.0）

`TranslateSvc` 已有 13 个引擎：`google` `googleapi` `bing` `youdao` `mymemory` `libretranslate`
`deeplx`（免密钥）＋ `deepl` `microsoft` `baidu` `tencent` `caiyun`（需密钥）＋ `llm`（走 AI 通道）。
默认活动引擎为 `llm`，回退链默认 `google → bing → youdao`。

**结论：广度已够，缺的是"稳定性补强"与"零配置可用度"。**

### 4.2 差距与处理建议（按优先级）

> **进展（0.31.0 已落地 P0 三项 + P1 三项）**：MyMemory 改为按官方 **500 UTF-8 字节**自动分段（并同步给必应 1000 字符、
> 腾讯 2000 字符、百度 4000 字节等）、新增免密钥 **`edge`** 引擎（`edge.microsoft.com/translate/auth` → `api-edge`）、
> `microsoft` 引擎补上 Azure F0 申请指引。另修一处**静默缺陷**：`prepare()` 此前只声明、从未被调用，
> 导致依赖它的 `bing` 引擎整体失效（见 §2.1 注）。
> P1 亦已完成：**回退链调度三件套**（单路预算 20s / 整条链总预算 45s / 失败冷却 60s，参考 FluentRead 的
> per-route 5s / total 20s / cooldown 1min 思路并按本项目全文翻译的体量放宽）、新增 **`lingva`**（C4，自建即无限流）
> 与 **`transmart`**（A6，腾讯交互翻译，免密钥、中文强，标注实验性）；默认回退链升级为 `edge → google → bing → youdao`
> （仅在用户从未自定义排序时迁移）。引擎总数 16：**完全免配置 7 个**（google / googleapi / bing / edge / youdao / transmart / mymemory）
> ＋ 免费但需填自建地址 3 个（libretranslate / deeplx / lingva）＋ 需密钥 5 个（deepl / microsoft / baidu / tencent / caiyun）＋ AI 大模型 1 个。
>
> **P2 亦已完成**：设置面板底部给出**数据去向提示**（免密钥引擎会把文本发往第三方；自建/本地不出本机；未发表稿件建议走自建或本地通道）；
> 引擎列表按「完全免配置 / 免费·需地址 / 需备密钥 / AI 大模型」**分组**，开箱即用的那批一眼可见；
> 并新增**本机自建服务探测**——一键发现 LibreTranslate(5000) / Lingva(3000) / DLX(1188) 并填入地址。
> 这条把 §2.3 的自建方案从"要自己记端口"变成一键可用，**因此 P3 无需新增任何引擎**。
>
> **P3 结论（不建议做）**：NLLB / Argos 本地离线已可由现有 `libretranslate` 引擎填自建地址覆盖；
> **Bergamot WASM 端侧不建议引入**——语言对只有 ~12–15 个、每对模型数十 MB 需随包分发，
> 收益（不联网）与已有自建方案重叠，成本却高一个量级。下表保留原始评估，便于回溯。

| 优先级 | 事项 | 为什么 | 引入成本 |
|---|---|---|---|
| **P0** | **修 MyMemory 500 字节上限** | 现实现按 1200 字符分段，超 500 字节必然失败/被截断；这是**线上缺陷** | 极小：分段函数改成按 UTF-8 字节切（可参考 FluentRead 的 `splitByByteLimit`），加单测 |
| **P0** | **新增 `edge` 引擎**（Edge token 方式） | 免注册、~140 语种、比现有 `bing` legacy 路径稳；FluentRead 把它排在免密池**第一位** | 小：`prepare()` 取 token + 复用 `microsoft` 的 v3 请求体/解析（我们已有 microsoft 解析逻辑） |
| **P0** | **补 Azure F0 申请指引**（`microsoft` 引擎） | 2M 字符/月**永久免费**是所有官方云端里最划算的；引擎已就绪 | 零代码：设置面板加说明文案 + 文档 |
| **P1** | **回退链增强：每路超时 + 总预算 + 失败冷却** | 现在只有"重试一次 + 依次回退"，缺**冷却**与**总预算**；一阵网络抖动会把整条链跑满、拖慢全文翻译 | 中：引擎调度层加 `perRouteTimeoutMs / totalBudgetMs / cooldownUntil`，UI 暴露两项 |
| **P1** | **新增 `lingva` 引擎**（可填自建地址） | 自建即得"Google 质量 + 100+ 语种 + 无限流"，是**长跑/批量全文翻译**最划算的兜底 | 小：REST `GET /api/v1/{from}/{to}/{q}`，与现有 `libretranslate`/`deeplx` 同型（免密钥但需地址） |
| **P1** | **新增 `transmart` 引擎**（腾讯交互翻译，免密钥） | 中文场景质量好、免注册；补足"中文强且零配置"的位置 | 中：需按网页协议逆向签名，**脆弱**，建议标注"实验性" |
| **P2** | **DeepL 额度语义修正** | 现在 UI 未区分"一次性 100 万"与"每月 50 万"；用户易误解 | 极小：文案 + 提示 |
| **P2** | **设置面板补隐私提示** | 免密钥引擎会把文本发往第三方；学术全文可能含未发表内容 | 极小：一段文案 |
| **P3** | **NLLB / Argos 本地离线引擎** | 语种最广、完全离线；但要用户自备 Python 环境或 Docker | 大：要么插件内嵌（体积/许可）要么引导用户自建后填地址（其实**可用 `libretranslate` 引擎填自建地址覆盖**，不必新增） |
| **P3** | **Bergamot WASM 端侧** | 隐私最好；但语言对少（~12–15）、每对模型数十 MB 要随包分发 | 大：打包体积与加载时序都复杂 |
| **P3** | **Amazon Translate** | 未核实其免费额度，**本次不纳入** | — |

### 4.3 推荐的目标形态（落地后的默认链路）

```
活动引擎：llm（有 AI 时质量最好，保留现状）
  ↓ 失败/不可用
回退链（免密钥，按稳定性排序）：
  edge（新，~140 语种最稳）
    → google（质量好）
      → bing（legacy 兜底）
        → youdao / transmart（中文强）
          → mymemory（最后兜底，已修字节分段）
用户可选（自备，稳定兜底）：
  microsoft（Azure F0，2M/月免费）· deepl · baidu · tencent · caiyun
自建可选（长跑/隐私）：
  lingva（自建，Google 质量无限流）· libretranslate（自建）· deeplx（自建）
```

同时把"每路 5s / 总 20s / 失败冷却 1 分钟"作为回退链默认参数（可调），
避免一次网络抖动把 5 个引擎依次跑满。

### 4.4 风险与合规

- **协议脆弱性**：A 类接口均非官方 API，可能随时失效。→ 必须保证"任意单点失效不影响可用性"（回退链已具备，需补冷却）；**P0 的 `edge` 也不是官方 API**，只是比 legacy 稳。
- **商标/许可**：DeepLX 已因 DeepL 商标通知改名 **DLX**（镜像名保留）——文档里写清，避免用户困惑；NLLB-200 模型为 **CC-BY-NC（非商用）**，商用需换 MADLAD-400 / Opus-MT；LibreTranslate 为 AGPL-3.0（自建自用无碍）。
- **隐私**：免密钥引擎会把文本发到第三方。学术场景下未发表稿件可能敏感，建议默认不自动翻译全文、并在设置面板明示数据去向。
