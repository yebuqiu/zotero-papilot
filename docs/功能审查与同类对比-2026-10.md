## 一、总评

Papilot 的功能**广度已显著超过任何单一同类插件**（同类插件大多是单功能：翻译 / 标签 / 参考文献各管一摊），入口体系（右键 41 命令注册表 + 功能中心 Hub + 顶部快捷按钮 + 3 侧栏 section + 2 阅读器工具栏按钮）也已形成自己的章法。主要差距不在"缺功能"，而在三点：

1. **交互深度**：同类头部插件在高频交互上打磨得更细（zotero-gpt 的 #命令标签、pdf-translate 的拼接模式、zotero-reference 的 `+` 一键入库双向关联、zotero-style 的手势分级）。
2. **阅读器内覆盖偏弱**：主流做法是"阅读时的功能放阅读器"（zotero-reference 整个活在阅读器侧栏），Papilot 的阅读器侧只有 2 个工具栏按钮 + 3 个共享 section，参考文献、对照翻译等阅读时高频功能仍要回主窗口右键触发。
3. **可定制性不足**：快捷键只有 1 个全局键且不可改；列只有 2 个但没有"视图组"管理；设置面板 11 张卡片单页堆叠，未接入 Zotero 设置搜索。

## 二、逐项审查清单

格式：**现状 → 参考做法 → 建议 → 实现方案**

### A. AI 问答悬浮窗（对标 zotero-gpt / PapersGPT）

**A1. Prompt 技能库升级为可编辑 #命令标签体系** 【P0】
- 现状：悬浮窗内 Prompt 标签点击即发，但**不可自定义、不可编辑、不可分享**（chat-float.js）。
- 参考：zotero-gpt 的 #命令标签是最具辨识度的设计——`#标签名`+Enter 创建、单击执行、**长按进编辑界面**（改颜色/位置/trigger 正则）、`Ctrl+R` 运行 `Ctrl+S` 保存 `ESC` 退出编辑、Meet API 分享标签；PapersGPT 沿袭了同一套语法 `#Tag[color][position][trigger=正则]`。
- 建议：把现有 Prompt 技能库升级为完整 #标签体系：内置标签 + 用户自定义标签（增删改、排序、颜色）、trigger 正则自动触发、JSON 导入导出（为日后社区分享留口）。
- 实现：`chat-float.js` Prompt 标签区渲染处加长按（≥500ms）进编辑弹层；标签数据从硬编码迁到 pref（JSON，含 label/prompt/color/trigger 字段），启动时合并内置默认值；发送前若输入匹配某标签 trigger 正则则自动套用该 prompt；导入导出走剪贴板 JSON。新增 `test/chat-tags.test.js` 覆盖解析与 trigger 匹配。

**A2. 上下文注入补齐"拖拽条目"通道** 【P1】
- 现状：上下文 = 当前 PDF 全文（缺失回退摘要）；无"指定某几篇文献为上下文"的轻量方式。
- 参考：Aria 支持拖拽条目/分类进聊天作为上下文（未逐一核实，但方向明确）；zotero-gpt 支持按选中条目摘要问答。
- 建议：工作台与悬浮窗支持从主窗口拖入条目，生成"上下文清单"chip（可移除），提问时拼接各条目摘要/全文索引。
- 实现：悬浮窗/workbench 输入区注册 drop 事件，解析 `zotero/item` 拖拽数据；上下文 chip 列表存入会话状态；发送时在 system prompt 前拼接。复用 lib-search.js 的全文索引取段落。

**A3. 手势分级统一** 【P2】
- 参考：MuiseDestiny 系插件统一"单击=执行 / 长按=编辑或强刷 / Ctrl+单击=变体"手势语言。
- 建议：悬浮窗 Prompt 标签（A1）、参考来源切换等处统一采用这套手势，README/使用教程补一节手势说明。

### B. 划词浮窗（对标 zotero-pdf-translate 划词弹窗）

**B1. 拼接模式（Ctrl 多段选择合并）** 【P1】
- 现状：划词浮窗 2 已很强（约 12 按钮、字号持久化、写批注、多轮追问），但一次只能处理一段选区。
- 参考：pdf-translate 的拼接模式——按住 Ctrl/Cmd 可跨段多次选择、合并后一次性翻译，读双栏排版文献极其实用。
- 建议：阅读器内按住 Ctrl 划词时浮窗不立即触发，进入"拼接"状态累加选区，松开 Ctrl 后合并发送。
- 实现：`reader-popup.js` 的 selection 监听处加修饰键判断与 pending buffer；浮窗上加"已拼接 N 段"提示与撤销段按钮。

**B2. 写回批注加分隔标记，支持安全重译** 【P1】
- 现状：划词结果可"写入高亮批注"，但再次触发会重复追加/覆盖关系不明确。
- 参考：pdf-translate 把译文写入注释 comment 时用分隔符包裹，重译时可精确替换旧译文而不动用户手写内容。
- 建议：写入批注时用 `<!-- pp:translate -->...<!-- /pp:translate -->`（或不可见零宽标记）包裹，重译时替换标记内内容。
- 实现：`reader-popup.js` 写批注处统一序列化格式；读取时正则剥离。

**B3. 词典模式** 【P2】
- 参考：pdf-translate 单词走词典服务（带发音），整句走翻译引擎。
- 建议：选区为单个词时优先调词典接口（可复用现有引擎注册表加一个词典引擎），低优先级。

### C. PDF 翻译（对标 zotero-pdf-translate 全文/标题翻译）

**C1. 标题/摘要译文写回条目字段 + 快捷键切换显示** 【P1】
- 现状：翻译标题摘要的结果生成子笔记；条目列表不显示译文。
- 参考：pdf-translate 把译文存入 Title Translation / Abstract Translation 字段，`Ctrl+T` 在条目列表切换标题原文/译文显示。
- 建议：译文写回条目 extra/字段（不破坏原字段），提供列或切换键显示译文。
- 实现：`translate-pane.js`/aiTaskForSelected 翻译结果增加"写入条目"路径；新增可选列「标题译文」（ItemTreeManager.registerColumn，与分区列同机制）；快捷键归入 D4 统一快捷键表。

**C2. 多引擎同屏对比窗口** 【P2】
- 参考：pdf-translate standalone 窗口可多翻译服务同屏对比、可置顶。
- 建议：划词浮窗/翻译面板加"对比引擎"按钮，弹小窗同时显示 2-3 个引擎结果。Papilot 已有 13 引擎注册表，数据层现成，只是 UI 并列展示。
- 实现：translate.js 注册表并行请求 + 简单 xhtml 弹窗。

**C3. 合并/精简功能重叠项** 【P0，属"移除不合理设计"】
- 现状：「文本双栏对照」(bilingual.xhtml) 与「PDF 对照翻译」(pdf-dual.xhtml) 功能高度重叠（0.36.0 起后者已是主入口，前者标注"备用出口"）。
- 建议：右键菜单移除「文本双栏对照」独立入口，降级为对照翻译窗口内的一个视图切换（纯文本模式），减少 41 条命令里的认知噪音。
- 实现：`menus.js` ITEM_REGISTRY 删除该命令（注册表是单一真源，删一条即可全入口生效）；pdf-dual 窗口加"文本视图"切换；保留 bilingual.js 内核供调用。

### D. 参考文献一键入库（对标 zotero-reference）——差距最大的单项

**D1. 新增阅读器侧边栏「参考文献」section** 【P0】
- 现状：ref-import 是**独立对话框窗口**，从主窗口右键调起；阅读 PDF 时想看/抓当前文献的参考文献列表，必须切回主窗口。
- 参考：zotero-reference 整个活在**阅读器侧边栏 tab**——阅读状态自动抓取当前 PDF 参考文献列表，这是该功能的"官方地段"。
- 建议：新增阅读器侧栏 section「参考文献」，打开 PDF 自动解析文末参考文献列表（复用 ref-format.js/ref-sources.js 的解析与五源联合检索），每条右侧 `+` 按钮。
- 实现：`ItemPaneManager.registerSection`（reader 侧）；解析内核直接 require 现有 ref-format/ref-sources，UI 只做列表 + 操作列。注意分册 16 总结的 registerSection 四坑（onRender 必填/ftl/注销用返回值/时序）。

**D2. `+` 一键入库并建立双向 related 关联** 【P0】
- 现状：一键入库已有判重与 AI 补全，但入库后**不与当前文献建立 Zotero 原生 related（相关文献）关系**，追溯链断裂。
- 参考：zotero-reference 单击 `+` = 入库到当前文献所在所有文件夹**并双向关联**，`-` = 取消关联，这是事实标准交互。
- 建议：入库动作默认写入 related 双向关系（可在设置里关）；已存在条目（判重命中）也提供"仅建立关联"按钮。
- 实现：ref-import.js 导入成功后调 `item.addRelatedItem(currentItem)` 双向；UI 上已入库条目把 `+` 换成「已入库·关联」状态。

**D3. 多数据源圆点切换 + 缓存与长按强刷** 【P1】
- 现状：五源联合检索对用户是黑盒，看不到每条结果来自哪个源、也不能手动换源。
- 参考：zotero-reference 浮窗顶部小圆点点击切换数据源，本地缓存 + 长按强制刷新（避免重复解析大 PDF）。
- 建议：参考文献面板顶部放数据源圆点（crossref/S2/arXiv/CNKI/PDF 解析），点亮表示命中，点击可指定源重查；结果缓存于条目级（避免重复请求），长按刷新按钮跳过缓存。
- 实现：ref-sources.js 结果带 source 字段（已有打分体系，补来源标注即可）；缓存键 = 条目 key + 源，存 pref 或附加文件。

**D4. （跨域）快捷键自定义表** 【P0】
- 现状：全插件**仅 1 个全局快捷键**（Ctrl/Cmd+Shift+K），硬编码不可改；阅读器 Ctrl+Enter 也不可改。
- 参考：zotero-attanger 在设置面板把快捷键做成"动作-默认键-启用开关"表格，改动立即生效；Actions & Tags 支持**录制式**录入（点按钮→按组合键→保存）。
- 建议：设置面板新增「快捷键」卡片：表格列出所有可配动作（唤起悬浮窗/阅读器唤起/标题译文切换/对照翻译/功能中心等），支持点击录制、恢复默认、启用开关。
- 实现：keyset 注入改为读 pref 动态生成（chat-float.js 注册处改造）；录制 UI = 监听 keydown 合成修饰键串；prefs.xhtml 新增第 12 张卡片。注意分册 22 的 xhtml 纪律（禁 `&nbsp;` 等未定义实体）。

### E. 标签与状态（对标 zotero-actions-tags / zotero-style）

**E1. 自动化引擎绑定快捷键与菜单标签** 【P1】
- 现状：自动化引擎（触发-条件-动作）已与 Actions & Tags 同构，且条件系统（17 字段 × 9 操作）比它更强；但动作只能事件触发或右键执行，不能绑快捷键。
- 参考：Actions & Tags 每个动作可配快捷键 + 菜单标签（留空即隐藏），一个动作同时出现在条目/分类/工具/阅读器/注释五类菜单。
- 建议：自动化规则加「快捷键」与「出现在右键菜单」两个可选字段；快捷键纳入 D4 的统一表格。
- 实现：automation.js 规则模型加字段；menus.js 构建时从启用规则的 pref 动态追加菜单项（注意 pref 变更即时重建的现有机制）。

**E2. 阅读进度条列 + 评级列** 【P1】
- 现状：阅读状态只有三态标签（未读/在读/已读）；阅读时长统计在后台跑但没有列表可视化。
- 参考：zotero-style 的**阅读进度条列**（按每页标注字数推断进度，直接画在单元格内）是阅读器增强的招牌；彩色标签 ⭐️ 评级排序是 Zotero 原生+插件联动的通行做法。
- 建议：新增「阅读进度」列（数据源 = 现有阅读统计心跳 + PDF 页数，进度条就地绘制）；「评级」用 Zotero 原生彩色标签方案（不造新字段），提供右键 1-5 星快设。
- 实现：复用 rank-column.js 的 registerColumn 机制自绘单元格；评级走 `item.setColoredTag` 原生 API。注意列太多后的视图组问题（见 F1）。

**E3. 嵌套标签层级视图** 【P2】
- 参考：zotero-style 的 `#分类/子分类` 嵌套标签可部分替代分类体系。
- 建议：标签治理窗口加"嵌套视图"（已有标签归一/治理基础，视图层新增）。低优先级， Papilot 的分类右键统计已覆盖部分场景。

### F. 主窗口列与布局（对标 zotero-style 视图组）

**F1. 视图组（列组合预设）** 【P1】

- 参考：zotero-style 视图组——保存/切换列显示组合，解决"插件加列太多屏幕放不下"的痛点；左键切换、长按更新、右键删除。
- 建议：快捷按钮下拉或列头菜单加「视图组」：保存当前列组合为命名预设、一键切换（如"阅读视图"=进度+状态；"选刊视图"=分区+被引量+标题译文）。
- 实现：读取/设置各列 visible 状态（ItemTreeManager 列 + Zotero 原生列的 pref）；预设存 pref JSON；入口挂在 toolbar-quick.js 下拉。

**F2. 主题按钮位置收敛** 【P2，属"改进不合理设计"】
- 现状：主题切换按钮占用了**收藏夹工具栏**（zotero-collections-toolbar），这是 Zotero 原生导航地段，第三方插件按钮出现在这里不符合惯例，且换主题非高频操作。
- 建议：移除收藏夹栏主题按钮，入口收敛到：快捷按钮下拉 + 设置面板界面主题卡片 + classic 模式视图菜单（三处已存在，零功能损失）。
- 实现：theme-toggle.js 主窗口注入处删除该按钮注册。

### H. 笔记与批量分析（对标 zotero-better-notes）

**H1. 工作台/侧栏支持 `/` 命令面板** 【P1】
- 现状：笔记模板、导出、AI 任务等是菜单项或工作台按钮，无可搜索命令入口。
- 参考：Better Notes 的 Magic Key（编辑器内 `/` 唤起可搜索命令面板）是 2024 年后笔记类插件标准范式，比按钮阵列扩展性强。
- 建议：工作台输入框以 `/` 开头时弹出可搜索命令列表（模板插入/导出/切换模式/调起各 AI 任务），方向键导航 + Enter 执行；与 A1 的 #标签共用匹配内核。
- 实现：workbench.js 输入监听 + 命令注册表（初期复用 ITEM_REGISTRY 中适用命令，标注适用范围字段）。

**H2. 笔记模板中心（导入/导出/分享）** 【P1】
- 现状：笔记模板可自定义但仅本地，无分享机制。
- 参考：Better Notes 社区模板一键导入是其生态核心。
- 建议：模板支持 JSON 导入导出（先做剪贴板级，不做在线市场）；内置模板扩到 5-8 个（综述框架/组会汇报/精读卡片等）。
- 实现：note-templates.js 序列化层 + 设置面板「增强功能」卡片加导入导出按钮。
