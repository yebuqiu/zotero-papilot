# Papilot Cite for WPS：P0–P2 增量 PRD

## 1. 项目信息

- **Language**：中文
- **Programming Language**：沿用现有 Vanilla JavaScript + WPS jsapi + Zotero HTTP Integration；不引入前端框架
- **Project Name**：`papilot_wps_cite_p0_p2`
- **版本基线**：Papilot 0.79.1 / WPS 加载项 0.3.0
- **原始需求复述**：在现有 Zotero 原生引文、文献表、导航、双向链接、未引文献和诊断能力上，完整执行 P0–P2：先补齐注文引文、文档体检、稳定身份和安全刷新，再提升写作效率，最后提供投稿与迁移工具。
- **范围原则**：P0、P1、P2 均为本次交付范围，不以 PRD 代替实现，不降级为部分交付。

### 现状与增量边界

现有实现已具备 `addEditCitation`、`addEditBibliography`、`refresh`、文档首选项、上/下一条与列表、正文↔文献表、回到原文、查看引用、补入未引文献和诊断包；已有域代码/文档数据回读校验、错误通道收尾及重复 `citationID` 的会话内去重。

**基线回归证据**：`integration-smoke`、`integration-extra`（23 项）、`qa-protocol`（38 项）、`core`（82 项）、`nav`（39 项）、`raise`（6 项）当前全部通过。`qa-protocol` 仍以“已知不做/待修”probe 记录注文缺陷；这些 probe 不得作为豁免保留，修复后必须升级为强制 `check`，并继续通过上述完整基线。

本迭代重点修复以下已证实缺口：

1. `Document.getFields` 仅扫正文，`noteIndex` 恒为 0；`Document.convert` 未实现；新建脚注后建域失败会留下空脚注。
2. 文献表条目锚点仍以标题和有限数字样式顺序推断，同题文献会失锚。
3. 刷新虽有事务锁与错误收尾，但缺少刷新前数据备份、已改域快照恢复及结构化阶段诊断。
4. 导航与工具主要使用 prompt/alert，尚缺管理面板、右键入口、历史位置和自动化选项。

## 2. 产品定义

### Product Goals

1. **可靠**：正文、脚注、尾注中的引文均可插入、扫描、刷新和转换；异常可定位，失败不留下损坏或半成品。
2. **高效**：常用引文操作在 1–2 次操作内完成，长文档可检索、定位、连续核对并回到原位置。
3. **可投稿、可迁移**：投稿前发现数量与元数据问题，安全导出纯文本副本，并给出跨编辑器兼容依据和修改记录。

### User Stories

1. 作为论文作者，我希望在脚注/尾注中插入并刷新引文，以便使用 Chicago 等注文样式且保持注号、Ibid. 和文献表正确。
2. 作为长文档作者，我希望体检能指出异常引文的位置和原因，以便修复缺失、重复、截断或手工改写，而不是刷新后才发现编号错乱。
3. 作为改稿作者，我希望从管理面板或右键直接定位、编辑和打开原文，并能返回之前的位置，以减少来回查找。
4. 作为投稿人，我希望投稿前检查正文与文献表并另存无域副本，以便满足期刊要求且绝不破坏原稿。
5. 作为跨 Word/WPS/LibreOffice 协作者，我希望迁移前获得兼容报告和降级提示，以便判断哪些内容可刷新、哪些只能保留显示文本。

## 3. Requirements Pool

优先级定义：**P0 = 必须可靠完成；P1 = 应完成；P2 = 本次也应完成**。所有写操作默认串行，单项 API 不可用不得导致整个功能区失效。

### P0：引文可靠性

#### P0-1 完整脚注/尾注引文

- 统一正文、`Footnotes`、`Endnotes` 的域扫描模型，记录容器类型、真实注序号/稳定注标识、域范围和文档顺序；`insertField`、`cursorInField`、`getFields` 均返回正确 `noteIndex`。
- 插入注文引文时必须落在注正文；`refresh`、编辑、文献表更新、导航与体检使用同一扫描结果。
- 实现 `Document.convert` 的正文↔脚注↔尾注转换：按 Zotero 下发顺序逐项转换，保留域代码、富文本、条目顺序、邻接关系和文档数据；转换后刷新验证。
- 新建注后若建域/写码/写文本失败，必须删除本次空注并完成事务收尾；不得把注文引文静默写入正文。
- **验收标准**：
  1. 混合正文、2 个脚注、2 个尾注的样本文档中，扫描类型、数量、顺序及 `noteIndex` 全部正确；连续两次扫描域 ID 稳定。
  2. 脚注与尾注各插入、编辑、删除引用并刷新，显示文本、注号和文献表与 Zotero 结果一致； Chicago note 样式的同注/Ibid. 场景不退化为 `noteIndex=0`。
  3. 正文→脚注、脚注→尾注、尾注→正文各转换一次，域数与 `citationID` 集合不变，无嵌套域、空注或丢格式。
  4. 注入 `Footnotes.Add`、`Endnotes.Add`、`Fields.Add`、写码失败，均给出明确错误、完整收尾且不残留空注/半域。
  5. 不支持注集合或转换 API 时，仅禁用相应注文能力；正文引文、文献表、诊断仍可用，并在首选项前说明限制。
  6. `qa-protocol` 原有“`Document.convert` 未实现、正文漏扫注文、`noteIndex=0`、脚注失败留空注”的“已知不做/待修”probe 全部改为强制 `check`；旧 probe 不得删除、跳过或继续作为通过条件豁免，且基线各套件保持全绿。

#### P0-2 文档引文体检

- 一键只读扫描并输出：缺失 Zotero 条目、重复域身份、域代码截断/坏 JSON、文献表未刷新、疑似手工改引文、无法跳转。
- 每条问题包含严重级别、域/注位置、短摘要、原因、建议动作；支持定位与重新扫描。自动修复仅限明确安全动作，默认不批量改文档。
- “未刷新”以最近一次成功刷新的引文/文献表指纹和文档数据版本比较；“手工改引文”比较域结果与 Zotero `formattedCitation` 的规范化文本，格式差异不误报。
- **验收标准**：六类预制异常均被逐项识别，正常文档零误报；坏域不阻断其余扫描；点击问题能定位正文或注文；无文献表、无 Zotero 连接、无书签分别给出可执行提示；体检本身不改变域、注、文档属性或选区内容。

#### P0-3 稳定文献表条目身份

- 统一以 `libraryType + libraryID + itemKey` 作为条目身份；文献表映射优先使用 Zotero/citeproc 输出中可验证的条目级标识，其次使用唯一且完整的元数据映射。
- 标题、显示编号只可作最后兜底，且必须唯一、样式规则明确；不得仅凭序号或标题猜测。跨刷新保留映射，未命中/多候选标为“身份歧义”。
- **验收标准**：数字制与作者—年制刷新、重排、增删引文后，已识别条目均跳到正确身份；同题同作者、无标题、排序数字制和重复条目用例不建立猜测链接，并显示明确歧义提示；旧版无映射文档可重建，刷新不累积书签。

#### P0-4 安全刷新与自动恢复

- 刷新前保存 `ZoteroDocData` 原文备份及待改域的代码、文本、注位置、书签快照；备份按文档隔离，保留最近一次已知良好状态，不覆盖更早备份直到新刷新验证成功。
- 事务记录 `operationID`、阶段、命令、耗时、域数、重试与收尾结果；区分首连超时、用户选择等待、单步响应超时、收尾失败。不得在 Zotero 选择窗口仍开放时强行释放事务。
- 写失败先完成 Zotero 错误通道与 `Document.complete`，再仅恢复本次已触达的域/文档数据并回读验证；恢复失败时保留备份并明确指导另存/撤销，不反复自动写入。
- **验收标准**：
  1. 在 `getFields`、`setCode`、`setText`、`setDocumentData`、收尾阶段分别注入失败，均能结束或明确报告事务状态，不永久占用本地锁。
  2. 已修改域与文档数据恢复到刷新前内容，未触达域不变；恢复本身失败时不伪报成功，备份仍可导出诊断。
  3. 超时日志含阶段、最后命令、耗时、`operationID` 和收尾结果，诊断包不暴露完整论文正文。
  4. 连续刷新、无变化刷新、5000 步以内长文档刷新及用户取消均保持既有行为；刷新前备份失败则禁止写入并提示。

### P1：写作效率

#### P1-1 引文右键菜单

- 在引文上下文提供：编辑引文、转至参考文献、在 Zotero 中显示、打开 PDF、引用信息；多篇引文先显示“标题/作者/年份”选择器。
- 优先使用 WPS 原生上下文菜单；不支持时使用选中引文后的自定义快捷面板/功能区菜单，不注入全局鼠标钩子。
- **验收标准**：五个入口均执行对应现有/新增命令；非引文处不出现引文动作；不可用 PDF 单独置灰并说明；无原生右键 API 时快捷面板可用且其余功能区不受影响。

#### P1-2 快捷跳转、返回与同文献遍历

- 增加“返回跳转前位置”、同一文献“上一处/下一处”；位置栈至少保存 20 次，包含文档、正文/注容器、域身份与范围。
- 多篇与多处选择器显示标题、第一作者、年份及所在章节，不再只显示 itemKey。
- **验收标准**：正文→文献表→返回、同文献多处循环跳转均准确；刷新导致范围变化时按身份重定位；目标删除时跳过并提示；选择器取消不改变选区。

#### P1-3 常用样式与最近三种

- 功能区提供 GB/T 7714、APA、Nature、IEEE 和最近使用最多 3 种；完整样式、语言、注文制仍进入文档首选项。
- 最近列表按成功切换时间更新，去重；当前样式置顶标识，不将失败样式记为最近使用。
- **验收标准**：四种样式可一键切换并刷新；连续切换 5 种后仅保留最近 3 种且顺序正确；失败切换回滚且不污染历史；重开加载项后历史仍在。

#### P1-4 引文管理面板

- 可停靠面板列出：序号、正文显示、标题、作者、年份、页码/locator、章节、正文/脚注/尾注；支持搜索、定位、编辑、打开原文和异常标记。
- 一行代表一个物理引文域；多篇条目可展开。搜索覆盖标题、作者、年份、正文与页码；异常与 P0 体检共用结果。
- **验收标准**：混合 200 条引文可完整列出并筛选，定位/编辑命中当前行；删除或刷新后列表更新且身份不串行；无任务窗格时退化为对话框列表，仍支持搜索和定位；坏域保留并标记而非消失。

#### P1-5 刷新状态与可选自动化

- 展示上次刷新时间、结果、引文域数、文献表域数及异常数；状态按文档隔离。
- 提供“打开文档时检查”和“保存后自动刷新”两个选项，**默认均关闭**，默认保持手动刷新；自动刷新失败不循环重试。
- **验收标准**：成功、无变化、取消、失败后的状态文案和计数准确；开启打开检查只读扫描；开启保存后刷新时一次保存最多触发一次事务，已有事务/未保存新文档/备份失败时不启动；关闭选项后无后台写入。

### P2：投稿与迁移工具

#### P2-1 投稿前检查

- 输出正文/注文引文域数、唯一文献数、文献表条目数及差异；检查缺页码、缺 DOI、未引用条目、重复文献。
- 页码/DOI 按文献类型与当前样式提示为“建议”，不得把所有书籍/网页误判为错误；重复文献优先按身份，其次 DOI，最后规范化标题+作者+年份并标“疑似”。
- **验收标准**：预制文档的数量差异、未引、重复及缺失字段全部命中；`uncited` 条目单独列出；报告可定位、可导出，检查不修改原稿。

#### P2-2 另存无 Zotero 域纯文本副本

- 通过“另存为副本→仅处理副本→移除引文/文献表 Zotero 域代码并保留显示文本”实现；原稿不执行 `Unlink`、不保存、不改文档数据。
- 默认文件名 `<原名>_无引文域.docx`，已存在时要求选择新路径，不静默覆盖；完成前校验原稿路径、域数量与修改状态。
- **验收标准**：副本可见文本、注文和基础格式保留，Zotero 引文/文献表域为 0；原稿域数量、代码及文档数据逐字不变；取消另存、另存失败或处理失败均不触碰原稿，失败副本不冒充成功。

#### P2-3 Word/WPS/LibreOffice 迁移兼容检查

- 只读检查域方言、文档数据完整性、正文/注文覆盖、文献表锚点、截断风险及目标编辑器已知不支持能力；输出“可直接迁移 / 迁移后需重连 / 建议纯文本副本”。
- 不宣称未实测版本完全兼容；报告记录 WPS/Zotero 版本与能力探测结果。
- **验收标准**：官方 Word 域、旧版数据、注文、截断域和 LibreOffice 参考域样本得到对应报告；迁移检查不自动转换或保存；未知能力显示“未验证”而非“兼容”。

#### P2-4 引文修改记录

- 记录引文增删/编辑、样式变化、手动/自动刷新及恢复结果；包含时间、操作、文档、数量、前后样式或摘要、结果，不记录完整正文。
- 默认保留每文档最近 200 条，可查看、导出、清空；记录失败不阻断引文操作。
- **验收标准**：各类操作均只写一条结果记录，取消不记为修改；增删与样式前后值准确；超过 200 条滚动裁剪；重开后可读，导出与清空需用户确认。

#### P2-5 批量打开 Zotero/PDF/DOI/附件

- 对当前多篇引文或管理面板勾选条目，支持批量打开 Zotero、最佳 PDF、DOI 和附件；按条目去重并展示逐项结果。
- 默认一次最多 10 项，超出需确认；外部打开采用串行/有限并发，失败项可重试，不影响成功项。
- **验收标准**：混合个人库/群组库、有/无 PDF、有/无 DOI 样本均生成正确目标；无目标项明确跳过；重复条目只打开一次；取消批量确认不执行任何打开动作。

## 4. UI Design Draft

### 功能区结构

1. **引文**：插入/编辑文献、插入/更新文献表、刷新、刷新状态下拉。
2. **样式与排版**：4 个常用样式、最近 3 种、文档首选项。
3. **引文导航**：上一条/下一条、同文献上一处/下一处、返回原位置、正文↔参考文献、引文管理面板。
4. **双向链接**：回到原文、查看引用、批量打开。
5. **检查与工具**：文档体检、投稿前检查、迁移兼容检查、修改记录、另存无域副本、补入未引文献、诊断包、自动化设置、关于。

### 管理/检查面板

- 顶部：搜索框、刷新状态、异常筛选、重新扫描。
- 中部：引文表格或检查问题列表；异常行有统一图标与原因，不仅靠颜色。
- 底部/行操作：定位、编辑、转文献表、Zotero、PDF、引用信息；批量模式显示勾选数与 10 项上限提示。
- 面板打开前保存当前选区，关闭后尽可能恢复；API 不支持时按“任务窗格→对话框→prompt/alert 基础列表”逐级降级。

### 渐进降级规则

- 建立按文档/会话缓存的能力矩阵：注集合、注范围域枚举、`Document.convert` 所需移动能力、书签、右键、任务窗格、对话框、另存、事件监听。
- 每次能力调用独立捕获异常并留痕；只禁用对应按钮或动作，不能让初始化失败拖垮整个 Ribbon。
- 无事件 API：隐藏自动化选项，保留手动检查/刷新；无右键 API：使用快捷面板；无面板：使用对话框；无注 API：保留正文引文并明确禁用注文制。
- 对“可能写错位置”的能力不得以未知结果继续执行；探测失败采取只读或禁用，而非静默猜测。

## 5. 默认决策（无需再向用户确认）

1. 以 Zotero 原生 citeproc 和 Integration 为唯一排版真源，不另造注文编号或 bibliography 排序算法。
2. 默认手动刷新；打开检查和保存后自动刷新均默认关闭，需用户逐项开启。
3. 体检、投稿检查、迁移检查默认只读；身份歧义不自动合并、不自动选择。
4. 刷新仅保留最近一次已知良好备份；新刷新完整验证后才替换旧备份。备份属于文档私有数据，不上传。
5. 恢复采用最小写入原则；完整恢复失败即停止，不循环重试，不自动删除原稿或另存覆盖。
6. 无域副本固定走新文件流程，绝不在原稿执行移除域；不自动删除 Zotero 文档数据之外的其他非 Zotero 域。
7. 修改记录默认每文档 200 条；批量外部打开默认 10 项上限；返回位置栈默认 20 条。
8. 样式快捷入口固定 GB/T 7714、APA、Nature、IEEE；最近 3 种可包含其他成功使用的样式。
9. 所有外部链接和附件仅通过本机 Zotero/系统已配置方式打开，不上传论文或文献库。
10. 目标平台未实测时标记“未验证”，以能力探测和样本回归结果作为兼容结论依据。

## 6. 非目标与数据安全边界

### 非目标

- 不重写 Zotero 引文选择器、CSL 样式编辑器或文献库管理器。
- 不在本迭代支持云端多人同时编辑、实时协同合并引文域。
- 不自动修复所有坏域、重复库条目或手工改写；这些需用户确认。
- 不保证任意 WPS/Word/LibreOffice 版本完全等价，不用纯文本外观相同替代域兼容验证。
- 不把无域副本当作可继续用 Zotero 刷新的工作稿。

### 数据安全

- 原稿优先：任何恢复、转换、移域操作必须限定目标文档和本次事务范围。
- 诊断、状态与日志默认不包含完整正文、完整域 JSON、附件内容或 DOI 列表；仅保留定位所需短摘要并脱敏路径。
- 文档数据备份、修改记录和能力矩阵不上传远端；外部网络仅用于 Zotero 已有样式获取和用户主动打开的 DOI。
- 对写码、文档属性和恢复结果必须回读校验；校验失败不得显示“成功”。

## 7. 测试与完成定义

- 保留并通过现有 `core`、`qa-protocol`、`integration-extra`、`nav`、`ui-wiring` 等测试；将现有注文、`Document.convert`、`noteIndex` 和空注回滚 probe 升级为必过测试。
- 新增统一注文域扫描、混合正文/脚注/尾注、转换往返、六类体检、身份歧义、刷新故障注入与恢复、面板、自动化防重入、无域副本和迁移样本测试。
- WPS jsapi 桩必须覆盖“属性不存在、调用抛错、返回 null、行为不完整”四类差异；每种差异均验证局部降级。
- 至少在项目支持的 WPS 真机版本完成正文与注文插入/编辑/刷新、失败恢复、另存副本和面板导航；未实测的 Word/LibreOffice 结论保持“未验证”。
- **完成定义**：P0–P2 各项验收标准均有自动化或可重复真机证据，无哑按钮、无静默写错位置、无原稿破坏性路径，诊断能解释失败阶段与降级原因。
