## 1. 安装（可复现）

```bash
# ① 打包（版本以 manifest.json 为准；生成的包会自检包内版本与条目数）
python scripts/build-xpi.py 0.49.0
# → dist/papilot-0.49.0.xpi

# ② 关闭 Zotero（覆盖前必须，否则文件被占用）
taskkill /IM zotero.exe /F

# ③ 覆盖到用户 profile 的 extensions（文件名 = 插件 id）
copy /Y dist\papilot-0.49.0.xpi ^
  "%APPDATA%\Zotero\Zotero\Profiles\tvmr3s3i.default\extensions\papilot@dev.local.xpi"

# ④ 删除 addonStartup 缓存（不删可能仍加载旧版本）
del "%APPDATA%\Zotero\Zotero\Profiles\tvmr3s3i.default\addonStartup.json.lz4"

# ⑤ 启动 Zotero 验证
```

**校验已安装版本**（不启动 Zotero 也能查）：

```python
import zipfile, json
p = r'%APPDATA%\Zotero\Zotero\Profiles\tvmr3s3i.default\extensions\papilot@dev.local.xpi'
mf = json.loads(zipfile.ZipFile(p).read('manifest.json'))
print(mf['version'])          # 期望 0.49.0
```

## 3. 验证路径（用户操作）

### 3.1 会员购买 → 付款单弹窗 → 扫码 → 核销

1. Zotero → 编辑 → 设置 → Papilot → 「账号」卡片，登录。
2. 「升级专业版 / 续费」→ 选周期 →「生成订单」。
3. **预期：自动弹出「会员订单」付款单**（金额含对账尾数、订单号、状态=待支付、收款码 + 支付宝二维码）。
4. 手机扫码 → 按**精确金额**转账 → 回插件点「我已完成支付」（或在弹窗里点）。
5. 管理端（控制台 → 网页管理页 → 会员管理 → 订单）核销 → 插件轮询（6 秒）自动更新为「已开通」。

> 手动收款码路径依赖人工核销；需要**自动到账**请用下面的充值在线支付路径。

### 3.2 AI 额度充值 → 付款单弹窗 → 在线支付扫码 → 回调自动入账

1. 设置 → Papilot →「AI 额度」→「充值额度」→ 选档位 →「生成充值订单」。
2. **预期：自动弹出「充值订单」付款单**，按钮含「在线支付（扫码）」（服务端开通时才出现）。
3. 点「在线支付（扫码）」→ 系统浏览器打开网关收银台（ljlliu.cn 支付宝码）。
4. 扫码支付（金额以收银台页为准，可能因免签唯一金额机制比订单多 1–N 分）。
5. 网关异步通知 → 服务端验签 → **自动入账**（面板/弹窗 6 秒内变「已开通」）；即便通知丢失，点「刷新状态」也会主动查单入账。

### 3.3 控制台

启动控制台 → 「计费与会员」页 → 底部「在线支付网关（服务端 1.8.3 · 免签网关适配）」：

- 网关状态（就绪/未启用/缺密钥/缺 PP_PUBLIC_URL）
- 协议/网关/pid/查单变体
- **免签多付容差**（默认 ¥1.00，`PP_PAY_OVERPAY_CENTS` 可调，0=精确比对）
- 按钮：连接测试 / 深度测试（0.01 元，需确认）/ 网关配置（管理页）

## 6. 金额口径：为什么会出现「订单 ¥10、实付 ¥10.24」

**来源是本项目自己的「唯一尾数」机制，不是支付网关加的价。**

- 旧设计（1.4.5 起）：下单时在标价上加 **1~99 分随机尾数**（如 ¥10.00 → ¥10.24），
  用于「用户无备注转账时，管理员按金额自动匹配订单」（`server/lib/membership.js` 的 `assignTail`）。
- 1.8.4 起：**该机制默认关闭**——下单金额 = 标价（所见即所付）。
  需要按金额自动对账的运营商可在 管理页 → 会员配置 → 「订单金额唯一尾数」勾选开启。
- 另一个「加价」来源是**支付网关本身**：免签网关（个人收款码）对**并发同额**订单
  自动 +1 分递增加价（¥10.00 → 10.01 → 10.02），目的是区分同时到达的多笔同额转账。
  该行为只在「同一时刻存在多笔相同金额的待支付网关订单」时发生，幅度为分，
  服务端回调金额校验已留 ¥1 多付尾差窗口（`PP_PAY_OVERPAY_CENTS`）。

**开关（三处同一真源）**：

| 位置 | 作用 |
|---|---|
| `membership.json` 的 `tailEnabled` | 权威配置（默认 false） |
| `PUT /api/admin/membership {"tail":{"enabled":true}}` | 管理接口写入 |
| 管理页 → 会员配置 → 「订单金额唯一尾数」 | 勾选/取消 + 保存配置 |

已配置的既有订单不受影响（未支付旧单仍带原尾数，可取消后重下）。
