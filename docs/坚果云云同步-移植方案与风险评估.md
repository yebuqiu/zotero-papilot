# 坚果云云同步 · 移植方案与风险评估

> 目标：把坚果云作为 Papilot 的**统一数据同步通道**（设置、对话记录、技能包/安装包等），
> 不再依赖 Zotero 自带附件同步，也不另建对象存储。
> 参考实现：`nutstore/zotero-plugin-nutstore`（AGPL-3.0，仅作机制参考，不复制其代码）。
>
> 本文结论对应实现：`chrome/content/scripts/core/webdav.js`（协议层）、
> `chrome/content/scripts/features/cloud-sync.js`（同步域）、`chrome/content/prefs-cloud.js`（面板）。
>
> 实现状态：功能代码已落地并通过门禁（`preflight --fast` 80/80，其中 `test/cloud-sync.test.js` 131 项）；
> **`manifest.json` 尚未升版**——当前工作区叠加了其它并发会话的改动，按项目发版纪律不构建、不发布，
> 待工作区清理后统一 bump 到 0.56.0 再打包。

## 1. 参考实现到底做了什么（先纠正一个常见误解）

`zotero-plugin-nutstore` **本身不是同步引擎**，它只做两件事：

| 模块 | 实际职责 | 关键代码事实 |
|---|---|---|
| `src/modules/nutstore-sso.ts` | 把 SSO 拿到的凭据**写进 Zotero 原生同步配置** | `Zotero.Prefs.set('sync.storage.protocol','webdav')`、`sync.storage.url = 'dav.jianguoyun.com/dav'`、`sync.storage.username = oauthInfo.username`、`setWebdavPassword(oauthInfo.access_token)`，随后 `reInitZoteroSync()` 刷新设置页 |
| `src/modules/protocol.ts` | 注册 `zotero://nutstore-sync?s=<token>` 自定义协议 | 登录页回调 → `decryptToken(s)` → 存 `nutstore-sso-token` pref → 询问是否自动写入 WebDAV 配置 |
| `src/utils/sso.ts` | 调 `@nutstore/sso-js` 的 `createOAuthUrl({app:'zotero'})` / `decryptSecret` | **依赖私有 npm 包**；token 是加密串，解密后得到 `{username, userid, access_token}` |
| `src/modules/enhanced-webdav.ts` | 读坚果云**桌面客户端**的本地配置（仅 Windows），取出预先配好的 WebDAV 账号/密码，写进 Zotero | 目的是绕开"直接用 WebDAV 偶发不稳"的问题；本质仍是写 `sync.storage.*` |
| `src/modules/preference.ts` | 只负责面板渲染与按钮状态 | — |

所以它**没有**：文件级增量索引、冲突合并、上传进度、断点续传、大文件分卷、非附件类数据同步。
真正的读写全部由 Zotero 内置的 `Zotero.Sync.Runner.getStorageController('webdav')` 完成。

**对我们的启示**：能借的是"协议事实"和"凭据供给方式"，不能借的是"同步逻辑"——因为我们
要同步的东西（设置、技能包、任意安装包）不在 Zotero 的附件模型里。

## 2. 可直接复用 / 必须适配

### 2.1 可直接复用（协议与常量层）

| 项 | 说明 |
|---|---|
| WebDAV 端点 | `https://dav.jianguoyun.com/dav`（国际版/团队版另配 `cloudUrl`，做成可改） |
| 认证方式 | HTTP Basic；用户名 = 坚果云账号（邮箱），密码 = **应用密码**（非登录密码） |
| 目录语义 | 普通集合，`MKCOL` 建目录（已存在返回 405），`PROPFIND` 取 `getetag`/`getcontentlength`/`getlastmodified` |
| 条件写 | `If-Match: <etag>` 做乐观并发；`If-None-Match: *` 做"仅新建"。**坚果云返回的 ETag 是裸串**（如 `iwlZel-VA8cnzqRY9CcZSg`，不带引号），补引号会被判 412 —— 必须原样回传 |
| 冲突信号 | `412 Precondition Failed` |
| 配额信号 | `507 Insufficient Storage` |
| 认证失效 | `401`（**403 不是过期**，是权限/路径问题——与本项目账号体系同一条纪律） |
| 大文件 | 单次 `PUT` 受服务端配额限制；标准 WebDAV 无 "append/compose"，只能**客户端分卷 + 清单** |

### 2.2 必须适配（架构差异）

| 差异 | 适配方案 |
|---|---|
| 参考实现是 TS + `zotero-plugin-template` + 打包器 | 本项目是**零依赖特权 JS**、`loadSubScript` 直接加载：改为 `var WebDAV = (function(){…})()` 风格，不引入任何 npm 包 |
| 依赖 `@nutstore/sso-js` 解密 SSO token | **不移植**。改为"账号 + 应用密码"直连；SSO 只保留一个"打开授权页"的跳转按钮（见 §5 风险 R2） |
| 参考实现把传输交给 Zotero 附件同步 | 自建引擎：数据集注册表 + 本地索引 + 三向增量判定 + 自己的冲突策略 |
| Zotero 附件同步只有"条目附件"概念 | 自定义远程目录树（`data/`、`packages/`、`devices/`），与条目无关 |
| 参考实现只要写 pref，无需状态机 | 需要完整状态机（idle→scanning→uploading→…→error）、进度事件、错误分类与重试 |
| 老版本项目用 `Zotero.Prefs` 全局 | 沿用 `Prefs` 薄封装（`extensions.zotero.papilot.*`），并遵守本项目"一律 `global=true`"纪律 |

## 3. 总体设计

```
┌─────────────────────────────── 设置面板（prefs-cloud.js）
│  登录/应用密码 · 冲突策略 · 方向 · 数据集勾选 · 进度条 · 日志
└───────────────┬───────────────────────────────────────────────
                │  Zotero.Papilot.cloudSync
┌───────────────▼───────────────────────────────────────────────
│ CloudSync（features/cloud-sync.js）                            │
│  · 凭据与配置          · 状态机 / 事件 / 日志环形缓冲          │
│  · 数据集注册表        · 本地索引 index.json（etag/fingerprint）│
│  · 三向增量判定        · 冲突策略（keepBoth/local/remote）      │
│  · 分卷上传 + 清单组装 · 断点续传下载（Range）                  │
└───────────────┬───────────────────────────────────────────────
                │  WebDAV 客户端（协议层，无业务）
┌───────────────▼───────────────────────────────────────────────
│ core/webdav.js：encodePath / PROPFIND 解析 / 条件 PUT / GET    │
│                 Range / MKCOL / 状态码分类 / 退避 / SHA-256    │
└───────────────┬───────────────────────────────────────────────
                │  Zotero.HTTP.request（有 XMLHttpRequest 时优先用 XHR，带上传进度）
        https://dav.jianguoyun.com/dav
```

### 3.1 远程目录组织

```
/Papilot/                                  ← 可配置根（cloudSyncRoot）
  data/
    settings.json                          ← 设置项快照（白名单，剔除密钥）
    papilot-chat-sessions.json             ← AI 对话记录（整文件）
  packages/
    skill-packs/<id>-<version>.json        ← 已安装技能包（自动收集）
    installers/<原文件名>                   ← 用户拖入的任意安装包（xpi/zip/json…）
  devices/
    <deviceId>.json                        ← 设备心跳（名称/版本/最后同步时间）
  .ppparts/<文件名>.<hash8>/0001.part      ← 大文件分卷（仅超大文件出现）
```

**为什么这样分**：
- `data/` 与 `packages/` 分离，是为了给"整目录镜像"和"整文件替换"两种同步语义留边界；
- `devices/` 只写不读，用于多机排查"谁最后改的"；
- `.ppparts/` 用点前缀，扫描时跳过，不和业务文件混在一起。

### 3.2 数据集注册表（后续所有同步需求的唯一入口）

| key | 形态 | 本地来源 | 远程 |
|---|---|---|---|
| `settings` | 虚拟文件（pref 快照） | `Services.prefs.getChildList(PREFIX)` + 白名单 | `data/settings.json` |
| `chatSessions` | 单文件 | `papilot-chat-sessions.json`（数据目录/ProfD 双落点） | `data/papilot-chat-sessions.json` |
| `packages` | 目录 | `<数据目录>/papilot-cloud/packages/**` | `packages/**` |

新增同步需求 = `CloudSync.registerDataset({key, kind, …})`，UI 勾选项由注册表自动渲染，
不需要再动引擎。这是"后续所有数据同步统一由坚果云处理"的落点。

### 3.3 增量同步判定（三向）

对每个文件取三份事实：本地指纹、云端 `etag/size`、本地索引里"上次同步成功"的记录。

```
localChanged  = 本地 size/mtime（或内容哈希）≠ 索引
remoteChanged = 云端 etag/size ≠ 索引
有本地无云端 → 上传
有云端无本地 → 下载
都有，且都未变 → 跳过
仅本地变      → 上传
仅云端变      → 下载
两边都变      → 冲突（按策略）
无索引 + 两边都有：size 相同视为同一内容（记索引跳过），否则冲突
```

`settings` 数据集用**内容 SHA-256** 判变化（pref 快照没有可靠 mtime）；文件/目录用
`size + mtimeMs`，超过 16MB 不再算哈希（避免每次同步读一遍大文件）。

### 3.4 冲突处理

| 策略 | 文件/目录 | 设置快照 |
|---|---|---|
| `keepBoth`（默认） | 本地改名为 `foo (冲突 本机 20261019-103000).json` → 作为**新文件上传** → 再下载云端版本覆盖原名。两份都留，零丢失 | 本机为准上传；云端旧版存到 `papilot-cloud/conflicts/settings-<时间>.json` |
| `local` | 带 `If-Match` 覆盖云端（412 时重试一次取新 etag） | 同左 |
| `remote` | 先把本地复制到 `conflicts/`，再下载覆盖 | 下载并**逐键应用**，应用前弹确认 |

**删除不做传播**（默认）：任何一侧删掉的文件只记日志、不删对面。理由：同步工具里
"误删传播"是最常见的数据灾难；需要清理时走面板的"清理云端多余文件"显式操作。

### 3.5 大文件与安装包

- **阈值**：`cloudSyncLargeFileMB`（默认 64MB）以下单次 `PUT`；以上走分卷。
- **分卷**：`partMB`（默认 32MB）切片 → 逐片 `PUT` 到 `.ppparts/<name>.<hash8>/`，
  已存在且大小一致的片直接跳过（**天然断点续传**）→ 最后写 `<name>.ppmanifest.json`
  （含总大小、总 SHA-256、每片大小）。下载端先找正式文件，404 再找清单并组装校验。
- **上限**：`cloudSyncMaxFileMB`（默认 512MB）以上的文件直接跳过并在 UI 明确报"超限"，
  不静默失败。
- **下载续传**：本地留 `.part`，用 `Range: bytes=N-` 续传；服务端返回 200 表示不支持
  Range，则整份重下（不损坏已有 `.part`）。
- **技能包**：`stageSkillPacks()` 调 `SkillPacks.listInstalled()` + `exportPack(id)`，
  把每个已装包的 manifest 写成 `<id>-<version>.json` 落到 `packages/skill-packs/`，
  再走普通增量上传；用户自己的 xpi/zip 放 `packages/installers/` 一并同步。

### 3.6 状态反馈与错误处理

状态机：`idle → auth → scanning → uploading/downloading → (conflict) → done | error`

事件：`CloudSync.on(fn)` → `{type:"state"|"progress"|"log", …}`；面板订阅渲染进度条、
当前文件、字节数、最近错误。

错误分类（`WebDAV.CODES`）：

| code | 触发 | 是否重试 | 用户提示 |
|---|---|---|---|
| `AUTH_REQUIRED` | 401 且没填凭据 | 否 | 请填写应用密码 |
| `AUTH_EXPIRED` | 401 且有凭据 | 否 | 应用密码失效：重新生成后填入（**不清空已存凭据**，避免"越修越丢"） |
| `NETWORK` / `TIMEOUT` | 0 / 超时 | 是（3 次，指数退避 + 抖动） | 网络中断，已重试 N 次；已传文件不会重传 |
| `QUOTA` | 507 | 否 | 坚果云空间不足 |
| `TOO_LARGE` | 413 / 超阈值 | 否 | 文件超过上限，已跳过 |
| `CONFLICT` | 412 | 一次（取新 etag 后按策略） | 云端已被其它设备修改 |
| `FORBIDDEN` | 403 | 否 | 路径无权限（≠ 授权过期） |
| `SERVER` / `RATE_LIMIT` / `LOCKED` | 5xx / 429 / 423 | 是 | 服务端繁忙，稍后继续 |

## 5. 风险评估

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| R1 | **坚果云 WebDAV 不接受登录密码**，只接受"应用密码" | 用户按字面填密码 → 401 → 以为功能坏 | 已实测 100% | 面板写明路径（账户信息 → 安全选项 → 添加应用密码），按钮直达；401 提示"不是登录密码" |
| R2 | 参考实现的 SSO 依赖私有包 `@nutstore/sso-js` | 无法零依赖复刻；token 加密格式不可知 | 高 | 不做 token 解密；只提供"打开授权页"跳转 + 应用密码主路径。若官方提供 OAuth 客户端再补 P4 |
| R3 | 凭据落盘 | pref 明文存应用密码，本机他人可读 | 中 | 默认保存但可关闭（`cloudSyncRememberToken=false` 仅内存）；面板明示；快照同步**永不包含**凭据（`cloudSync*` 与密钥正则双重排除） |
| R4 | 设置快照把 API Key 同步到云端 | 密钥外泄 | 高（若不处理） | 导出白名单 + `apiKey/token/secret/password` 正则排除 + `aiChannels` 等整键排除；测试覆盖 |
| R5 | 双向同步误删/覆盖 | 数据丢失 | 中 | 默认不传播删除；冲突默认 `keepBoth`；覆盖前备份到 `conflicts/`；`settings` 冲突不自动合并 |
| R6 | **坚果云频率限制** | 密集请求触发 `503 BlockedTemporarily`，实测持续 >75s，期间所有 WebDAV 请求失败 | **已真实发生** | 客户端请求节流 300ms/次；把该响应归因为 `RATE_LIMIT` 并等待 120s（不是短退避硬撞）；串行同步、`Depth:1` 分层递归、深度上限 6；单次同步文件数上限（默认 2000） |
| R7 | 大文件内存占用（分卷组装） | Zotero 卡顿/OOM | 中 | 组装上限 `maxFileMB`（512MB）；超过则报错不硬拼；后续可改流式落盘 |
| R8 | WebDAV 方法/头被 Zotero HTTP 层限制 | `PROPFIND`/`MKCOL` 失败 | 低 | 已按仓库既有经验使用 `Zotero.HTTP.request`（4xx 不抛异常，需自判 status）；协议层可注入 transport，便于真机替换 |
| R9 | 与 Zotero 原生附件同步并存 | 同一账号两套写入，互相看不见 | 中 | 远程根用独立 `/Papilot`；面板明确"本功能不替代 Zotero 附件同步"；不改 `sync.storage.*`（与参考插件的做法相反，避免打架） |
| R10 | 中文/空格/特殊字符路径 | 404 或写错位置 | 中 | `encodePath` 逐段 `encodeURIComponent`（含 `'()`），`PROPFIND` 结果统一 `decodeURIComponent`；测试覆盖 |
| R11 | 多设备同时同步 | 竞态覆盖 | 中 | 条件 PUT（`If-Match`）+ 每文件独立判定；冲突即分流，不整包覆盖 |
| R12 | AGPL 许可 | 许可证污染 | 低 | 只参考机制，不复制代码；本项目保持 Apache-2.0 |

## 6. 真机验证结果（2026-10-19，真实账号）

用 `scripts/verify-nutstore-sync.js` 对 `dav.jianguoyun.com` 实跑（凭据只走环境变量，脚本不存）：
**17 项全部通过**。覆盖：根目录列举、MKCOL、中文/空格/括号文件名 PUT、大小与 ETag、
PROPFIND 解码、GET 内容一致、错误 `If-Match` → 412、正确 `If-Match` → 条件覆盖、
目录列举、引擎首轮上传、第二轮 0/0、改设置只传 1 个、两边都改产生冲突并留档。

三个只有在真机上才暴露的事实：

1. **ETag 是裸串**（无引号）。客户端原先把 etag 统一补引号 → 条件覆盖直接 412。
   已改为 `etagRaw` 原样回传（同时兼容 Nextcloud 的带引号形态）。
2. **密集请求会被临时封**：脚本约 20+ 次请求后收到 `503 BlockedTemporarily`，
   等 75s 未解除。已加 300ms 请求节流 + 120s 冷却，并把该响应单独归因为限流。
3. 限流期间连删除也会失败 → 清理逻辑改为按已知路径删、请求间隔 400ms，
   避免"清理本身又触发限流"。

## 7. 验收清单（真机）

1. 设置 → Papilot → 云同步：填账号 + 应用密码 → "测试连接" → 显示网盘根目录。
2. 点"立即同步"：`/Papilot/data/settings.json` 出现；再点一次应为"0 上传 0 下载"。
3. 改一个设置项再同步 → 只上传 `settings.json`，其余跳过。
4. 两台设备（或手动改云端 etag）→ 触发冲突 → 生成 `(冲突 本机 …)` 文件，两份都在。
5. 放一个 >64MB 的 xpi 到 `packages/installers/` → 同步后云端出现 `.ppparts/` 与清单；
   在另一台机器"仅下载"能还原出完整文件且大小一致。
6. 断网 → 显示网络错误并重试；恢复后继续，已传文件不重传。
7. 在坚果云后台吊销应用密码 → 同步提示"应用密码失效"，不崩溃、不重复弹窗。
