# Papilot 会员专属功能候选清单

> **分析日期**：2026-10-19 ｜ **代码基线**：插件 `0.60.2` / 服务端 `1.8.1`
> **对比样本**：GitHub 上按 Star 排序的 Zotero 插件 Top 100（快照见 `docs/Papilot-Zotero插件Top100调研.csv` 与 `Papilot-功能借鉴地图-Zotero插件Top100.csv`，1–100 名 Star 区间 11,959 → 91）
> **本文回答**：在「哪些功能可以只卖给会员」这个问题上，哪些是真正能收钱的、哪些是收了会反噬的，以及先做哪一个。

## 0. 结论速览

**一句话**：Papilot 现在卖的是「模型额度」，不是「功能」。要长出会员专属功能，必须选**服务端有真东西**的那一类——因为客户端是 Apache-2.0，任何纯本地功能的付费墙都能被 fork 掉；只有算力、数据授权、托管、跨设备这四样，付费墙才立在用户改不了的地方。

| 序 | 候选功能 | 加权分 | 优先级 | 一句话理由 |
|---|---|---|---|---|
| C1 | 整篇双语 PDF 成品 | **4.60** | **P0** | 两个头部项目合计 1.9 万 Star，痛点恰是「部署难」——成品交付即卖点，且 PDF 不出本机 |
| C2 | 云端文献订阅（每日推送 + AI 摘要） | **4.40** | **P0** | 唯一能做成「每天触达一次」的订阅制，且服务端邮件通道已就绪 |
| C3 | 官方评价指标数据服务（分区/IF/预警/核心） | **4.10** | **P0** | 数据本身要授权费，12 个热门插件在做，付费理由最硬 |
| C4 | 云端 MCP 中继（Remote MCP） | 4.35 | P1 | 稀缺性最高，但隐私模型要先设计，不宜抢跑 |
| C6 | 深度研究 Agent（服务端长任务） | 4.05 | P1 | 高客单、强感知，是 Pro 提价的主要抓手 |
| C12 | 可信度核验（撤稿/预警/图片复用） | 3.55 | P1 | 医学与投稿人群刚需，适合打包进 Pro 而非单独卖 |
| C5 | Papilot Cloud 托管同步 | 3.80 | P1 | 门槛降低明显，但存储毛利薄，当赠品别当卖点 |
| C11 | 团队 / 课题组版 | 3.70 | P2 | 客单最高，但要先有 C5 与权限模型 |
| C9 | 云端 OCR（扫描版/中文老文献） | 3.50 | P2 | 与 C1 天然串联，可作翻译链的前置收费点 |
| C8 | 学科技能包 / 模板订阅 | 2.95 | P2 | 内容型毛利高但易复制，靠持续更新撑 |
| C10 | 论文语音（TTS / 通勤听） | 2.65 | P2 | 体验差异化，付费意愿弱，观察即可 |
| C7 | 付费数据库代查 | 4.00（风险扣减） | **不做** | 需求真实但法律与 ToS 风险不可控，见 §7 |

**成本前提（重要）**：P0 三项里 C2、C3 属 **L0——不新增任何服务器与存储**；C1 虽标 L1，但 PDF 装配在客户端完成，云端只出翻译算力。**不需要先建一朵云，才能开始卖会员功能。**

**三条必须先立的规矩**：

1. **不收回已承诺免费的东西**。README 现在写的是「插件本体永久免费开源」。加会员功能只能「新增云端能力」，不能「把原有功能上锁」；措辞同步改为「核心功能永久免费，云端服务订阅制」。
2. **Free 必须有可用基线**。每项云端能力都给 Free 一个能跑通的额度（如每月 2 篇翻译、每周 1 次订阅推送），否则第一环体验断裂——这正是 2026-10 那次「flash 档全进付费清单」踩过的坑。
3. **门控写服务端，客户端只做提示**。`Account.isPro()` 只用于提前告知，真正的拒绝在服务端签发能力时完成。

## 1. 现状盘点：Papilot 是什么、已经有什么

### 1.1 定位

**「Zotero 负责收集与引用，Papilot 负责打开一篇 PDF 之后的事」**——读懂、翻译、提问、沉淀笔记、补回引文。三条设计原则：本地优先、不锁定模型（14 个通道 + 16 个翻译引擎）、不劫持 Zotero。

与 Top100 的绝大多数项目相比，Papilot 的形态差异是**全家桶 vs 单点工具**：前 10 名单个插件平均只覆盖 1 个功能域，Papilot 覆盖 9 类、40+ 入口。

### 1.2 现有功能资产（按功能中心九组）

| 组 | 关键能力 | 与 Top100 的关系 |
|---|---|---|
| 阅读助手 | AI 工作台、总结/解读、PDF 左原右译、问答悬浮窗五入口、思维导图、技能商店、入库自动精读 | 对标 zotero-gpt 7447★ / pdf-translate 11959★，功能面更宽 |
| 检索与发现 | 库内问答（两阶段检索 + `[n]` 可点引用）、库内检索、arXiv 每日推荐 | 对标 arxiv-daily 6002★，**但只在本地、默认关闭** |
| 笔记与卡片 | 批注转笔记、模板笔记、AI 制卡 Anki、笔记关系图谱、综述工作台 | 对标 better-notes 8281★，缺「模板生态」与批量整理 |
| 批量分析 | 最多 4 篇并排、文献矩阵、综述、引文追溯、参考文献一键入库（五源）、统计报告 | 对标 zotero-reference 2821★，属领先项 |
| 库健康 | 中文元数据（知网/万方）、知网账号登录、元数据体检/医生、真假文献、附件体检、补全文 | 对标 jasminum 7267★，**中文链路是独有护城河** |
| 标签与状态 | AI 打标（受控词表 + 置信度）、规则打标、自动化引擎（17 字段 × 9 操作）、标签治理、阅读三态 | 对标 actions-tags 2837★，条件系统更强 |
| 集成与互操作 | 本地 MCP 10 工具（Bearer + allowWrite）、10 个数据列、云同步（坚果云） | 对标 zotero-mcp 1201★，**但只有本地、无公网** |
| 数据列与配置 | 期刊分区列、被引量列、标题列内嵌阅读进度、主题、菜单定制 | 对标 zotero-style 5284★，进度条形态是独有 |
| 账号（可选） | 官方 AI 通道、设备管理、余额与消耗展示 | 付费墙**仅存在于 AI 网关** |

### 1.3 现有付费结构（这是问题的起点）

生产配置实况（`server/data/`）：

| 项 | 现状 |
|---|---|
| 档位 | Free / Pro 两档 |
| 价格 | 月 ¥9.9 ／ 季 ¥19.9 ／ 年 ¥69（永久档 ¥128 已停用） |
| Pro 权益 | 16 个高级模型、每月 ¥20 额度（不结转）、第三方文献源软门控（注：原「easyscholar 官方 Key」已于 0.56.0 因授权问题移除，当前 Pro 不再自带） |
| Free 权益 | auto + `deepseek-v4-flash`、注册赠 ¥6/30 天、7 天全模型试用 |
| 充值 | ¥10 / ¥30→33 / ¥100→115，永不过期、全模型可用 |

**结构性问题**：Pro 的四条权益里，两条是「模型」，一条是「额度」，一条是「邮件优先支持」这种无代码强制的文案。用户对 Pro 的感知因此只剩一句话——**「贵一点的模型」**。而模型是可以自带 Key 绕过的（这是刻意设计），所以 Pro 的价值锚点其实非常薄。

`docs/会员体系商业模式诊断.md §7` 已经点明：Pro 的真实客群是「不会配 API Key、不想折腾的人」，增值必须发生在**服务层**，不在模型层。本文的候选清单就是沿这条结论往下找。

### 1.4 云端能力盘点：不是没有云，是云只做了两件事

先纠正一个容易误判的前提。Papilot 的服务端确实很薄，但薄在**业务**，不薄在**底座**：

| 已有能力 | 具体实现 | 能直接支撑什么 | 还缺什么 |
|---|---|---|---|
| 身份与会话 | register / login / me / sessions / revoke，滑动续期 | 门控、设备管理、用量归属 | 无 |
| **通用代理** | `/v1/chat/completions` → 活动通道上游，SSE 透传、`extraBody` 合并、超时熔断 | **换一个上游就是一个新付费能力**（翻译 / TTS / OCR / 核验） | 非 OpenAI 形状的上游需加适配（约 1 个 route + 1 条定价） |
| 计量与余额 | 按 token 计费、三档余额、预扣、流水 | 按次 / 按页 / 按篇都能挂 | 非 token 单位（页、次）要加一个计量器 |
| 邮件 | `server/lib/mail.js`，零依赖 SMTP，已在跑验证与重置信 | **C2 订阅推送零新基建** | 定时任务、退订页 |
| 公网入口 | Cloudflare 隧道 `pp.xinglintools.top → :8000` | C4 Remote MCP 不用买服务器 | 只读令牌、字段白名单、审计日志 |
| 交易 | 订单、在线支付、激活码、优惠券、对账 | 新档位 / 额度包可直接开卖 | 无 |
| 运维 | 备份、告警、审计、账号锁定 | 新功能上线有兜底 | 无 |

**关键结论**：现有 `/v1/chat/completions` 本质是一个**带鉴权、限流、计量、余额的多租户 API 中转**。这条底座目前只被用来转 chat，一旦把它当成「通用计费代理」，C1 / C9 / C10 / C12 全都变成「加一个上游 + 加一条定价」，而不是「做一个云产品」。

真正需要新基建的只有两处：**对象存储**（C5 托管同步）与**多租户权限**（C11 团队版）。其余候选都可以长在现有进程里。

> 本文后文凡称「云端」，均指上述现有设施的复用（网关 / 邮件 / 隧道 / 交易），不含新建基础设施；只有标注 L2、L3 的项才需要真的加东西。

### 2.2 五个趋势判断

**① 最大公约数是「库卫生」，不是「AI」。** 21/100 在做元数据、附件、重复项、中文题录。这类需求不性感，但**人人都要做、每次都烦**——这正是付费意愿的来源（省时间）。中文场景只有一个竞品 jasminum（7,267★，全站第 4），Papilot 已覆盖且多了知网账号登录，这是最容易被低估的资产。

**② AI 已从「有没有聊天窗」进入「用得好不好」。** zotero-gpt（7,447★）2026-05 后停更，说明单点 GPT 浮窗的窗口期已关闭；仍在增长的是 llm-for-zotero（3,179★）、PapersGPT（2,662★）这类**多模型 + 任务化**的形态。结论：再做一个聊天窗没有意义，**把 AI 变成可交付的产物**才有意义。

**③ 「整篇 / 批量 / 成品」胜过「逐句」。** pdf-translate 11,959★ 是划词级，pdf2zh 7,058★ 是整篇保留版式——后者 Star 更少但**用户愿意为它折腾 Python 环境**，这是最强的付费信号。同理，批量矩阵/综述比单篇总结更接近「写论文」的真实场景。

**④ 用户缺的不是功能，是「托管」。** arxiv-daily 6,002★ 要求用户自己配 GitHub Actions；zotero-mcp 1,201★ 要求自己跑 Node；pdf2zh 要求本地 Python + 字体。这三件事的共同点是——**功能开源，部署劝退**。托管是天然的订阅理由，也是唯一无法被 fork 拿走的东西。

**⑤ 互操作成为新战场。** 9/100 在做 Notion / Obsidian / Word / MCP / 纯文本导出。Zotero 正在从「终点」变成「中转站」，谁能把库接到用户的其他工具上，谁就拿到下一轮入口。

### 2.3 竞争格局里 Papilot 的位置

- **宽度第一**：没有任何单一插件覆盖「读—译—问—记—引—治库」全链。
- **中文深度第一**：知网登录、中文文件名解析、中科院分区、中文 PDF 对照，Top100 里无同构竞品。
- **云端能力最弱**：所有能力都在本机，服务器目前只做账号与 AI 转发。**这既是短板，也正是会员功能的空间所在。**

## 3. 差异化空间：三个真实空位

| 空位 | 说明 | 为什么现在能进 |
|---|---|---|
| **A. 中文科研工作流的「成品交付」** | 现有中文能力停在「面板里的工具」，没有变成「可以直接用的东西」（双语 PDF、投稿前自查报告、中文综述草稿） | jasminum 只做元数据，pdf-translate 不管中文排版，无人在此交付成品 |
| **B. 库即服务（Library-as-a-Service）** | 本地 MCP 已有，但没有公网入口；订阅推荐只在本地跑 | zotero-mcp 需自部署、arxiv-daily 需 Actions，托管侧完全空白 |
| **C. 持续供给型价值** | 指标数据每周更新、每日推荐、撤稿预警——都是「停订就退回原点」 | 现有插件全是「装一次管一辈子」，没有订阅心智，Papilot 可以先占 |

**同时要避开的红海**（做了也收不到钱）：

- BibTeX / citekey：BBT 7,181★ 且 MIT 免费，正面做毫无胜算，只能联动。
- 基础翻译引擎：pdf-translate 已免费覆盖 20+ 引擎，收费即劝退。
- 主题与美化：zotero-night 2,452★ 免费，用户不接受为皮肤付费。
- 基础云同步：Zotero 自带附件同步，插件层收存储费毛利极薄。

## 4. 候选清单（逐项）

评分口径：需求强度 30% ／ 差异化 20% ／ **可防御性 25%** ／ 变现力 15% ／ 落地容易度 10%，各项 1–5 分。可防御性权重特意给高——客户端开源，防不住 fork 的功能不值得投入。

### 4.0 先按「要新建多少云」分个级

这一层比功能本身更能决定先做谁。**L0 意味着不新增任何服务器与存储**：

| 级别 | 定义 | 候选 | 增量工作量 |
|---|---|---|---|
| **L0 零新基建** | 只复用现有代理 / 邮件 / 隧道 / 交易，加业务逻辑 | C2、C3、C9、C10、C12 | 1–3 人周 / 项 |
| **L1 同机扩展** | 在现有 Node 进程里加队列与 worker，不买机器 | C1、C6 | 3–6 人周 / 项 |
| **L2 轻基建** | 需要新的网关路由或对象存储 | C4、C5 | 4–8 人周 / 项 |
| **L3 重基建** | 需要多租户隔离、权限与审计模型 | C11 | 8 人周以上 |

按这个分级重排，P0 三项里有两项是 L0——**这正是「没啥云端能力」也能先开卖的原因**。

### C1 · 整篇双语 PDF 成品（网关算力 + 客户端装配）★P0

**功能内容**：选中条目（可多选）→ 批量送翻译（官方网关或自带 Key 均可）→ **客户端装配**出「左原文右译文」或「上下双语」的 PDF 成品，回挂为附件；支持术语表统一、页码对照、失败页重试。

**对比依据**：pdf-translate 11,959★（段落级对照，不产出成品 PDF）；pdf2zh 7,058★（保留版式，但需本地 Python + 字体 + 模型，配置门槛劝退大量用户）。Papilot 已有 `PdfText` 双路径 blocks、左原右译窗口，以及 `pdf-export.js` 527 行——**它已经能把每页 canvas 与译文原位叠画成 PDF 并挂附件**。

**潜在价值**：**唯一能按「篇」而不是按「token」计价的 AI 功能**，用户对「一篇论文 ¥2」的心理账户远好于「花了多少 token」。写综述/开题阶段单用户月均 10–30 篇，ARPU 显著高于纯问答；且成品文件天然可分享，带自传播。

**实现可行性**：高（比原方案高一档）。既然装配在客户端，**PDF 根本不出本机**——这既省掉了服务端渲染基建，又是一个能打的隐私卖点。云端只需在现有网关上加「页级计量 + 批量队列」，工作量集中在客户端批量调度与断点续传。风险集中在双栏、表格、公式三处——**MVP 只承诺单栏 + 图表保留，双栏降级为线性对照并明示**，不要一上来承诺「像素级还原」。

**定价形态**：Pro 每月含 50 页，超出买页数包（¥10/50 页）；Free 每月 2 篇体验（限 20 页内）。

---

### C2 · 云端文献订阅（每日推送 + AI 摘要）★P0

**功能内容**：服务端按用户库内画像（分类/主题/作者/近期阅读）每天拉取 arXiv / OpenAlex / Crossref / Europe PMC / PubMed，去重打分后生成一份摘要邮件（或客户端收件箱），点标题直达条目/PDF；支持每日、每周、仅工作日；一键退订。

**对比依据**：arxiv-daily 6,002★ 是全站第 7，但它要用户自己 fork 仓库、配 GitHub Actions、填邮箱密钥——**功能开源、运维劝退**。Papilot 本地 `discovery.js`（598 行）+ 五源适配层 + `buildProfile` + 12h 缓存已完整，只差「7×24 在云端跑」。

**潜在价值**：**订阅制最自然的形态**——每天触达一次，停订即失去。它能解决 Papilot 目前最大的留存问题：用户不打开 Zotero 就完全想不起插件。邮件到达率也让它成为唯一能跳出 Zotero 的触点。

**实现可行性**：高。`server/lib/mail.js` 已是零依赖 SMTP 实现（现用于验证/重置邮件），cron + 队列 + 退订页是常规工程量；客户端只需「订阅设置 + 摘要预览」。唯一要注意的是**成本控制**：Profile 计算与候选拉取可全库共享缓存，单用户边际成本接近 0。

**定价形态**：Pro 每日推送；Free 每周 1 次（同时是转化钩子：想天天收就升级）。

---

### C3 · 官方评价指标数据服务（分区 / IF / 预警 / 核心）★P0

**功能内容**：服务端统一取数 + 缓存 + 容灾，向客户端下发「分区 / 影响因子 / CiteScore / 中科院预警名单 / 北大核心 / CSSCI / CSCD」多体系数据；支持按刊名/ISSN 反查、整库批量刷新、每周增量更新；任一数据源失效自动回退到备用源。

**对比依据**：指标与数据列 12/100 是第二大域——zotero-style 5,284★、citationcounts 931★、updateifsE 923★、zotero-if 477★、Scholar-Rank 165★ 挤在同一件事上。而这些插件的数据源普遍是**会员制或需申请**（easyScholar 本身即付费服务），用户对「查分区要付费」早有心理预期。

**潜在价值**：**付费理由最硬的一类**——不是「我做了个功能」，而是「这份数据我替你付了授权费、并保证它每周是新的」。可以单独卖年费（¥39–69/年），也可以作为 Pro 的核心权益。Papilot 有先例但已撤：0.41.0 起 easyscholar 官方 Key 仅 Pro 可用，0.56.0 因无转售授权而移除——**C3 若重做，必须先拿到商用授权，不能复用个人 Key**。

**实现可行性**：高，而且**几乎不涉及"云"**。列机制与离线兜底已在跑；数据包可以在构建期用 Python 脚本生成（离线 JSON 随包发布或单独下发），服务端只做「授权校验 + 每周增量」。真正的成本是**数据授权谈判与数据工程**，不是服务器——所以这一项要早启动、慢上线。

**定价形态**：Pro 含全体系；Free 只给「中科院分区」一个体系且不保证时效。

---

### C4 · 云端 MCP 中继（Remote MCP）— P1

**功能内容**：把本地 10 个 MCP 工具通过公网 HTTPS 暴露，配 OAuth / 个人访问令牌、按工具授权、审计日志；用户在手机上的 ChatGPT、平板的 Claude、公司电脑的 Cursor 都能问「我库里关于 X 的文献有哪些」。

**对比依据**：zotero-mcp 1,201★ 只有本地 stdio，必须同机运行；notero 3,233★ 只能单向推到 Notion。**「随时随地访问自己的库」这个需求目前无人满足**，而它天然需要服务器。

**潜在价值**：稀缺性最高的候选，也是最能体现「Pro 不是贵模型而是多一个入口」的功能。适合放进更高的 Pro+ 档，而不是基础 Pro。

**实现可行性**：中。协议层已现成（`mcp.js` 806 行 + Bearer + `allowWrite`），公网入口也不用新建——`pp.xinglintools.top` 隧道已经把 `:8000` 暴露在外，加一条路由 + 一套只读令牌即可。难的是**隐私模型**：默认只暴露元数据与摘要、全文按需拉取并逐次记录、默认只读、可一键吊销、可按分类白名单。这些设计没做完之前不要上线——一次泄露事故会毁掉「本地优先」的全部口碑。

**定价形态**：Pro+（¥29–39/月）或 Pro 加购。

---

### C6 · 深度研究 Agent（服务端长任务）— P1

**功能内容**：用户提一个研究问题 → 服务端跑 20–60 分钟的多步任务（库内两阶段检索 + 外部五源补全 + 逐条证据抽取 + 引用核验）→ 产出「证据表 + 分节综述草稿 + 可点击引用」，直接回写为 Zotero 笔记。

**对比依据**：llm-for-zotero 3,179★、PapersGPT 2,662★、AI-Butler 1,770★、ai-research-assistant 1,729★ 都停在「单轮问答 / 单篇总结」。长任务一旦超过几分钟，用户在客户端跑就意味着**关掉 Zotero 就断**——这给了服务端一个天然理由。

**潜在价值**：客单价最高的 AI 形态（一次任务可计价 ¥1–5），且结果可交付、可炫耀，是 Pro 提价的主要抓手。Papilot 已有 Agent 模式（JSON 工具协议、11 工具、写确认）与综述工作台，起点不低。

**实现可行性**：中。需要任务队列、断点续跑、成本上限（防止一次任务烧穿额度）、引用核验（每个 `[n]` 必须能落到真实段落）。**早期量级单机就够**：跑在现有 Node 进程的子任务队列里即可，不需要独立的作业集群。建议先在客户端做「同步版」验证提示词质量，再搬到服务端。

**定价形态**：Pro 每月 5 次深度任务，超出按次购买。

---

### C12 · 可信度核验（撤稿 / 预警 / 图片复用）— P1

**功能内容**：入库或投稿前自动核验：是否被撤稿（Retraction Watch）、期刊是否在中科院预警名单、PubPeer 是否有质疑、图片是否重复（可选）；输出一份「投稿风险自查单」。

**对比依据**：pubpeer_zotero_plugin 216★ 只做评论查询；Papilot 已有 `fake-check.js`（AI 幻觉检测）与「真假文献识别」。把散落的核验汇成**一份可交付的报告**，是差异化而非重复。

**潜在价值**：医学、临床、投稿人群的强需求（关系到能否发表），但单独收费意愿一般——**更适合作为 Pro 的信任型权益**，用来提升 Pro 的整体价值感。

**实现可行性**：高。数据源以公开接口为主，服务端做同步与缓存即可；图片复用检测成本高，放 P2。

---

### C5 · Papilot Cloud 托管同步 — P1

**功能内容**：把现有坚果云 WebDAV 同步换成「一键开通」的官方托管：设置项、AI 会话、技能包、术语表跨设备同步，含容量配额、版本历史、冲突留档。

**对比依据**：Top100 无插件级对标（Zotero 自带只同步附件与元数据）。Papilot 的 `cloud-sync.js` 已有 2,202 行三向增量引擎，**能力在、门槛在**——用户要自己去坚果云申请应用密码，这一步流失率很高。

**潜在价值**：降低门槛、增强粘性，但**存储成本真实、毛利薄**（1GB 用户年成本可能吃掉一次年费）。定位应是「Pro 赠品（1GB）」而不是独立卖点。

**实现可行性**：中高。同步引擎可复用，需加对象存储、鉴权、配额与清理策略；注意「换机器必须能恢复」是信任底线。

---

### C11 · 团队 / 课题组版 — P2

**功能内容**：席位制，共享标签体系、术语表、技能包、自动化规则模板、文献推荐订阅；管理员可看使用概况，成员各自库不互通。

**对比依据**：Top100 在插件层完全没有团队功能（Zotero 群组库是原生能力，插件不涉足）。但课题组「统一术语、统一标签、共享模板」是真实痛点。

**潜在价值**：客单最高（¥/席位/年），B 端续费稳定，是长期天花板。

**实现可行性**：低—中。依赖 C5 的托管底座与一套权限/审计模型，工作量在「组织与权限」而非功能本身。建议 6 个月后再评估。

---

### C9 · 云端 OCR（扫描版 / 中文老文献）— P2

**功能内容**：无文本层 PDF → 云端 OCR（版面还原、中英混排、公式尽量保留）→ 回写文本层，使后续翻译/问答可用。

**对比依据**：zotero-ocr 830★ 依赖本地 Tesseract，装语言包、中文与公式效果差。Papilot 的「附件体检」已能识别无文本层 PDF，**发现了问题却没有解法**，这是明显的断点。

**潜在价值**：中文老文献、扫描版学位论文的刚需；按页计价，是 C1 的天然前置收费点（不能 OCR 就谈不上排版翻译）。

**实现可行性**：中。需接 OCR 服务并控成本；建议先只支持「中文 + 英文」两种，公式与表格明确降级。

---

### C8 · 学科技能包 / 模板订阅 — P2

**功能内容**：官方策展的学科包（医学 / 法学 / 计算机 / 社科），每月更新：提示词、术语表、笔记模板、Agent 预设；Pro 可一键安装并自动跟随更新。

**对比依据**：better-notes 8,281★ 的模板生态、zotero-addons 1,760★ 的插件市场证明「内容市场」有需求；Papilot 技能商店与 manifest 四槽（prompts / glossary / noteTemplates / agentPreset）已具备零代码分发能力。

**潜在价值**：内容型订阅毛利最高、边际成本近零，但**内容可被复制**，护城河只有「持续更新 + 学科深度」。

**实现可行性**：高（商店已存在）。真正的投入是找人写内容，不是写代码。

---

### C10 · 论文语音（TTS / 通勤听）— P2

**功能内容**：把单篇论文或综述草稿转成 10–20 分钟音频，支持倍速、章节跳转，可导出 mp3。

**对比依据**：zotts 211★ 属于长尾；但「通勤听论文」是被播客验证过的场景。

**潜在价值**：体验差异化强、传播性好（可分享音频），但付费意愿弱，更适合当增长功能而非收入功能。

**实现可行性**：高（TTS 接口按字计费），成本可控。

---

### C7 · 付费数据库代查 — **不做**

**功能内容**（若做）：知网/万方机构资源代查、第三方文献站入口（现有 `third-source.js` 已软门控 27 个入口）。

**为什么不做**：jasminum 7,267★ 与 scipdf 1,017★ 证明需求真实，但这条链路的风险不对等——Sci-Hub 类入口涉及法律风险，知网 ToS 明确禁止代检代下，**一次投诉就可能让整个插件下架**。现有「第三方文献源」作为默认关闭的试验功能尚可，**绝不能变成会员卖点**。合规版只保留：Unpaywall / OA 合法补全文，以及用户自有机构账号的本地凭据代理（凭据不出本机）。

## 6. 包装与定价：从「卖模型」到「卖交付」

现价月 ¥9.9 / 年 ¥69，模型额度 ¥20/月——**这个价位撑不起「功能型权益」的期待，也不该靠堆功能涨价**。建议改成「按交付物分层」，而不是「按功能开关分层」：

| 档 | 价格（建议） | 卖的是什么 | 关键权益 |
|---|---|---|---|
| **Free** | 0 | 完整体验，不残缺 | 本地全部功能（保持现状）+ 云端：每月 2 篇翻译（≤20 页）、每周 1 次订阅、基础分区一个体系 |
| **Pro** | ¥19–29/月，¥129/年 | **省时间** | 全部云端模型、每日订阅、全指标体系、50 页/月翻译、5 次深度研究、可信度核验、1GB 托管同步 |
| **Pro+ / 额度包** | 按次 | **不想订阅的人** | 页数包 / 任务包，永不过期，可买 C4 Remote MCP |
| **团队** | 席位制 | 统一与合规 | 共享术语/标签/模板 + 管理视图（C11，远期） |

**三件必须先改的事**：

1. **README 措辞**：从「插件本体永久免费开源」改为「**核心功能永久免费；云端交付与数据服务为订阅制**」，并在功能表里标出哪些是云端能力。承诺变了要提前说，不能等用户发现。
2. **价值可视化**：每次云端交付完成后显示「本次节省约 X 分钟 / 消耗 1 页额度 · 本月剩余 N 页」。额度只有被看见才会产生续费压力——这条在 `会员体系商业模式诊断 §4` 已经被验证过一次。
3. **先给后卖**：新功能上线首月对全部登录用户开放（限次数），收集真实使用率再决定哪一项进付费墙。**不要凭直觉锁功能**。

## 7. 风险与红线

| 风险 | 说明 | 应对 |
|---|---|---|
| **开源承诺反噬** | 客户端 Apache-2.0，用户可 fork 去掉门控；若被指「假开源真收费」，口碑损失远大于收入 | 只对**服务端交付**收费；客户端所有门控都用「服务端拒绝」实现，客户端只提示；公开说明哪些是云服务 |
| **合规** | Sci-Hub / 知网代检 / 第三方文献站 | 明确不做（C7）；现有试验功能保持默认关闭、不宣传、不收费 |
| **隐私** | C4/C5 会把库内容带出本机 | 默认关闭、最小字段、可吊销、审计日志、明示「只传元数据与摘要」；全文按需并逐次授权 |
| **成本失控** | C1 大页数、C6 长任务、C9 OCR | 服务端硬上限 + 预扣额度 + 超时熔断；Free 档永不进入高成本路径 |
| **功能税** | 把太多东西塞进 Pro，Free 变成残废版 | 每项云端能力都给 Free 一条能跑通的基线；Free 的目标是「用得上瘾」，不是「用不下去」 |
| **数据授权** | C3 的指标数据涉及版权 | 优先聚合公开/授权数据；拿不到授权就只做「用户自填 + 本地缓存」，不硬上 |

## 8. 如果一行云端都不想加：Plan B

适用场景：短期没有精力扩服务端，或想先用最低成本验证「到底有没有人愿意为功能付钱」。

**三条现成手柄**（都不用碰服务端架构）：

| 手柄 | 已有实现 | 代价 |
|---|---|---|
| **激活码 + 客户端软门控** | `/api/redeem`、`admin/codes`、`Account.isPro()`；`third-source.js` 已有完整先例 | 代码量以小时计，今天就能卖 |
| **官方 Key 代管** | 0.41.0 起 easyscholar 官方 Key 曾仅 Pro 可用，**0.56.0 已移除**（无转售授权）；现无任何官方 Key 通道 | 需先取得 easyScholar 商用授权 + 服务端代理，见 C3 |
| **内容与数据包** | 技能商店 manifest 四槽；分区离线包 | 构建期生成，随包或单独下发 |

**必须承认的代价**：

- **软门控只防老实用户**。客户端 Apache-2.0，改一行 `isPro()` 就绕过；社区一旦出现「破解版」，付费转化会被打穿。
- 所以 **Plan B 适合验证，不适合当终局**。正确用法：先用 1–2 个软门控功能卖三个月，拿到真实付费率，再决定值不值得做 L0/L1 的云端能力。
- **绝不能用 Plan B 去锁已有免费功能**。那会同时损失口碑与收入：老用户流失，新用户不进门。

**判断信号**：三个月内如果付费转化率 < 1%、且退款/投诉集中在「功能不值这个价」，说明问题不在门控形式，而在价值本身——此时该做的是 C1/C2 这类「交付物」，不是继续加锁。
