# Papilot 账号系统与 AI 模型通道（0.14.0 设计文档）

> 客户端（本插件）已实现并经 50 项 E2E 测试验证；配套账号后台（server/）与启动管理器已随仓库交付，
> 双击项目根目录 `启动Papilot后台.bat` 即可管理（见第四节）。
> 模型通道管理移植自「AI 带教中心」的通道面板，功能结构与交互逻辑保持一致。

## 一、总体架构

```
Zotero 插件（本文档）
├── Account（ai/account.js）      邮箱密码登录 / 会话持久化 / 过期处理 / 用量展示
├── Channels（ai/channels.js）    模型通道注册表 / 厂商预设与探测 / 官方通道权限
└── AIClient（ai/client.js）      全部 AI 功能统一从「活动通道」取配置调用

账号服务器（官方 https://pp.xinglintools.top，0.15.0 起地址内置固定、设置界面不再提供入口）
├── /api/auth/*                   鉴权三端点（登录/登出/会话信息）
└── /v1/*                         OpenAI 兼容网关（models + chat/completions，Bearer 令牌）
```

核心规则：**登录后官方模型按 AI 额度扣费；未登录时官方通道不可切换、不可调用**（所有 AI 功能统一拦截并给出指引），用户仍可配置自己的通道使用任意 OpenAI 兼容接口，自带 Key 不消耗平台额度。

## 二、服务端 API 契约

所有应答为 JSON；鉴权头 `Authorization: Bearer <token>`。

### 1. 登录

```
POST /api/auth/login
{ "email": "user@example.com", "password": "..." }

200 { "ok": true, "token": "pp-xxx", "expiresAt": "2026-10-09T00:00:00Z",
      "user": { "email": "user@example.com", "name": "昵称", "plan": "Free",
                "balance": { "totalMicro": 6000000, "text": "¥6.00" },
                "usage": { "today": 3, "last7": 12, "days": [ ... ] } } }
401 { "ok": false, "error": "邮箱或密码错误" }        # 文案由服务端定，客户端原样展示
429 { "ok": false, "error": "尝试过于频繁" }
```

- `expiresAt`：ISO 8601；客户端据此做本地过期判断
- `user.usage`：调用次数**统计**（1.8.0 起不再有次数上限；放行与计费统一看 `user.balance`）
- `user.balance`：AI 额度余额（微元 + 已格式化文案；旧服务端无此字段时客户端整块隐藏）

### 2. 登出

```
POST /api/auth/logout        # Bearer token
200 { "ok": true }
```

客户端尽力调用（2s 超时，失败不影响本地登出）。

### 3. 会话信息（刷新用量 / 滑动续期）

```
GET /api/auth/me             # Bearer token
200 { "ok": true, "user": { ... }, "expiresAt": "..." }   # 返回 expiresAt 即滑动续期
401 { "ok": false, "error": "登录已过期" }
```

调用时机：插件启动恢复会话时、设置面板「刷新状态」按钮、官方网关调用后（客户端本地对齐）。401 → 客户端自动失效会话。

**令牌生命周期（0.15.1 / 服务端 1.3.1）**：TTL **30 天滑动续期**——`/api/auth/me` 与 `/v1/*` 网关调用均续期（网关续期内存即时、磁盘 30s 节流落盘，停机强制落盘）。用户只要在用（含仅用 AI 而不重启 Zotero 的场景）登录就一直有效；连续 30 天不使用才需要重新登录。旧版（7 天 + 仅 /me 续期）曾导致"距上次重启超过 7 天，插件更新后首次校验 401 → 被登出"，表现为"每次更新都要重新登录"。

### 4. 官方模型网关（OpenAI 兼容）

```
GET  /v1/models              # Bearer token → { "data": [{ "id": "auto" }, ...] }
POST /v1/chat/completions    # Bearer token → 标准 OpenAI 格式（支持 SSE 流式）
```

`model` 取值：`auto`（官方默认模型）或网关支持的具体模型名。401/403 → 客户端视为登录过期，自动失效会话并弹窗提醒。

#### 多厂商路由与双成本账（服务端 1.10.1）

- 当前生产托管范围：`auto` / `deepseek-flash` / `deepseek-v4-pro`；auto 固定路由 Flash，Pro 属高级档，其余模型优先走用户自带 Key。
- `channels.json.modelRoutes` 按公开模型选择通道：`{ "auto": { "channelId": "deepseek-main", "upstreamModel": "deepseek-flash" } }`。管理接口 `PUT /api/admin/channels/routes` 整体更新路由；未单独配置的模型仍走 `active`，保持旧部署兼容。采购硅基流动等 OpenAI 兼容 API 后，新增通道、价格、路由、发布清单即可，无需改插件。
- `pricing.json.requireKnown=true` 时，未配置明确销售价的模型不能上线或调用。管理页可维护销售输入/输出价、上游输入/输出/缓存成本价。
- 请求发出前冻结 `tariffModel`，上游响应里的 `model` 仅作对账，不能改写用户售价。`usage.costMicro` 是销售扣费，`usage.upstreamCostMicro` 是已知上游成本；成本未配置或不完整时记 `upstreamCostUnknown`，不伪造为 0。
- 完整 usage 按实际 token 结算；缺 usage、只有 `total_tokens`、响应无法解析、收到部分内容后断连，按请求前预估值结算并累计 `estimatedCharges`。未收到任何上游内容的取消仍不收费。
- Pro 后续周期每月额度为 ¥8；已经发放的周期额度不回收。官方 DeepSeek 成本按高峰价配置，低峰与缓存命中形成额外毛利空间。

### 5. 注册（公开自助，服务端 1.1）

```
POST /api/auth/register     { email, password(≥8位), nickname? } → { ok, user:{email,name,plan:"Free"} }
GET  /register              公开注册页（public/register.html，浏览器打开）
```

公开注册固定 Free 套餐（100 次/天）；每 IP 每分钟限 5 次。升级套餐/设有效期走本机管理。
客户端「注册账号」链接打开 `{server}/register`——本机后台与公网部署均适用。

## 三、客户端实现要点

### 会话与安全

- **持久化**：`{Zotero数据目录}/papilot-account.json`，`IOUtils.writeUTF8` + `tmpPath` 原子写 + `0o600`；不进 prefs（避免明文/被配置同步带走），**密码永不落盘**。**卸载/更新不删除该文件**（0.15.1：旧版卸载钩子删文件曾导致更新后被迫重新登录；令牌安全性由服务端保障——仅存散列、30 天滑动过期、改密即吊销）
- **过期处理**：本地 `expiresAt` 判断（30 天滑动，网关调用成功即续期对齐）+ 服务端 401 双保险（AI 调用/刷新遇 401 → 清会话 + 弹窗「登录已过期」+ UI 联动切回未登录态）；403（WAF/反代拦截）不清会话
- **网络异常翻译**：超时/拒连/5xx/429 均给出可操作中文提示（如「本地网关未启动，或地址在设置中改错」）
- **卸载清理**：`bootstrap.js` uninstall 时删除会话文件

### 模型通道（pref `aiChannels`）

```json
{ "channels": [ { "id": "deepseek-main", "name": "DeepSeek 日常", "provider": "deepseek",
    "baseUrl": "https://api.deepseek.com/v1", "apiKey": "sk-...",
    "model": "deepseek-chat", "models": ["deepseek-chat", "deepseek-reasoner"],
    "extraBody": {}, "timeoutMs": 12000 } ],
  "active": "official" }
```

- **官方通道**（`official`）：恒存在、置顶、不可删除；`baseUrl`/`apiKey` 由账号系统运行时注入（不落盘）；未登录不可设为活动通道；模型可在账号卡片切换（auto + 网关模型列表）
- **交互**（与原通道面板一致）：状态卡（活动通道/模型/总数）→ 通道行（切换/实测/参数/删除）→ 新增/编辑表单（厂商预设自动填充、🔍 检测按密钥格式圈定候选并行探 /models、📡 拉取上游模型、模型 chips、extraBody JSON、探活超时；编辑时 Key 留空=保持原密钥）
- **迁移**：首次启动把旧版 `aiBaseUrl/aiApiKey/aiModel` 与 `aiProfiles` 快照自动转为通道（幂等，不丢数据）；删除活动通道自动回落官方通道
- **快速切换**：工具菜单「Papilot AI 模型通道」+ 工作台顶栏下拉

### AIClient 消费链

`AIClient.chat/chatStream` 每次调用实时解析 `Channels.getActiveConfig()`：

| 状态 | 行为 |
|---|---|
| 官方通道 + 已登录 | 网关 = `{server}/v1`，令牌 = 登录 token |
| 官方通道 + 未登录 | 抛「官方模型需要登录：请在 设置 → Papilot 登录账号…」（34 项功能 catch 链直接展示） |
| 自定义通道 | 通道 baseUrl/apiKey/model/extraBody（extraBody 并入请求体） |
| 官方通道调用遇 401/403 | 自动失效会话 + 弹窗提醒 |

`hasKey()`（各功能的「AI 可用」门）在官方通道未登录时返回 false，提示文案统一为登录引导。

## 四、账号后台服务端（server/，0.14.0 已随仓库交付）

> Node ≥ 14 零依赖实现（`server/account-server.js`），完整实现第二节契约 + 本机管理 API。
> 端到端测试 71/71（`.workbuddy/account-tests/test-server.js`）。

### 架构

```
server/
├── account-server.js        主入口：鉴权 + 官方网关 + 管理 API（--port=8000，env PP_PORT/PP_DATA_DIR）
├── lib/presets.js           17 家厂商预设（与插件端 channels.js 同源维护）
├── lib/store.js             JSON 原子存储（tmp+rename，损坏自动备份回退）
├── public/admin.html        浏览器管理页（/admin，仅本机）
└── data/                    运行时数据（gitignore，绝不入库）
    ├── users.json           用户（scrypt 密码散列）+ 令牌表（仅存 SHA-256 散列）
    ├── channels.json        官方网关上游通道池 + active
    └── server-console.log   控制台日志（经启动管理器启动时）
```

### 与插件的关系

- 插件默认 `http://127.0.0.1:8000` **零改动直连**：登录 → 令牌 → `/v1` 网关
- 官方网关把登录用户请求转发到**服务端活动通道**上游（`auto` → 通道默认模型，`extraBody` 合并不覆盖调用方键，SSE 流式透传，上游 4xx/5xx 原状态码透传）
- 服务端通道池与**插件本地通道**（用户自己的 Key）互不相干：前者决定「官方模型走哪个上游」，后者是用户直连
- 每成功转发一次用量 +1（仅统计）；1.8.0 起**没有每日次数上限**，余额不足返回 402；套餐有效期过期自动降级 Free（模型范围与月度额度）

### 管理 API（仅 127.0.0.1）

| 分组 | 端点 |
|---|---|
| 健康检查 | `GET /api/health` |
| 厂商预设 | `GET /api/admin/providers` |
| 用户 | `GET/POST /api/admin/users` · `PUT/DELETE /api/admin/users/:id` · `POST /api/admin/users/:id/password` |
| 通道 | `GET/POST /api/admin/channels` · `PUT/DELETE /api/admin/channels/:id`（支持部分更新：只传 `model` 即改官方默认模型，Key/地址等保持原值） · `PUT /api/admin/channels/active` |
| 通道探测 | `POST /api/admin/channels/:id/test`（实测）· `GET /api/admin/channels/:id/models`（拉取，成功后自动刷新该通道的模型列表缓存） · `POST /api/admin/channels/detect`（密钥检测） |
| 上线管控 | `PUT /api/admin/channels/published`（0.15.0：`{models:[...]}` 空数组=全部上线） |
| 管理页 | `GET /admin`（浏览器版通道+账号管理）· `GET /register` → 302 管理页 |

**官方默认模型（0.14.1）**：= 活动通道的 `model` 字段。网关把登录用户的 `auto` 映射到它，也可在请求中直接指定活动通道模型列表中的任意模型。三处管理界面均可「拉取模型 → 下拉选择（或输入自定义名）→ 设为默认」：
- 启动管理器「通道管理」弹窗的「官方默认模型」行（📡 拉取 + 设为默认）
- 浏览器管理页「网关状态」卡（同款拉取/设为默认）
- 通道编辑表单的「默认模型」下拉（候选来自模型列表，支持自由输入）；插件设置面板的模型 chips 点击即选用

**对外上线模型（0.15.0）**：官方模型**不再一次性全部上线**——由后台配置控制实际对外发布的数量与范围。
- 数据：`channels.json` 顶层 `publishedModels`（模型名数组）；**空/缺省 = 全部上线**（兼容既有部署）
- 生效：`GET /v1/models` 只返回 `auto` + 上线清单内的模型；显式调用未上线模型返回 400（`auto` 恒放行，映射官方默认模型）
- 管理：启动管理器「通道管理」的「对外上线模型」行（📡 填充候选 + 保存上线，逗号分隔）；浏览器管理页「对外上线模型」卡（chips 勾选 / 手动添加 / 全部上线一键恢复）
- 用途：小步快跑发布——先上 1-2 个稳定模型，观察用量与上游预算再逐步放开；插件端 `fillOfficialModelSelect` 拉取 `/v1/models` 后即只展示上线模型，无需发版

**邮箱验证与密码找回（服务端 1.2 / 插件 0.14.5）**

- 端点：`POST /api/auth/resend`（重发验证）、`POST /api/auth/verify`、`POST /api/auth/forgot`、`POST /api/auth/reset`；公开页 `/verify` `/forgot` `/reset`
- 行为：配置邮件后注册 = `pending`（验证邮件 24h）→ 验证后可登录；忘记密码发重置链接（30min，一次性，重置后吊销全部会话）；未配置邮件时自动降级为「注册直接激活 + 找回密码引导联系管理员」，完全向后兼容
- 防枚举：resend/forgot 对任意邮箱返回恒定文案；邮件请求限速每 IP 每分钟 3 次；一次性令牌只存 SHA-256 散列
- **邮件服务配置（Resend，免费 100 封/天）**：
  1. 注册 [resend.com](https://resend.com) → Domains → 添加 `xinglintools.top` → 按提示在 **Cloudflare DNS** 加 SPF（TXT）与 DKIM（CNAME）记录 → 等待验证
  2. API Keys → 创建 key（`re_` 开头）
  3. 写入 `server/data/pp.env`（gitignored，密钥不进 git）：`PP_RESEND_KEY=re_xxx`（可选 `PP_MAIL_FROM`、`PP_PUBLIC_URL`）→ 重启账号后台，health 的 `mail` 字段变 `on` 即生效
  4. Cloudflare 本身不发邮件（Email Routing 只收不发）——Resend 的 HTTPS API 与零依赖服务端天然契合

安全要点：密码 scrypt+盐（timingSafeEqual 校验）；令牌只存 SHA-256 散列（数据文件泄露拿不到可用令牌）；登录限速每 IP 每分钟 10 次；重置密码/删除用户即吊销其全部令牌；`/api/admin/*` 与 `/admin` 仅接受本机回环连接。

### 公网部署（Cloudflare Tunnel，服务端 1.1）

适用：多设备使用 / 面向公众提供服务（任何人可注册、登录、免费使用官方模型）。零公网端口、零证书管理、无需境内服务器入站。

**安全模型（服务端已内置，勿破坏）**

- account-server 始终只监听 `127.0.0.1:8000`，公网流量经 cloudflared 回源到本机回环
- `clientIp()` 从 `CF-Connecting-IP` / `X-Forwarded-For` 取真实访客 IP（限速按真实 IP 计）
- 管理面（`/admin`、`/api/admin/*`）只认「本机直连」：回环 socket 且无代理头。经 Tunnel 进来的公网请求（即使 socket 是回环）一律 403——公网只开放 `/register`、`/api/auth/register|login|logout|me`、`/v1/*`
- 远程管理 = 远程桌面/SSH 到服务器本机打开 `http://127.0.0.1:8000/admin` 或用启动管理器

**部署步骤（约 10 分钟）**

1. **域名托管到 Cloudflare**（免费）：域名 NS 指向 CF（在 CF 添加站点按引导改 NS；域名已托管则跳过。本仓库现网使用 `xinglintools.top`）
2. **建 Tunnel**：CF Zero Trust 控制台 → Networks → Tunnels → Create a tunnel（cloudflared）→ 命名 `papilot` → 复制安装令牌。**或复用本机已有隧道**（一服务一隧道的架构下建议独立；复用时在既有隧道的 Public Hostname 加子域即可）
3. **装 cloudflared**（跑账号后台的机器，与后台同机）：
   - Windows（管理员）：`winget install --id Cloudflare.cloudflared`，然后 `cloudflared.exe service install <令牌>`
   - Linux：按 CF 页面给的包安装后 `cloudflared service install <令牌>`
   - 参考实现：`~/.cloudflared/cloudflared-run-*.bat`（token 模式 runner）+ `scripts/start-account-server.ps1`（账号后台孤儿拉起器，服务端进程独立于任何会话存活）
4. **配 Public Hostname**（CF Tunnel 页面）：子域 `pp` + 域名 → Service `HTTP://localhost:8000`。DNS CNAME 与边缘 HTTPS 证书全自动，**隧道热加载秒生效**（无需重启 cloudflared）
5. **启动账号后台**（启动管理器「启动后台」；开机自启 Run 键 `PapilotAccountServer` → `scripts/start-server-hidden.vbs`）
6. **Zotero 端**：设置 → Papilot → 服务器地址填 `https://pp.<你的域名>`（现网：`https://pp.xinglintools.top`）→ 注册账号 → 登录

**域名条件核对**

| 条件 | 说明 |
|---|---|
| 域名实名 | .top 在国内注册商需已实名；NS 托管到 CF 后不受影响 |
| ICP 备案 | **走 CF Tunnel 无需**（不使用境内服务器入站端口；CF 免费版大陆访问经境外边缘节点）。追求大陆低延迟再考虑备案+国内 CDN |
| DNS 解析 | Tunnel 自动建 CNAME，无需手动 A 记录 |
| HTTPS | CF 边缘自动签发（访问者→CF 全程 https；CF→源站走本机回环，无需证书） |

**注意事项**

- 通道上游（模型厂商 Key）消耗由你承担：公众服务建议保持 `balance.enforce=true`（余额不足即拦），或给上游设月度预算
- 源站 8000 端口**不要**改为绑定 0.0.0.0（否则 CF 头可被直连伪造，管理面失守）
- 若未来改用「公网 IP + nginx 直连」而非 Tunnel，需自行处理 trust proxy 与管理面鉴权（加 IP 白名单或管理密钥）

### 公网通道故障排查（530 / readyConnections=0）

公网打不开时，**先分层定位再动手**，不要一上来就重启隧道：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\diag\probe-tunnel.ps1
```

脚本按 L1→L6 自底向上检查（本地后台 / 隧道进程 / 边缘就绪 / 主机→边缘 TLS / 公网端点 / 出口路径），
退出码 0=健康、1=有故障层，`-Json` 输出机器可读结果。

**关键判据**

| 现象 | 含义 |
|---|---|
| `/ready` 端口通但 `readyConnections=0` | 进程活着但没连上边缘 —— **端口通 ≠ 健康** |
| 公网 530 + `/ready` 为 0 | Cloudflare 找不到健康的 connector |
| 到 edge `:7844` TCP 在 **<5ms** 内"连上"但 TLS 立刻 EOF | 本地有 TUN/代理**抢答**了握手，上游那段是坏的 |
| 到 edge `:7844` TLS 能完成但 L3 仍为 0 | 隧道自身（令牌/账号侧）问题，看 `runtime\cloudflared\logs\cf-run-papilot.log` |

**已知根因 1：本地代理 TUN 劫持 Cloudflare 边缘段（2026-10-27 实例）**

Clash 等 `TUN` 模式用 `0.0.0.0/1` + `128.0.0.0/1` 抢占默认路由，同时把 argotunnel 的
`198.41.128.0/17:7844` 也吞进去。若此时订阅里没有这条 CIDR 的专用分流规则，流量会落到
`MATCH` 兜底的机场节点，而该节点无法承载 argotunnel 的 TLS → cloudflared 无限
`TLS handshake with edge error: EOF` → 公网 530。
**症状特征**：Clash 日志里能看到 `rAddr=198.41.192.x:7844 ... rule=Match() proxy=节点选择[...]`。

修复（管理员）：给边缘段加一条比 `/1` 更具体的直连路由，让隧道流量绕过 TUN：

```powershell
New-NetRoute -DestinationPrefix '198.41.128.0/17' -InterfaceIndex <物理网卡index> `
  -NextHop <物理网关> -RouteMetric 1
powershell -File scripts\tunnel\tunnel.ps1 restart
```

`PapilotGuard` 的 **pass 3** 会在每次巡检时自动补这条路由（TUN 若在 Clash 重启后重新接管，
一分钟内自愈），无需人工干预。

**已知根因 2：守护根本没在跑**

`guard-papilot.ps1` 的健康判据是对的（`readyConnections > 0`），但若计划任务缺失或指向旧路径，
隧道卡在"进程在、边缘不通"的状态就**永远不会有人发现**。核对：

```powershell
Get-ScheduledTask -TaskName 'PapilotGuard' | Select-Object TaskName,State
Get-ScheduledTaskInfo -TaskName 'PapilotGuard' | Select-Object LastRunTime,LastTaskResult,NextRunTime
Get-Content server\data\guard.log -Tail 5     # 健康时静默，只在异常/恢复时写行
```

- 任务须为 `Ready`、`LastTaskResult=0`、`NextRunTime` 持续前进（每分钟一次）。
- 以**最高权限**注册（pass 3 改路由需要提权），否则路由自愈会静默失败。
- 日志中 `ALERT:` 开头 = 需要人工介入；`RECOVERED:` = 已自愈。可直接用这个前缀接外部告警。
- 注意：`PaperPilot Update Tunnel` 是**另一条独立隧道**（`paperpilot-updates`），与主隧道无关，勿混。
