- **Project Name**：paper-pilot（Papilot）

## 0. 原始需求复述

设置面板「账号与会员」卡片代码评审发现 8 项问题（均有代码证据），用户拍板全部实现：2 项 P0（修改密码缺失、赠送额度文案硬编码漂移）、3 项 P1（会员开通记录、我的订单、余额流水不可见）、3 项 P2（对比表口径、新设备登录邮件、余额不足联动按钮）。本 PRD 是增量需求文档，不做竞品分析。

## 1. 产品定义

### 1.1 Product Goals

| # | 目标 | 说明 |
|---|---|---|
| G1 | **账号安全闭环** | 用户能自助改密码并被正确引导（当前警告文案指向一个不存在的功能），异常登录可感知 |
| G2 | **信息单一真源** | 赠送额度等营销口径由服务端配置下发，客户端三处文案不再硬编码漂移 |
| G3 | **资产透明可查** | 会员开通记录、订单、余额扣费明细在面板内自助可见，减少「钱去哪了」类咨询 |

### 1.2 User Stories

1. As a 登录用户，I want 在面板里直接修改密码，so that 设备超限警告指向的「改密码」动作真实可达，改完全部设备被踢下线。
2. As a 运营者，I want 修改管理端赠送配置后客户端文案自动跟随，so that 不再出现「面板写 ¥6、实际发 ¥10」的口径漂移。
3. As a 付费用户，I want 查看我的会员开通/续期记录、订单列表和扣费明细，so that 我能自助核对账目，不用找管理员。
4. As a 免费用户，I want 余额不足时一键跳到模型通道设置，so that 我能立刻换用自己的 Key 继续用 AI。
5. As a 账号持有者，I want 新设备登录时收到邮件提醒，so that 账号被盗用时能第一时间发现。

## 2. 需求池

### P0（必须实现）

#### R1 · 修改密码（服务端接口 + 面板入口）

| 项 | 内容 |
|---|---|
| 用户故事 | 见 Story 1。背景：prefs-account.js:1067 设备超限警告写「请踢掉不认识的设备，或改密码（会踢掉全部设备）」，但全端无改密码功能 |
| 功能规格 | ① 服务端新增 `POST /api/auth/change-password`（Bearer）：body `{oldPassword, newPassword}`；校验旧密码 → 校验新密码强度（与注册同规则，≥8 位）→ 更新哈希 → **踢除该用户全部会话（含当前设备）** → 返回 `{ok:true}`。② 面板已登录区（设备列表附近）加「修改密码」按钮，点开内联表单（旧密码/新密码/确认新密码），成功后本地清 session、回到登录视图并提示「密码已修改，请重新登录」 |
| 服务端纪律 | 遵循现有写操作三件套：**速率限制**（复用 login 同款失败计数/锁定，防旧密码爆破）+ **auditLog('修改密码')**（`lib/audit.js` 与 `launcher.ps1` 的 `Get-AuditText` 两处补中文名）+ users.json 变更前 snapshot |
| 验收标准 | ① 旧密码错误 → 401 且计入登录失败锁定；② 新密码 <8 位 → 400；③ 成功后旧 token 访问 /api/auth/me 立即 401；④ 面板改密成功后回到登录视图，用新密码可登录；⑤ audit.log 有一条「修改密码」记录（不含密码明文/哈希） |
| 降级行为 | 新客户端 + 旧服务端：接口 404 → 入口按钮整块隐藏（面板现有惯例）；旧客户端 + 新服务端：无影响 |
| 涉及文件预估 | `server/account-server.js`（路由）、`server/lib/sessions.js`（踢全部会话）、`server/lib/audit.js`、`scripts/launcher.ps1`、`chrome/content/prefs.xhtml`（表单）、`chrome/content/prefs-account.js`、`chrome/content/scripts/ai/account.js`（changePassword 方法）、`test/sessions.test.js` 或新增 `test/change-password.test.js`、`scripts/check-wiring.py` |

#### R2 · 赠送额度文案改为服务端下发

| 项 | 内容 |
|---|---|
| 用户故事 | 见 Story 2。背景：「注册赠送 ¥6（30 天）」「Pro 月发 ¥20」硬编码在 `prefs.xhtml:66`、`prefs-account.js:918`、对比表 L248 共三处；而 `signupGrantMicro/signupValidDays` 是管理端可改配置（PUT /api/admin/pricing），公开 /api/plans 不下发 |
| 功能规格 | ① `/api/plans` 响应新增 `signupGrant: { amountMicro, validDays, scopeNote }`（scopeNote 固定「仅限基础模型」，与 R6 口径一致）与 `proMonthlyGrant: { amountMicro }`（Pro 月发额度，读现有配置）；② 客户端三处文案改为从 plans 缓存渲染，拉取失败时保持现有占位文案不报错 |
| 验收标准 | ① 管理端把 signupGrantMicro 改为 ¥10 后，重新拉 /api/plans，三处 UI 均显示 ¥10 且无需发版；② validDays=0 时显示「永久有效」而非「0 天」；③ signupGrantMicro=0（关闭赠送）时三处不再出现「注册赠送」字样；④ 新增 Node 测试断言 /api/plans 带 signupGrant 块 |
| 降级行为 | 新客户端 + 旧服务端：plans 无 signupGrant 块 → 回退现有硬编码文案（保证面板不空白）；旧客户端 + 新服务端：无影响 |
| 涉及文件预估 | `server/account-server.js`（/api/plans 组装）、`server/lib/balance.js`（下发字段）、`chrome/content/prefs.xhtml`（去硬编码）、`chrome/content/prefs-account.js`（渲染）、`test/balance.test.js`、`scripts/check-wiring.py` |

## 3. 技术规范与硬约束（边界）

| 约束 | 要求 |
|---|---|
| 服务端零依赖 | 全部新代码只用 Node 标准库；持久化走 `lib/store.js` JsonStore，不直改 `data/*.json` |
| 写操作三件套 | R1 必须 snapshot + auditLog + 速率限制（参考 /api/redeem、/api/orders 现有写法）；审计中文名 `lib/audit.js` 与 `launcher.ps1` Get-AuditText 两处同步 |
| XHTML 严格 XML | 面板文案改动不得引入未定义实体（会导致面板整页空白）；中文直接写在 xhtml/js |
| 数据脱敏 | 用户域接口只回本人数据；IP 打码；订单列表不下发收款账户；审计不含密码 |
| 新旧兼容 | 旧服务端/旧客户端互不认时按「整块隐藏」降级，不允许报错或半残 UI |
| 测试纪律 | 新测试端口用 `listen(0)`、HTTP 助手带 `agent: false`、时间戳相对 Date.now()；完成后 `python scripts/preflight.py --fast` 全绿，并同轮重启生产 :8000 |
| 密钥 | 任何密钥不进 git |

## 4. Open Questions（含默认决策）

| # | 问题 | 默认决策 |
|---|---|---|
| Q1 | 改密成功后是否踢当前设备？ | **踢全部（含当前）**，面板回登录视图重新登录。理由：与警告文案「会踢掉全部设备」口径一致，实现最简单，安全语义最清晰 |
| Q2 | 订单/流水列表条数？ | 订单默认 10、流水默认 20，两者 `limit` 上限均钳制 50；不做分页（数据量小，折叠区滚动即可） |
| Q3 | /api/plans 新增块命名？ | `signupGrant: {amountMicro, validDays, scopeNote}` + `proMonthlyGrant: {amountMicro}`，沿用现有 *Micro 金额约定 |
| Q4 | 新设备登录邮件是否给用户开关？ | **不做开关**（P2 阶段保持简单）；频率控制靠「同设备不重复发」 |
| Q5 | R6 守卫做成静态断言还是人工清单？ | **静态断言**，进 check-wiring.py；人工清单会被遗忘，静态守卫与仓库现有门禁文化一致 |
| Q6 | 流水功能标签（label）在服务端还是客户端生成？ | **服务端生成**：功能标签需要 refId → 模型/功能的映射知识，客户端不该重复维护；客户端只做展示 |
