## 0. 先划掉不该做的

Papilot 已有 100+ 模块、9 类功能、41 条右键命令。继续加「同类功能」的边际收益已经很低：

| 不做 | 原因 |
|---|---|
| BibTeX / citekey 生成（BBT 7,181★） | MIT 免费且极成熟，重造性价比为零；最多做「检测已装则联动」 |
| Word / WPS 引文插件（zotero-citation 1,285★） | Zotero 官方 Word 插件已占位，第三方插件做不出差异 |
| 又一个 AI 聊天入口 | 已有 6 个入口（工作台/悬浮窗/侧栏/划词/右键/分屏），11/100 的 AI 插件里 zotero-gpt 已停更 |
| 主题 / 美化 | 免费竞品成熟，用户不为皮肤付费 |
| 通用 Markdown 编辑器 | Zotero 7+ 原生支持，做了是负资产 |
| Sci-Hub / 代查 | 法律与 ToS 风险不对等（见会员清单 §7） |

## 1. 断点类：现有能力「差最后一步」

这一类最值得做——功能已经存在，但用户走到一半就断了，断点处就是投诉与流失。

| # | 功能 | 现状缺口 | 优先 |
|---|---|---|---|
| A1 | **OCR 回写文本层** | `attach-doctor.js` 能检测「无文本层 PDF」，但**只出报告不修**；扫描版中文文献因此无法进翻译/问答/打标全链 | **P0** |
| A2 | **笔记大纲 + 批量整理** | 有模板、图谱、批注转笔记，但**没有单篇笔记的大纲视图，也没有批量移动/合并/重打标签** | P1 |
| A3 | **模板条件块与变量扩展** | `note-templates.js` 只有 8 个占位符（`{{title}}`…`{{aiSummary}}`），**无条件块、无循环、无自定义字段** | P1 |
| A4 | **图表速览** | 有 PDF 速览（偏文本）、并排对比，但**没有「把一篇论文的图/表/公式抽出来集中看」**；路线图 0.23.0 曾暂缓 | P1 |
| A5 | **库内语义检索** | `lib-search` 是关键词两阶段（标题/标签加权 → 全文索引），**问「有没有讲过 XX 方法」搜不到** | P2 |

### A1 为什么排 P0

- 这是唯一一个「修好之后，下游 5 个功能同时变强」的项：扫描版 → OCR → 可翻译、可问答、可打标、可统计。
- 中文老文献、学位论文、部分知网下载件大量是无文本层的，中文用户命中率远高于英文用户。
- 实现有两条路：**本地 Tesseract**（零成本、需用户装，体验差）或**云端 OCR**（体验好、按页计费，正好接会员清单 C9）。建议先做「检测 → 一键云端 OCR → 回写」最小闭环，本地引擎作为无网备选。

### A4 的实现要点

不要自己解析 PDF 图形对象。用 pdf.js 的 operator list 取「图像块 + 图注文本块」，按页面纵向位置配对，生成缩略图墙；公式用文本块坐标近似框选。风险在双栏与跨页图，**MVP 只做「单页内的图 + 图注」**，跨页降级为不配对。

## 2. 独有输出类：中文场景里几乎零成本的差异

| # | 功能 | 现状 | 为什么值得做 |
|---|---|---|---|
| B1 | **GB/T 7714 参考文献表导出** | `ref-format.js` 已有 GB/T 7714 **解析器**（第 821 行起）与中文题录字段映射；`cn-meta.js` 用它生成文件名。**但没有「把选中条目输出成 GB/T 7714 参考文献列表」** | 毕业论文、中文期刊投稿的第一道刚需；解析器现成，**反过来做序列化几乎是纯函数**，成本 1–2 天 |
| B2 | **中文题录字段补全规则强化** | `cn-meta` 已覆盖知网/万方命名 | 卷期页码的非常规格式（如「2023(12):45-52+67」）仍易错；可对照 jasminum 的字段规则补边界 |

B1 是本文性价比最高的一项：输入是 Zotero 条目，输出是一段可直接粘进 Word 的文本，用户感知极强，且**竞品大多只做 BibTeX，不做国标**。建议同时支持三种形态：顺序编码制、著者-出版年制、以及「带 `[J]/[M]/[D]` 类型标识」的完整版。

## 3. 连接类：把库接到用户真正写东西的地方

| # | 功能 | 对标 | 判断 |
|---|---|---|---|
| C1 | **Obsidian 单向导出** | mdnotes 1,399★、markdb 681★、notero 3,233★（Notion） | **建议做**。单向、按需、不改原库，成本低；Papilot 的差异点是「导出的不是原始笔记，而是 AI 整理过的综述/矩阵」 |
| C2 | **Notion 同步** | notero 3,233★ | 暂缓。OAuth + 增量同步 + 冲突处理是持续维护成本，且 Notion API 变动频繁 |
| C3 | **待读清单推送到 Todoist/滴答** | zotodo 223★ | 暂缓。用户面窄，且各平台 API 都要单独适配 |
| C4 | **能力集市（插件市场）** | zotero-addons 1,760★ | 中期。功能中心已有骨架，但要做版本兼容过滤与一键安装，属于平台级投入 |

C1 的具体形态建议：右键「导出到 Obsidian 库」→ 选目录 → 生成 `{citekey}.md`，含 front-matter（title/year/doi/tags/zotero-link）、AI 摘要、批注摘录、双向链接占位。**只导出，不回读**，避免变成同步引擎。

## 5. 优先级汇总

| 阶段 | 做哪些 | 理由 |
|---|---|---|
| **立即（1–2 周）** | B1 GB/T 7714 导出、D1 作者截断、A3 模板变量扩展 | 低成本、高感知，且都能独立发版 |
| **近期（1–2 月）** | A1 OCR 闭环、A2 笔记大纲与批量、A4 图表速览、C1 Obsidian 导出 | 补断点，直接提升留存与口碑 |
| **季度** | A5 语义检索、D2 争议度、D3 网页存档、D4 版本合并 | 需要索引或外部数据，单独排期 |
| **中期评估** | C4 能力集市、C2 Notion 同步 | 平台级投入，等装机量再决定 |

## 6. 一个判断标准

以后评估「要不要加这个功能」，用三问过一遍：

1. **它是否让某条已有链路从「断」变「通」？**（A1/A2 是，B1 是）
2. **竞品做不了或不愿做吗？**（B1 国标、A1 中文扫描件，是；再做一个聊天窗，不是）
3. **三个月后它还值得维护吗？**（外部 API 同步类要慎重，纯函数类可以放心做）

三个都答「是」，才值得进路线图。
