### 调研小结

- **「领域元数据 + 按域子集导出」的黄金标准是 IATE**：条目带 domain/subdomain、可靠度、评价等级；
  下载页按「领域 × 语言」组合筛选生成子集。这是术语库领域事实上的功能范式。
- **TBX（ISO 30042）的数据模型**（termEntry → langSet → term，Terminologue 同构）是领域化术语
  条目的通用结构；轻量化后即 `{原文, 译文, 领域}` 三元组。
- **中英对照的可用数据**集中在：计算机（微软术语集及其衍生）、AI（AITD）、医学（meddict /
  rime_clinic / CMeKG）、金融（finance_i18n / CNEconDict）；法律领域开源双语词库稀缺
  （EuroVoc 等多语叙词表覆盖法律域但非中英对照）——本项目以自编种子词包补位。
- **格式生态**：CSV 最通用（ECDICT、EECS-Terminology）；TBX 是行业标准交换格式；
  pyglossary 证明「多格式识别 + 纯函数转换」是可维护的导入导出架构。

## 二、Papilot 采纳的设计方案

基于调研，【术语表与全文翻译优化】面板从「单一平面文本」升级为「领域化术语管理」，核心采纳四项设计：

| 来源项目 | 借鉴的设计 | Papilot 落地 |
|----------|------------|-----------------|
| IATE | 条目带领域元数据 + 按领域启停 | 行式第三段「`原文 = 译文 \| 领域`」（多标签 `;` 分隔）+ pref `translateGlossaryDomains` 启用域白名单（空 = 全部启用）；设置面板渲染**领域筛选 chips** |
| IATE「按需子集」+ 本项目 60 条注入上限的矛盾 | 按需选子集注入 | `glossaryBlock(list, text)` 相关性排序：**待译段落命中的术语优先注入**，长表被 60 条上限截断时保证本段术语必进 prompt |
| ECDICT CSV 范式 + pyglossary 多格式理念 | 导入导出 | `glossaryToCsv`（表头 `source,target,domain`，UTF-8 BOM 兼容 Excel）/ `parseGlossaryImport`（自动识别 **CSV / TSV / 带表头 / 裸列 / JSON / 行式** 四形态）/ `mergeGlossary`（行级 upsert，注释保留）——全部纯函数，FilePicker 只做 IO 薄壳 |
| AITD「专项领域篇」+ finance_i18n / meddict 域分档 | 内置种子词包 | `ai/glossary-packs.js`：计算机/AI、医学、经济金融、法律四域各 ~20 条**自编高置信术语**（不抄版权受限词库），面板一键追加 |
| TBX / Terminologue 的质量观（IATE 的 reliability/evaluation） | 一致性可观测 | `glossaryStats` 译后自检：translate() 返回 `glossary:{hit,total}`，全文对照翻译完成文案与双栏窗口状态行汇报「**术语一致 n/m**」（只观测不阻断） |

### 术语一致性保障的完整链条（优化后）

1. **注入前**：领域过滤（IATE 式按域选子集）+ 相关性排序（命中优先，60 条上限下零漏配）；
2. **注入时**：LLM prompt 术语约束（原有能力，两处注入点——`_runEngine` 与划词浮窗——都升级为带文本排序）；
3. **译后**：一致性统计（新增强化——原文命中术语的译法是否出现在译文，逐段累计 n/m）；
4. **缓存**：指纹随「过滤后的实际注入内容」变化——**改领域启停 = 改术语表**，旧缓存自动失效
   （沿用 0.33.0 的指纹进缓存键纪律，且过滤发生在指纹之前，语义自洽）。

### 关键工程决策

1. **向后兼容零迁移**：旧「`原文 = 译文`」两段行、JSON 双形态照常解析（`d` 为空 = 通用域，永不被过滤）；
   缓存键机制不变。
2. **域过滤放在 `glossary()`、指纹之前**：启用域变化 → 过滤结果变化 → 指纹变化 → 缓存键变化。
   不需要 `clearCache()`，也不会出现「关掉医学域还吃医学术语旧缓存」。
3. **防误判护栏**：正文里的 `|` 不当域分隔符——`_looksLikeDomain` 要求域段为「无空格、≤20 字符/标签、
   ≤48 字符整体」的短标签串；`a | b = c` 仍解析为 `s="a | b"`。
4. **导入合并 = 行级 upsert**：`#` 注释、无法解析的行原样保留（不重建丢注释）；同原文新译覆盖、
   重复行去重；JSON 形态输入保 JSON 输出（程序化形态保真）。
5. **导出带 BOM**（`\uFEFF`）：Excel 双击打开中文 CSV 不乱码；导出**全量**（含被域过滤停用的条目——
   域是启停开关不是数据删改）。
6. **一致性统计只观测不阻断**：miss 术语不改写译文（避免破坏流畅性），只在完成文案/状态行汇报，
   供用户回查术语表。
7. **种子词包自编**：每条为社区/教科书通行译法，不抄录微软术语集（专有许可）、商业词典等
   版权受限数据；种子是起点不是词典，导入后用户自由增删改。

### 对接开源词库的操作路径（用户视角）

- **EECS-Terminology**：下载 `Termbase.csv` → 面板「导入文件」→ 识别为带表头 CSV
  （`en,zh_CN,pos,description` 的 pos/description 列自动忽略）。
- **IATE**：下载页选 English + Chinese + 目标领域 → 导出 CSV → 预处理为 `source,target,domain`
  三列（IATE 原始导出为多行多列结构）→ 导入。
- **AITD / 其他 MD 表**：复制术语两列存成 `原文,译文` 裸 CSV → 导入（零命中 `=` 的裸两列按 CSV 识别）。
- **自有积累**：直接「导出 CSV」备份/换机迁移。

对「多学科 + 中英 + 机器可读 + 按域取用 + 宽松许可」的专门 GitHub 数据库做了第二轮检索：

- 结构上最接近的先例是 **za-marito**（dsfsi/za-marito，南非 11 语言多领域术语库，CSV/JSON
  发布、学术论文背书）——**语言对不同**，恰好证明此模式有真实需求与学术价值；
- 中英方向：CFPAOrg/Glossary（Minecraft 单域）、Geolexica（地理信息单域）、

- 结论：**en↔zh 这一格是真实空白** → 已在本地建仓 `H:/project/open-termbank`（v1.0.0 已提交）。

### 同步协议（消费方视角）

- **入口**：`data/index.json` = `{version, updated, domains:[{domain,slug,file,count,sha256}], total}`；
- **增量判定**：轮询 index.json → 对比本地记录的每域 sha256 → 变了才重新拉对应 CSV
  （一次请求即可判断有无更新；与本项目 update.json 通道同一设计哲学）；
- **取用 URL**：`https://cdn.jsdelivr.net/gh/<owner>/open-termbank@main/data/<slug>.csv`
  （jsDelivr，带缓存）或 `raw.githubusercontent.com` 直链；
- **CAT 工具**：`tbx/open-termbank.tbx`。
