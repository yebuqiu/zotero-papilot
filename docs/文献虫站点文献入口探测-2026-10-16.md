## 0. 结论提要（TL;DR）

1. **站点本身运行正常**：登录、栏目、列表、入口交接页全部可用；实测无频率限制、站内无验证码；但存在**“同一帐号同一时刻只能一人在线”**的单会话硬限制。
2. **279 个叶子入口中 275 个能正常生成交接**（96%+）：204 个 POST 至机构网关、39 个 JS 跳转、29 个 POST 至登录系统、7 个手动流程页；仅 4 个（未开通库）被引导至购买页。
3. **真正的瓶颈在“落地层”**：入口指向的外部系统鱼龙混杂——CNKI 镜像节点、sci-hub、panda985 等**确实可用**；但大量机构网关报错/超时/需人工验证，且部分域名已死（38 个入口指向已停放的 `sxxs.shop`，5 个指向 404 的 `hggfdd.top`）。
4. **接入价值判断**：**技术可行但复杂且不稳定，不建议作为 Papilot 的主力或默认来源**。若接入，应做成“用户可选、默认关闭”的实验性来源，并注意单会话冲突、Referer/参数链复刻、验证码人工介入等约束。现有 Unpaywall → Sci-Hub → Sci-Net 链路已覆盖其可用的英文部分；其独有增量主要是**中文库（知网/万方/维普）入口**，但落地多为机构网关，直连成本高、失效快。

## 2. 站点结构（4 级）

```
库（ListInfo?classid=61/63/66…）
 └─ 栏目（如 知网62 / 万方79 / sci-hub 176 / 快速下载221 …）
     ├─ 静态入口文章：ShowInfo.php?classid=X&id=Y（33 个，多为 JS 跳转页）
     └─ 动态入口列表：e/rk/liebiao1.php?shujuku=<数据库标识>（JS 注入；**按 Referer 填写 bclassid**）
         └─ 叶子入口：e/rk/zhuangchu.php?zhongwenaddid=…&zhongwenid=…&bclassid=<库>&userid=<用户>
             └─ 交接页（3 种机制）→ 外部落地系统
```

**关键工程细节（对自动化至关重要）**：
- `liebiao1.php` 生成的链接是否带 `bclassid` **取决于请求的 Referer**（栏目页上下文）。**裸调用会生成缺参链接，`zhuangchu.php` 随即报 SQL 语法错误**（我们在无 Referer 场景复现多次）。接入方必须完整复刻“栏目页 → liebiao → zhuangchu”的调用链与 Referer。
- 交接页（`zhuangchu.php` 输出）共 3 种：
  1. **JS 跳转页**：`location.href=外部URL`（39 个）；
  2. **自动 POST 表单**：`obj.action=机构网关`，表单字段 `siteid=站点域名 / uname=账号 / uid=用户ID`（204 个）；部分额外带 `boz/reurl`（如大连理工 webvpn 参数）；
  3. **手动流程页**（7 个）：要求“第一步打开官网 → 第二步复制页面上的账号密码粘贴登录”（如万方GW、JSTOR官网、Nature），或两步点击法（Spie“启盟”页）、iframe+2.5s 延时跳 sci-hub。

## 4. 整体可用性评估

- **站内层（b.r88r.top）**：✅ 稳定可用。全程 600+ 请求无 429/封禁；响应快（均值 0.16s）；结构完整；无站内验证码。❌ 但单会话限制对“自动化 + 用户浏览器并存”是硬伤；HTTP 明文传输凭据（安全风险）。
- **入口层（交接生成）**：✅ 275/279 生成正常。
- **落地层（实际取文）**：⚠️ 分化严重。直接验证可用的：CNKI 节点、sci-hub.ren、panda985、typicalgame 学术搜索、cdclib；不可用/受限的：约 40+ 入口（死域名）、多个网关超时/业务错误、验证码类需人工。
- **综合判断**：**适合“人工偶尔使用”，不适合“稳定自动化接入”**。作为文献获取来源，其可替代性高（英文部分与既有 Sci-Hub/Sci-Net 链高度重叠）、稳定性与合规风险均不理想。

## 5. 接入建议（若决定接入）

**总体建议：不作为默认来源；如接入，则作为用户可选、默认关闭的实验性来源（参照 `scihubEnabled` 的 pref 模式），且仅用户自备账号时启用。**

优先度排序（若做）：
1. **知网入口3链路**（`rk9998.php → api4/6.wenxian.shop → CNKI 节点`）：链路已验证可达，价值最高（中文库唯一直接可用路径）。需处理 wenxian.shop 两级跳转 + 节点地址硬编码（随时可能变）。
2. **sci-hub / panda985 链接类**（低价值，项目已有同类）。
3. **机构网关类（sjuku.top/yyttgd.top 等）**：不建议逐一代入——域名多（125+）、失效快、无统一返回格式、部分需点击验证码。

**接入必须满足的条件**：
- **登录态维护**：需账号密码（POST 明文）或从浏览器复制 Cookie；⛔ 因单会话限制，插件内保活会把用户浏览器踢下线（反之亦然）——只能做成“用户摇一摇/临时借用”模式，或干脆依赖用户手动在浏览器完成入口点击后由插件接管解析（推荐）。
- **调用链复刻**：必须保持 `栏目页 → liebiao1(Referer=栏目页) → zhuangchu(bclassid) → 交接页` 的参数与 Referer 链，否则得到 SQL 报错/缺参链接。
- **交接解析**：需同时支持 `location.href` JS 跳转与 autosubmit 表单 POST 两种形态（后者需按字段代提交至第三方网关）。
- **频率限制**：实测 1.2s 间隔约 500 请求无任何限制；建议保守 ≥2s/次、单条任务上限 ≤50 次，避免触发封禁（站点侧虽无限制，但机构网关侧不可知）。
- **验证与降级**：点击验证码（clicaptcha）/共享会话/手动账密类入口无法自动完成，必须设计“转人工浏览器打开”的降级路径。
- **合规注意**：该站为无授权聚合代查（机构账号池、共享账密明文出现），版权与合规风险高于普通学术工具；接入应默认关闭、显著提示风险、绝不内嵌/传递账号凭据、绝不批量下载。
- **账号安全**：全站 HTTP 明文；账号为卡密制弱口令生态。提醒用户勿复用密码；探测/使用痕迹可能被记录。
